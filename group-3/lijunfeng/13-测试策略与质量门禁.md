## 一、测试分层

| 层级 | 工具 | 覆盖对象 | 说明 |
|------|------|----------|------|
| **L1 Unit** | JUnit 5 + Mockito | 单个类/方法的逻辑（Repository、Parser、CompareEngine） | 不依赖网络，最快 |
| **L2 Integration** | Spring Boot Test + MockMvc | API 端点 + 存储 | 模拟 HTTP 请求 |
| **L3 Contract** | JUnit 5 + JSON Schema 断言 | 响应体结构与 `09` 一致 | 验字段名、类型 |
| **L4 E2E** | Playwright / Cypress | 完整用户旅程（行业概览→解读→对比→问答） | 浏览器级操作 |

## 二、用例拆分原则

> **核心理念：数"可独立失败的点"** — 每条 TC 只回答一个问题，失败时不看代码就知道哪里坏了。

| 来源 | 计数方法 | 示例 |
|------|----------|------|
| 正常路径 | 每个端点的 happy path = 1 条 | `POST /ask → 200` = TC-001 |
| 错误码 | 每个 distinct error code = 1 条 | `EMPTY_QUERY` = TC-002 |
| 分支路径 | 每个 if/else 降级分支 = 1 条 | 无 API Key → demo = TC-004 |
| 类型约束 | Spec `09` 约定的字段类型 = 1 条 | `llm_used` 必须 bool = TC-006 |

## 九、质量门禁

| Gate-ID | 条件 | 阻塞合并 |
|---------|------|----------|
| **G-LINT** | `black --check` + `flake8` 通过 | **是** |
| **G-UNIT** | Unit 测试（L1）全绿 | **是** |
| **G-INT** | Integration 测试（L2）全绿 | **是** |
| **G-AC** | P0 验收标准全覆盖（US-001~004 的 P0 AC） | **是** |
| **G-PERF** | `response_time_ms < 5000`（问答端点） | 否（warning） |
| **G-SEC** | 零敏感信息硬编码（API Key 等） | **是** |

## 十、TDD 适用场景

| 场景 | TDD 价值 | 建议 |
|------|----------|------|
| 简单 CRUD（会话列表、删除） | 低 | 写完补测试 |
| 参数校验 / 错误码 | 中 | 建议 TDD |
| 多级降级 / 状态机 | **高** | **强烈建议 TDD** |
| 研报解析提取逻辑 | **高** | **强烈建议 TDD** |
| 多研报对比（同时间段校验） | **高** | **强烈建议 TDD** |
