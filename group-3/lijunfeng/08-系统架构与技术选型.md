### 1.2 架构风格

> 选择架构风格时思考：教学场景需要什么样的复杂度？分层带来什么好处？

| 决策 | 选型 | 理由 |
|------|------|------|
| **前后端分离** | Vue3 SPA + Spring Boot REST API | 前端独立开发，参照南方基金现有欧拉平台风格 |
| **单体部署** | 前后端各一个进程 | 一期不引入微服务复杂度，快速交付可演示版本 |
| **分层架构** | Controller → Service → Repository | 替换存储引擎或 LLM 提供商时上层零改动 |
| **本地部署** | 全部服务内网运行 | 数据安全第一，数据不出域（用户访谈 S-03 核心诉求） |

## 2. 后端分层结构

> 每层写清"允许做什么、禁止做什么"。Java 后端采用经典 Spring Boot 分层。

| 层 | 包/类 | 允许做 | 禁止做 |
|----|------|--------|--------|
| **Controller** | `controller/AgentController.java` | 参数校验、HTTP 状态码、traceId 注入 | 直接操作数据库、调用 LLM |
| **Service** | `service/AgentService.java` | 降级编排、问答结果组装 | 感知 HTTP 请求/响应 |
| **Parser** | `service/ReportParserService.java` | 研报解析、关键信息提取（评级/目标价/核心观点） | 操作数据库 |
| **Compare** | `service/CompareEngineService.java` | 多研报指标对比、同时间段校验 | 调用外部 API |
| **Provider** | `provider/CoPawBridge.java` / `BailianClient.java` | HTTP 调用外部 LLM API | 操作数据库 |
| **Repository** | `repository/*Repository.java` | 数据 CRUD、数据校验（JPA/MyBatis） | 调用外部 API |

## 3. 前端架构

| 项 | 选型 | 理由 |
|----|------|------|
| UI 框架 | Vue 3（Composition API）≥ 3.3 | 南方基金团队技术栈匹配，学习曲线平缓 |
| 构建工具 | Vite ≥ 5 | 极快 HMR，Vue3 官方推荐 |
| 状态管理 | Pinia | Vue3 官方状态管理方案，TypeScript 友好 |
| HTTP 客户端 | Axios | 拦截器机制便于统一 traceId 注入和错误处理 |
| UI 组件库 | Element Plus | Vue3 生态最成熟组件库，参照欧拉平台风格 |
| 样式方案 | SCSS + Element Plus 主题定制 | 参照欧拉平台现有风格，保持 UI 一致性 |

## 7. ADR（架构决策记录）

> 每条 ADR 记录一个"为什么选 A 而不选 B"的决策。至少写 2 条。

| ADR | 决策 | 核心理由 |
|-----|------|----------|
| ADR-001 | Spring Boot 而非 Flask/FastAPI | Java 为南方基金主力技术栈，团队熟悉度高，生态成熟 |
| ADR-002 | Vue3 而非 React | 团队 Vue 经验丰富，Element Plus 组件库与欧拉平台风格一致 |
| ADR-003 | MySQL 而非 JSON 文件 | Java 生态天然适配关系型数据库，JPA 开发效率高 |
| ADR-004 | 本地部署而非云端 | 用户访谈明确要求数据不出域（S-03：必须内部部署，数据安全第一） |

## 8. 安全架构

> 对齐 `07` 4 安全需求。当前教学版与生产需求的差距。

| 层 | 当前措施 | 生产改进 |
|----|----------|----------|
| 认证 | 无（开放访问） | JWT + 南方基金内部 SSO |
| CORS | 全开放 | 欧拉平台域名白名单 |
| 密钥 | `application.yml` 环境变量注入 | Vault / Secrets Manager |
| 数据安全 | 内网部署，数据不出域 | 数据加密存储 + 审计日志 |
| 操作留痕 | traceId 链路追踪 | 全量操作日志 + 行为审计 |
