> **04 的定位**：`03` 说了"为什么做"，04 翻译成"做什么、不做什么、多重要"。`05` 再拆成用户故事和验收标准。

## 1. 愿景与目标

> 把 `03` §1 的痛点翻译成正面目标。

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息分散：研报、新闻、数据分布在多个系统，无统一入口 | 在欧拉平台权益研究模块增加研报AI解读菜单，提供统一的研报阅读与问答入口 |
| 效率低：研报内容多且长，关联不同数据源困难，格式不统一 | AI自动提取研报关键信息（评级、目标价、核心观点），按行业/日期分类，开盘前批量生成 |
| 易用性：不同数据间切换复杂、耗时，数据对比不直观 | 提供可视化对比界面，支持同时间段多研报关键指标对比，自动生成对比表 |

## 2. 目标用户

> 来源：`02` S-01 参会人员 + S-03 用户访谈。

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 投研部门总监（李总监） | 查看所有行业研报统计概览，快速掌握重要信号 | 每天 1-2 次 |
| 高级分析师（陈研究员） | 快速提取研报关键信息，多研报对比分析 | 每天多次 |
| IT部经理（王经理） | 系统健康监控、技术方案评估 | 每周 |

## 3. 核心业务场景

> 把 `03` §2 提案概要拆成用户路径。

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 行业研报概览 | 用户登录 → 进入研报AI解读菜单 → 查看申万二级行业分类列表 → 查看各行业研报数量 → 点击进入具体行业 |
| SC-02 | 单篇研报AI解读 | 用户选择研报 → 点击"AI解读" → 查看评级、目标价、核心观点 → 查看财务预测 → 查看历史解读记录 |
| SC-03 | 多研报数据对比 | 用户勾选 ≥2 份研报 → 选择同一时间段 → 点击"开始对比" → 查看对比表格（评级/目标价/营收增速/PE） |
| SC-04 | 自然语言问答 | 用户创建会话 → 输入问题 → 获得AI回答（含来源标识）→ 回答自动落库 → 查看历史问答 |
| SC-05 | 每日研报批量生成 | 系统每日开盘前（8:00）自动触发新增研报AI解读 → 分析师上班即可查看当日解读结果 |

## 4. 产品规则

> 把 `03` §4 成功标准 + §3 范围约束展开成可落地的规则。

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 每条问答提问 MUST 绑定 `session_id` | 03 §2 "会话式问答" |
| R-02 | `query` 长度 1～500 字符，为空或超长返回明确错误码 | 03 §4 成功标准 |
| R-03 | 回答 MUST 携带 `answer`、`llm_used`、`model`、`response_time_ms`、`answer_source`、`traceId` | 09 POST /ask 响应 |
| R-04 | LLM 不可用时按 CoPaw → 百炼 → Demo 三级降级，静默执行，通过 `answer_source` 标识 | 03 §5 风险应对 |
| R-05 | 首次问答自动将会话标题重命名为 query 前 20 字 + `...` | 10 §9 业务逻辑 |
| R-06 | 研报行业分类 MUST 按申万二级行业标准 | 02 S-01 需求记录 |
| R-07 | 多研报对比 MUST 为同一时间段，参与对比研报 ≥ 2 份 | 05 US-001 AC-001-03 |
| R-08 | 删除会话 MUST 级联删除所有关联问答记录 | 10 §9 业务逻辑 |
| R-09 | 所有写操作 MUST 记录 traceId + 时间戳（操作留痕） | 03 §3 范围边界 |

## 5. 能力与优先级

> P0 = 必须实现，阻塞发布；P1 = 应当实现，不阻塞首版。

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 行业研报概览（申万二级分类 + 研报数量统计） | **P0** | SC-01 |
| 单篇研报AI解读（评级/目标价/核心观点提取） | **P0** | SC-02 |
| 多研报数据对比（同时间段关键指标对比表） | **P0** | SC-03 |
| 会话管理（列表 / 新建 / 删除） | **P0** | SC-04 |
| 自然语言问答与三级降级 | **P0** | SC-04 |
| 历史问答记录查看与追溯 | **P0** | SC-04 |
| 每日研报批量自动生成 | **P1** | SC-05 |
| 系统健康检查 | **P1** | — |

## 6. 验收与成功标准（PRD 层）

> 从 `03` §4 可度量标准出发。

| 标准 | 度量 |
|------|------|
| 主路径可走通 | 用户在 3 分钟内完成"新建会话 → 提问 → 查看历史"全链路 |
| 每日批量生成 | 每天早上开盘前 8:00，可生成对应行业的所有研报AI解读内容 |
| 问答命中率 | 自然语言问答命中率 ≥ 80% |
| 离线可用 | 未配置 LLM 密钥时系统仍返回离线演示回复（`answer_source=demo`） |
| 数据不出域 | 全部服务内网部署，研报内容与问答记录零外传 |

## 7. 与 05 用户故事的关系

> **04 定"做什么、多重要"；05 定"谁要什么、怎么验收"。**

| 本文（PRD） | 作用 | 05 中落地 |
|-------------|------|-----------|
| §3 SC-01 行业研报概览 | 一条叙事场景 → US-001 AC-001-01 | US-001（行业分类 + 研报数量） |
| §3 SC-02 单篇研报解读 | 一条叙事场景 → US-001 AC-001-02 | US-001（公司研报解读 + 历史） |
| §3 SC-03 多研报对比 | 一条叙事场景 → US-001 AC-001-03 | US-001（数据对比 + 同时间段） |
| §3 SC-04 自然语言问答 | 一条叙事场景 → US-002 + US-003 | US-002（问答提交）+ US-003（历史记录） |
| §4 产品规则 | 字段/状态/错误口径 | 拆入各 US 的 AC |
| §5 能力优先级 | P0 / P1 | 与各 US 优先级一致 |
