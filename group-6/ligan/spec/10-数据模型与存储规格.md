## 1. 概念模型

```
Session（会话）1 ── * QARecord（问答记录）
   │                      │
   │  session_id (PK)     │  record_id (PK)
   │  title               │  session_id (FK → Session)
   │  query_count          │  query / answer / llm_used
   │  created_at           │  model / response_time_ms
   │  updated_at           │  answer_source / timestamp
   └                       └
```

> **核心关系**：一个 Session 可包含零到多条 QARecord。外键通过 `session_id` 字段逻辑引用。

## 2. 存储引擎

| 项 | 说明 |
|----|------|
| 引擎 | JSON 文件（`json` 标准库） |
| 编码 | UTF-8，缩进 2 空格 |
| 读写模式 | RMW（全量读入 → 修改 → 全量写回） |
| 并发安全 | 无锁，不支持并发写入 |
| 文件布局 | `{DATA_DIR}/sessions.json` + `qa_records.json` |

## 3. 实体定义 — Session

| 字段 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| `session_id` | `string` (UUID) | 是 | **PK** | 会话唯一标识 |
| `title` | `string` | 是 | ≤100 字符 | 默认"新会话"，首次问答自动重命名 |
| `created_at` | `string` (ISO-8601) | 是 | UTC+Z | 创建时间 |
| `updated_at` | `string` (ISO-8601) | 是 | UTC+Z | 最后更新时间 |
| `query_count` | `integer` | 是 | ≥ 0 | 累计问答次数 |

## 4. 实体定义 — QARecord

| 字段 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| `record_id` | `string` | 是 | **PK**，`rec_{ts}` | 记录唯一标识，基于时间戳生成 |
| `session_id` | `string` | 是 | **FK** → Session | 所属会话 |
| `query` | `string` | 是 | 1–500 字符 | 用户提问原文 |
| `answer` | `string` | 是 | — | LLM/Demo 返回的答案 |
| `llm_used` | `boolean` | 是 | — | 是否使用真实 LLM |
| `model` | `string\|null` | 是 | — | 模型标识，Demo 时为 null |
| `response_time_ms` | `integer` | 是 | SLO < 5000 | 响应耗时（ms） |
| `answer_source` | `string` | 是 | 枚举 | `copaw`\|`bailian`\|`demo` |
| `timestamp` | `string` (ISO-8601) | 是 | UTC+Z | 记录创建时间 |

## 5. Storage 方法清单

> 列出 Storage 类的全部公开方法。每个方法标注关联的 TC 编号（来自 `13`）。

### 5.1 会话管理

| 方法 | 签名 | 行为 | 关联 TC |
|------|------|------|---------|
| `create_session` | `(session_id, title) → dict` | 创建新会话 | TC-M01-041 |
| `get_sessions` | `() → list` | 返回全部会话 | TC-M01-042 |
| `delete_session` | `(session_id) → None` | 删除 + **级联删除**记录 | TC-M01-043 |
| `update_session` | `(session_id: str, title: str) → dict` | 1. 查找 session_id 对应会话（不存在则抛 KeyError）<br>2. 更新 title 字段（≤100 字符）<br>3. 更新 updated_at 为当前时间<br>4. 写回 JSON 文件<br>5. 返回更新后的 Session dict | TC-M01-046 |

### 5.2 问答记录管理

| 方法 | 签名 | 行为 | 关联 TC |
|------|------|------|---------|
| `add_record` | `(session_id, query, answer, ...) → dict` | 写入记录 + 更新 query_count | TC-M01-044 |
| `get_records_by_session` | `(session_id) → list` | 按 session_id 过滤 | TC-M01-045 |
| `delete_records_by_session` | `(session_id: str) → int` | 1. 过滤 qa_records.json 中 session_id 匹配的记录<br>2. 从列表中移除所有匹配记录<br>3. 写回 JSON 文件<br>4. 返回已删除的记录数（供 DELETE /sessions 的 `deleted_records` 字段使用） | TC-M01-047 |

## 6. 关键业务逻辑

**示例 — 首次问答自动命名**：

```python
if session["query_count"] == 1:
    session["title"] = query[:20] + ("..." if len(query) > 20 else "")
```

> **规则**：仅首次问答（query_count 从 0 → 1）触发，后续不再自动更名。

| 逻辑 | 触发条件 | 行为 |
|------|----------|------|
| 首次问答自动命名 | `query_count` 从 0 → 1 | 标题 = query 前 20 字 + `...`（超长截断） |
| 级联删除 | 调用 `delete_session` | 先调用 `delete_records_by_session` 删除所有关联 QARecord 并获取删除数，再删除 Session |
| query_count 自增 | 调用 `add_record` 成功写入记录 | Session.query_count += 1，同时更新 updated_at |
| updated_at 更新 | 会话内容变更 | 任何修改会话的操作（add_record、update_session）都更新 updated_at 为当前时间 |
| record_id 生成 | 调用 `add_record` | 格式 `rec_{timestamp_ms}`，基于毫秒时间戳保证唯一性 |
| timestamp 写入 | 调用 `add_record` | 自动注入当前 ISO-8601 UTC 时间作为 `timestamp` 字段 |
| title 长度校验 | 调用 `create_session` 或 `update_session` | title 超过 100 字符时拒绝操作，对齐 `09` §8 INVALID_SESSION_TITLE |
| 空会话删除 | 调用 `delete_session` 且无关联记录 | `delete_records_by_session` 返回 0，正常删除 Session |

## 7. API 响应 DTO 概要

> 详细端点定义见 `09`。此处列出关键 DTO 与存储字段的映射关系。

| API 端点 | 核心 DTO 字段 | 额外注入 |
|----------|---------------|----------|
| `POST /ask` | answer, llm_used, model, response_time_ms, answer_source | `traceId` |
| `POST /sessions` | session_id, title, created_at, query_count | `traceId` |
| `GET /sessions` | sessions[].session_id, title, created_at, query_count | `traceId` |
| `DELETE /sessions/{id}` | message, deleted_records | `traceId` |
| `GET /sessions/{id}/records` | records[].record_id, query, answer, llm_used, answer_source, model, response_time_ms, timestamp | `traceId`, `session_id` |
