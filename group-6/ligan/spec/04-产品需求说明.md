## 1. 愿景与目标

> 把 `03` §1 的痛点翻译成正面目标。格式："构建 XXX，帮助用户在 XXX 内完成 XXX"。

**示例 — 痛点→目标映射**：

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息分散、无统一入口 | 统一会话问答入口 |
| 复盘成本高 | 会话历史自动沉淀，随时回看 |

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息分散：研报、新闻、数据分布在多个系统，无统一问答入口 | 构建统一投研问答入口，整合研报、新闻、行情数据 |
| 股票信息分散，无行情信息汇总 | 提供股票行情信息聚合展示，支持一站式查看 |
| 研报无关键信息自动提取展示 | 自动提取研报关键信息（标题、评级、目标价、核心观点）并结构化展示 |

## 2. 目标用户

> 把 `03` §2 的一句话展开成具体角色。思考：谁会用？用来做什么？多常用？

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 投研分析师 | 快速查询投研观点与市场解释 | 每天多次 |
| 基金经理 | 查看研报比对信息（评级、目标价），辅助投资决策 | 每天多次 |
| 运营人员 | 查看新闻公告关键词推送，跟踪市场舆情 | 每天数次 |

## 3. 核心业务场景

> 把 `03` §2 提案概要拆成 4~5 条用户路径。每条场景 = 一条用户操作动线。

**示例 — SC-01**：

**SC-01 新建会话并提问**：用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 新建会话并提问 | （见上方示例） |
| SC-02 | 研报搜索与比对 | 用户输入搜索条件（评级、公司名称、目标价）→ 返回最新 10 条研报 → 展示同一公司研报比对信息（评级、目标价、核心观点） |
| SC-03 | 新闻公告查看与推送 | 系统从数据源获取新闻公告 → 提取标题与关键词 → 推送给用户 → 用户可按关键字查询最新 10 条新闻概要及详情 |
| SC-04 | 研报数据接入与落库 | 系统对接数据源 → 获取研报 → 去重、分析、比对 → 落库存储 → 供前端查询展示 |
| SC-05 | 会话历史回看 | 用户进入会话列表 → 选择历史会话 → 查看该会话下所有问答记录 |

## 4. 产品规则

> 把 `03` §4 成功标准 + §3 范围约束展开成可落地的规则。参考方向：输入约束、返回字段、状态管理、降级策略。

| 编号 | 规则 | 来源 |
|------|------|------|
 R-01 | 每条提问必须绑定 `session_id` | 03 §2 "会话式问答" |
| R-02 | `query` 长度 1～500 字符，为空或超长返回明确错误 | 03 §4 "P0 全部可测" |
| R-03 | 回答必须携带 `answer`、`llm_used`、`model`、`answer_source`、`response_time_ms`、`traceId` 字段 | 03 §4 可追溯 |
| R-04 | 三级降级：CoPaw → 百炼 → Demo，不可跳级，降级静默执行，通过 `answer_source` 标识 | 03 §5 风险应对 |
| R-05 | 新建会话标题默认"新会话"；删除会话须级联删除关联问答记录 | 05 US-001 |
| R-06 | 研报搜索支持按评级、公司名称、目标价筛选，默认返回最新 10 条 | 03 §4 / 05 AC-002-01 |
| R-07 | 同一时间段同一公司的研报须自动比对（评级、目标价、核心观点） | 03 §4 |
| R-08 | 新闻公告须提取标题与关键词，支持按关键字查询最新 10 条 | 03 §4 / 05 AC-003 |

## 5. 能力与优先级

> `03` §3 范围表写了"做什么"，04 按 P0/P1 排优先级。P0 = 必须实现，阻塞发布；P1 = 应当实现，不阻塞首版。

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 会话管理（列表 / 新建 / 删除） | **P0** | SC-01, SC-05 |
| 问答提交与三级降级 | **P0** | SC-01 |
| 研报搜索与关键信息展示（标题、评级、目标价、核心观点） | **P0** | SC-02 |
| 同公司研报比对分析（评级、目标价、核心观点） | **P0** | SC-02, SC-04 |
| 新闻公告获取、关键词提取与推送展示 | **P0** | SC-03 |
| 研报数据源对接与落库（获取、去重、分析、比对） | **P0** | SC-04 |
| 健康检查与能力探测 | **P1** | — |

## 6. 验收与成功标准（PRD 层）

> 从 `03` §4 可度量标准出发，加上演示条件。
> **参考句式**："种子数据 ≥ N 条下，XXX 在 N 分钟内完成"

| 标准 | 度量 |
|------|------|
| 可演示 | 种子数据 ≥ 10 条下，主路径 + 历史 + 能力状态 **3 分钟内**演示完毕 |
| 离线可用 | 未配置密钥时系统仍返回离线演示回复（`answer_source=demo`） |
| 研报搜索可用 | 按评级/公司名称/目标价搜索，1 秒内返回最新 10 条研报及比对信息 |
| 新闻推送可用 | 对接至少一个数据源，完成新闻获取、关键词提取、展示及推送全链路 |

> **04 定"做什么、多重要"；05 定"谁要什么、怎么验收"。** 填写完本文后，下一步进入 `05` 将场景拆成 US + AC。

| 本文（PRD） | 作用 | 05 中落地 |
