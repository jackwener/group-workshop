> **本文只做一件事**：按用户能理解的子场景拆成多条 **User Story**，并为每条写清 **REQ-ID**、**验收标准（AC）**。

## 字段说明 — 每条 UserStory 必须包含以下字段

| 字段 | 填写说明 | 数据来源 ← | 流向下游 → |
|------|----------|------------|-----------|
| **需求编号** | 唯一编号，如 REQ-SR-001 | ← `02` 采集编号 | → `14` 追踪矩阵首列 |
| **故事** | 作为【角色】，我希望【行为】，以便【价值】 | ← `04` PRD 场景拆解 | → `06` FSD 功能点 |
| **优先级** | P0（必须）/ P1（应该）/ P2（可选） | ← `03` §4 成功标准 | → `12` 里程碑排期 |
| **来源** | 对应 03/04 哪一条需求 | ← `03` 范围 · `04` 场景 | |
| **验收标准** | AC，每条可独立验证 | ← 故事 + `07` NFR | → `13` 测试用例依据 |

## US-001（P0）股票搜索

| 字段 | 内容 |
|------|------|
| **需求编号** | REQ-SR-001 |
| **故事** | 作为个人投资者，我希望在搜索框输入股票名称或代码后自动展示匹配建议，以便快速定位目标股票 |
| **优先级** | P0 |
| **来源** | ← 03 §3 / 04 SC-01 |
| **前置条件** | 用户已打开首页 |
| **功能对齐** | → 06 §2 首页布局 · 07 §1 延迟 SLO |
| **设计对齐** | → 08 §1 架构 · 09 `/api/v1/stock/search` · 11 §4 接口安全 |
| **验证对齐** | → 13 TC-SR-001~003 · 14 第1行 |

| 验收标准 | 描述（每条可独立测试） |
|----------|----------------------|
| AC-001-01 | 输入至少 1 个字符后，防抖 300ms 触发搜索请求 |
| AC-001-02 | 搜索结果以下拉列表展示，每项包含股票名称和代码 |
| AC-001-03 | 点击搜索建议项后，跳转到 `/stock/:secid` 详情页 |
| AC-001-04 | 搜索 API 返回结果在 3 秒内展示 |
