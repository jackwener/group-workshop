## 一、测试分层

| 层级 | 工具 | 覆盖对象 | 说明 |
|------|------|----------|------|
| **L1 Unit** | pytest | Service 层方法、工具函数 | 不依赖网络，mock 外部 API |
| **L2 Integration** | pytest + Flask test_client | API 端点 + 参数校验 | 模拟 HTTP 请求 |
| **L3 Contract** | pytest + schema 断言 | 响应体结构与 `09` 一致 | 验字段名、类型 |
| **L4 E2E** | 浏览器手动验证 / Playwright | 完整用户旅程 | 搜索→详情→各 Tab |

## 二、用例拆分原则

> **核心理念：数"可独立失败的点"** — 每条 TC 只回答一个问题，失败时不看代码就知道哪里坏了。

| 来源 | 计数方法 | 示例 |
|------|----------|------|
| 正常路径 | 每个端点的 happy path = 1 条 | `GET /stock/search → 200` = TC-SR-001 |
| 错误码 | 每个 distinct error code = 1 条 | `PARAM_ERROR` = TC-SR-002 |
| 边界条件 | 每个边界值 = 1 条 | keyword 空串 = TC-SR-003 |
| 数据转换 | 每个计算逻辑 = 1 条 | 同比计算 = TC-SR-008 |

## 四、质量门禁

| Gate-ID | 条件 | 阻塞合并 |

### 执行命令

```bash
# 后端测试
cd stock-research/backend
python -m pytest tests/ -q

# 后端测试 + 覆盖率
python -m pytest tests/ -q --cov=app --cov-report=term-missing

# 前端构建检查
cd stock-research/frontend
npm run build

# 前端 lint
npm run lint
```

## 五、TDD 适用场景

| 场景 | TDD 价值 | 建议 |
|------|----------|------|
| 简单 CRUD（会话列表、删除） | 低 | 写完补测试 |
| 参数校验 / 错误码 | 中 | 建议 TDD |
| 同比/环比计算 | **高** | **强烈建议 TDD** |
| 缓存 TTL 逻辑 | 中 | 建议 TDD |
| 滑动窗口上下文 | **高** | **强烈建议 TDD** |
