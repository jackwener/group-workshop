# 04 — 产品需求说明（PRD）

---

| 项 | 值 |
|---|---|

| 文档版本 | v1.0 |

---

> **04 的定位**：`03` 说了"为什么做"，04 翻译成"做什么、不做什么、多重要"。`05` 再拆成用户故事和验收标准。

## 1. 愿景与目标

| 03 痛点 | 04 目标 |
|---------|---------|
| 数据分散、无统一入口 | 统一搜索入口，一个页面展示股票全维度信息 |
| 涨跌分析困难 | AI 自动生成涨跌原因分析报告，结合行情与新闻 |
| 多页面跳转效率低 | 4 Tab 详情页聚合财务/分析/概况/问答 |
| 缺少 AI 辅助工具 | 集成多轮对话 AI 问答，支持会话上下文管理 |

## 2. 目标用户

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 个人投资者 | 查询股票行情与财务数据，了解涨跌原因 | 每天多次 |
| 投研学习者 | 通过 AI 问答学习股票分析方法 | 每周数次 |
| 课程评审者 | 验证平台功能完整性和技术实现 | 项目评审时 |

## 3. 核心业务场景

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 股票搜索 | 用户在首页搜索框输入股票名称/代码 → 防抖 300ms → 下拉展示搜索建议 → 点击目标股票 → 跳转详情页 |
| SC-02 | 查看财务数据 | 用户在详情页点击"财务数据" Tab → 展示 Recharts 双柱图（营收红+利润紫）+ 同比折线 + 数据表格 |
| SC-03 | 查看涨跌分析 | 用户点击"涨跌分析" Tab → 后端拉取行情+新闻→DashScope 生成分析 → 展示 AI 分析卡片 + 新闻列表 |
| SC-04 | 查看公司概况 | 用户点击"公司概况" Tab → 展示基本信息卡片（行业/上市日期）+ 主营业务 + 公司简介 |
| SC-05 | AI 问答 | 用户点击"AI 问答" Tab → 新建/选择会话 → 输入问题 → AI 回复（含股票上下文）→ 支持多轮追问 |

## 4. 产品规则

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 搜索防抖间隔 300ms，最少输入 1 个字符触发搜索 | 03 §4 "搜索可用" |
| R-02 | AI 问答每条消息必须绑定 `session_id` | 03 §3 "会话管理" |
| R-03 | 涨跌分析回答必须包含分析文本和相关新闻列表 | 03 §4 "AI 分析可用" |
| R-04 | 会话管理：最近 20 条消息传给 LLM（滑动窗口） | 03 §3 "AI 问答" |
| R-05 | 2 小时不活动的会话自动清理 | 03 §3 "内存存储" |
| R-06 | 东方财富 API 响应需 TTL 缓存，避免频繁调用 | 03 §5 "反爬限制" |

## 5. 能力与优先级

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 股票搜索（防抖自动补全 + 跳转） | **P0** | SC-01 |
| 实时行情展示（PriceHeader） | **P0** | SC-01~SC-05 |
| 财务数据可视化（图表 + 表格） | **P0** | SC-02 |
| 涨跌原因分析（AI 生成） | **P0** | SC-03 |
| 公司概况展示 | **P0** | SC-04 |
| AI 多轮问答 + 会话管理 | **P0** | SC-05 |
| 骨架屏加载态 | **P1** | 全局 |
| 错误降级 UI | **P1** | 全局 |

## 6. 验收与成功标准（PRD 层）

| 标准 | 度量 |
|------|------|
| 搜索可演示 | 输入"贵州茅台" → 3 秒内出现下拉建议 → 点击进入详情页 |
| 行情可展示 | 详情页 PriceHeader 正确显示股票名称、代码、实时价格、涨跌幅、成交量、市值 |
| 财务可视化 | 财务数据 Tab 渲染双柱图 + 同比折线 + 数据表格，数据与东方财富一致 |
| AI 全链路 | AI 问答 Tab 完成"新建会话 → 提问 → 回复 → 切换会话 → 删除会话"全流程 |
