> **04 的定位**：`03` 说了"为什么做"，04 翻译成"做什么、不做什么、多重要"。`05` 再拆成用户故事和验收标准。

## 1. 愿景与目标

> 把 `03` §1 的痛点翻译成正面目标。格式："构建 XXX，帮助用户在 XXX 内完成 XXX"。

**示例 — 痛点→目标映射**：

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息分散、无统一入口 | 统一会话问答入口 |
| 复盘成本高 | 会话历史自动沉淀，随时回看 |

| 03 痛点 | 04 目标 |
|---------|---------|
| 研报内容为非结构化文本，需要手动提取核心数据 | 构建研报结构化解析能力，帮助用户在秒级内自动提取研报标题、研究对象、券商、评级、目标价、核心观点 |
| 同一研究对象的多份研报无法横向对比 | 构建研报对比功能，帮助用户快速对比不同券商对同一上市公司的观点差异 |
| 阅读研报时需要另行查询股票价格 | 构建股票实时价格查询功能，帮助用户在研报阅读界面内实时获取股票当前价格 |

## 2. 目标用户

> 把 `03` §2 的一句话展开成具体角色。思考：谁会用？用来做什么？多常用？

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 投研分析师 | 快速解析研报核心数据，横向对比不同券商观点，实时查询股票价格 | 每天多次 |
| 基金经理 | 查看研报核心观点，辅助投资决策 | 每天数次 |
| 研究员实习生 | 学习研报分析方法，快速获取研报要点 | 每周数次 |

## 3. 核心业务场景

> 把 `03` §2 提案概要拆成 4~5 条用户路径。每条场景 = 一条用户操作动线。

**示例 — SC-01**：

**SC-01 新建会话并提问**：用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 研报解析 | 用户上传研报文档 → 系统自动解析 → 展示结构化数据（标题、研究对象、券商、评级、目标价、核心观点） |
| SC-02 | 研报对比 | 用户选择同一上市公司的多份研报 → 系统生成对比表格 → 展示不同券商的观点差异 |
| SC-03 | 股票价格查询 | 用户在研报详情页点击股票代码 → 系统调用外部接口 → 展示股票实时价格 |
| SC-04 | 研报管理 | 用户查看已解析研报列表 → 点击进入详情 → 查看/导出结构化数据 |

## 4. 产品规则

> 把 `03` §4 成功标准 + §3 范围约束展开成可落地的规则。参考方向：输入约束、返回字段、状态管理、降级策略。

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 研报解析必须支持 PDF 格式，单文件大小上限 20MB | 03 §3 范围约束 |
| R-02 | 解析结果必须包含：研报标题、研究对象主体（上市公司名称及代码）、研报作者（券商公司）、评级、看涨看跌方向、目标价、核心观点摘要 | 03 §4 成功标准 |
| R-03 | 研报对比必须基于同一研究对象主体，对比字段包括：券商名称、评级、目标价、核心观点 | 03 §3 范围约束 |
| R-04 | 股票价格查询响应时间 ≤ 1 分钟，支持多数据源降级 | 03 §4 成功标准 |
| R-05 | 当外部 LLM 不可用时，系统进入降级模式：CoPaw → 百炼 → Demo 模式兜底 | 03 §5 风险应对 |
| R-06 | 研报内容过大时采用分片解析后合并策略 | 03 §5 风险应对 |
| R-07 | 股价查询接口失效时自动切换备用接口 | 03 §5 风险应对 |

## 5. 能力与优先级

> `03` §3 范围表写了"做什么"，04 按 P0/P1 排优先级。P0 = 必须实现，阻塞发布；P1 = 应当实现，不阻塞首版。

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 研报上传与解析（提取核心数据） | **P0** | SC-01 |
| 研报对比（同一上市公司横向对比） | **P0** | SC-02 |
| 股票实时价格查询 | **P0** | SC-03 |
| 研报列表管理（查看/删除） | **P1** | SC-04 |
| 解析结果导出（Excel/JSON） | **P2** | SC-04 |

## 6. 验收与成功标准（PRD 层）

> 从 `03` §4 可度量标准出发，加上演示条件。
> **参考句式**："种子数据 ≥ N 条下，XXX 在 N 分钟内完成"

| 标准 | 度量 |
|------|------|
| 研报解析成功 | 上传研报后 30 秒内完成解析，成功提取 7 个核心字段（标题、研究对象、券商、评级、方向、目标价、核心观点） |
| 研报对比成功 | 选择同一上市公司多份研报后，5 秒内生成对比表格，正确展示各券商观点 |
| 股价查询成功 | 输入股票代码后 1 分钟内返回实时价格数据 |
| 离线可用 | 外部 LLM 不可用时，系统自动降级至 Demo 模式返回演示数据 |
| 可演示 | 种子数据 ≥ 5 份研报下，主路径（解析+对比+查询）**5 分钟内**演示完毕 |

## 7. 与 05 用户故事的关系

> **04 定"做什么、多重要"；05 定"谁要什么、怎么验收"。** 填写完本文后，下一步进入 `05` 将场景拆成 US + AC。

| 本文（PRD） | 作用 | 05 中落地 |
|-------------|------|-----------|
| §3 核心场景 | 一条叙事场景 → 一条或多条 US | SC-01 → US-001，SC-02 → US-002，SC-03 → US-003 |
| §4 产品规则 | 字段/状态/错误口径 | 拆入各 US 的 AC |
| §5 能力优先级 | P0 / P1 | 与各 US 优先级一致 |
