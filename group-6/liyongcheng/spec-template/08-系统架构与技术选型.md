### 1.2 架构风格

> 选择架构风格时思考：教学场景需要什么样的复杂度？分层带来什么好处？

| 决策 | 选型 | 理由 |
|------|------|------|
| **前后端分离** | React SPA + Flask REST API | 教学清晰度：前端独立开发服务器 |
| **单体部署** | 前后端各一个进程 | 不引入微服务复杂度 |
| **分层架构** | Route → Service → Storage | 替换存储引擎时上层零改动 |
| **多数据源降级** | 股价查询支持多备用接口 | 提升服务可用性，降低单点故障风险 |

## 2. 后端分层结构

> 每层写清"允许做什么、禁止做什么"。

| 层 | 文件 | 允许做 | 禁止做 |
|----|------|--------|--------|
| **Route** | `research_bp.py` | 参数校验、HTTP 状态码、traceId | 直接读写文件、调用 LLM |
| **Service** | `report_service.py` / `compare_service.py` / `stock_service.py` | 降级编排、结果组装、业务逻辑 | 感知 HTTP 请求/响应 |
| **Provider** | `llm_provider.py` / `stock_provider.py` | HTTP 调用外部 API | 操作本地存储 |
| **Storage** | `storage.py` | 文件 CRUD、数据校验 | 调用外部 API |

## 3. 前端架构

| 项 | 选型 | 理由 |
|----|------|------|
| UI 框架 | React（Hooks）≥ 18 | 教学通用性最高 |
| 构建工具 | Vite ≥ 5 | 极快 HMR，零配置启动 |
| 状态管理 | `useState` + `useEffect` | 简单场景足够，无需 Redux |
| HTTP 客户端 | `fetch` API | 浏览器原生，不引入 axios |
| 样式方案 | Tailwind CSS | 原子化 CSS，快速开发，无需维护独立样式文件 |

## 5. 数据存储架构

| 阶段 | 存储 | 变更范围 | 说明 |
|------|------|----------|------|
| **P0（当前）** | JSON 文件 | — | 适合教学，零运维 |

## 7. ADR（架构决策记录）

> 每条 ADR 记录一个"为什么选 A 而不选 B"的决策。至少写 2 条。

**示例 — ADR-001**：为什么选 Flask 而非 FastAPI？Flask 学习曲线低，无需 async/await，学员 Python 基础即可上手。

| ADR | 决策 | 核心理由 |
|-----|------|----------|
| ADR-001 | Flask 而非 FastAPI | 学习曲线低，教学更适合 |
| ADR-002 | JSON 文件存储而非 SQLite | 零运维开销，数据可读性强，便于教学演示 |
| ADR-003 | 前端不拆分过多组件 | 单文件组件足够，降低学员理解成本 |

## 8. 安全架构

> 对齐 `07` 4 安全需求。当前教学版与生产需求的差距。

| 层 | 当前措施 | 生产改进 |
|----|----------|----------|
| 认证 | 无（开放访问） | JWT / 内部 SSO |
| CORS | 全开放 | 白名单 |
| 密钥 | 环境变量 `.env` | Vault / Secrets Manager |
| 文件上传 | 类型+大小校验 | 增加病毒扫描、内容审计 |
