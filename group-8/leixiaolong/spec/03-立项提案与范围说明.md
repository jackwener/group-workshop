## 1. 背景与问题

> 描述用户遇到的问题，至少写 2~3 条痛点。参考：信息获取、历史记录、可追溯性、系统可用性。

| 痛点 | 来源 |
|------|------|
| 信息分散：研报、新闻、数据分布在多个系统，无统一问答入口 | 用户访谈 |
| 研报阅读耗时：每天阅读10+份研报，每份30-50页，耗时2-3小时 | 用户访谈 |
| 研报数量太多，不容易对比：不知道怎样判断高质量研报，需要同时与股票分析结合 | 用户访谈 |
| 深度研报格式格式不一，重复性累赘操作太麻烦 | 用户访谈 |

## 2. 提案概要

> 用 3~5 句话概括要做什么。参考格式："在 XXX 应用内交付 YYY 能力"。要素：会话式问答 · 能力降级 · 可追溯

在投研助手平台增加AI智能研报信息能力；在研报系统增加研报综合能力；在研报系统增加股票查询功能，实现会话式问答与多文档对比，帮助分析师提升研报阅读效率。

## 3. 范围边界

> 明确"做什么"和"不做什么"，避免范围蔓延。各写 3~4 条。

| 做（范围内） | 不做（范围外） |
|-------------|---------------|
| 会话管理：创建、列表、删除 | 多租户/行级数据权限 |
| 提取重点信息，满足用户需求（评级、目标价） | 获取研报数据要合规：数据一定要有来源，不能乱编/真空 |
| 综合评价规则：要结合用户实际需求 | 整体功能风格要和各位保持统一，不能乱发挥 |
| 增加股票查询功能，重要客户交易 |  |
| 系统要设计权限功能 |  |

## 4. 成功标准（可度量）

> 写出 3~4 条可量化的验收标准。句式：用户在 X 分钟内完成 XXX 全链路 / 未配置外部模型时返回 XXX

| 标准 | 度量方式 |
|------|----------|
| 主路径可走通 | 用户在 3 分钟内完成"新建会话 → 提问 → 查看历史"全链路 |
| 数据可溯源 | 用户获取对应一份研究报告，在指定官网能查到 |
| 权限系统可通 | 不同用户访问，没有权限的用户访问会提示无权限 |

## 5. 风险（简表）

> 列出 2~3 个主要风险。常见方向：外部依赖不可用、数据存储并发、模块间契约延期。

| 风险 | 影响 | 应对 |
|------|------|------|
| 外部 LLM 不可用 | 问答功能降级 | 三级降级：CoPaw → 百炼 → Demo 模式兜底 |
| 外部研报数据不可用 | 在线搜索功能不可用 | 数据转为内部留存的数据，或者通过下载内部数据方式使用 |

## 6. 立项前置条件（Go / No-Go）

- ☐ 后端与前端可独立启动
- ☐ 演示数据目录可读写
- ☐ 样本研测数据集准备完成（至少10份不同格式研报）
- ☐ 外部数据源对接完成（合规性确认）
