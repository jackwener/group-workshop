## 1. 里程碑（S1～S4）

> **切分原则**：每刀切出一个**可演示的用户价值**。不是"接口写好了"，而是"能给业务看什么"。

**示例 — S1**：

**S1 会话管理**：创建/列表/删除会话 API + 前端会话侧栏 → 满足 REQ-001 部分 → 验证 TC-M01-020～025

| 阶段 | 交付要点（可演示） | 满足的 REQ/US | 验证 TC |
|------|-------------------|---------------|----------|
| **S1** 会话管理 | 会话 CRUD API + 前端侧栏：新建/列表/删除会话，按时间降序排列 | REQ-001 (US-001) | TC-M01-020～025 |
| **S2** 问答核心 | 问答提交 API + 三级降级 + 前端对话区：输入问题→获得回答（含来源标识）→查看历史记录 | REQ-002 (US-002) 部分 + REQ-005 (US-005) | TC-M01-001～004, 005, 030～031 |
| **S3** 研报上传与对比 | 文件上传解析 + 研报对比查询页：PDF/Word/Excel 上传→AI 提取重点信息 + 多维度筛选分页浏览研报 | REQ-002 (US-002) 全部 + REQ-003 (US-003) | TC-M01-048～051 |
| **S4** 收口与发布 | 健康检查 + 权限控制 + E2E 全链路验证：能力状态芯片显示 + 无权限用户 403 提示 + 3分钟演示全流程 | REQ-004 (US-004) + 权限控制 | TC-M01-052～055, E2E |

## 2. WBS 任务拆分

> **拆分原则**：按**工程职责**切（路由、存储、Agent、前端），不按功能切。一个 W 可跨多个 S 迭代推进。

| 任务ID | 任务名称 | 具体内容 | DoD（指向 Spec） | 推进阶段 |
|--------|----------|----------|------------------|----------|
| W1 | 路由实现 | `agent_bp.py` 端点注册、参数校验 | 对齐 09 端点与错误码 | S1 起贯穿 S4 |
| W2 | 存储层 | `storage.py` JSON CRUD + 4个实体 | 对齐 10 数据模型 | S1～S3 |
| W3 | Agent 编排 | 三级降级逻辑 + 权限验证 | 对齐 07 降级策略 + 11 安全 | S2～S3 |
| W4 | 前端视图 | React 四态渲染 + 会话/对话/对比页 | 对齐 06 功能规格 | S1～S4 |
| W5 | 文件处理 | 文件上传、格式校验、key_points 提取 | 对齐 09 /upload 端点 | S3 |
| W6 | 测试门禁 | pytest 用例 + 质量门禁配置 | 对齐 13 测试策略 | S2～S4 |

## 5. 依赖与风险

**示例 — 依赖链**：

**S1 会话管理** → **S2 问答核心**（必须先有会话才能提问）→ **S3 历史与状态** → **S4 发布准备**

| 风险 | 影响 | 应对 |
|------|------|------|
| 外部 LLM 不可用 | 问答功能降级 | 三级降级：CoPaw → 百炼 → Demo 模式兜底 |
| 外部研报数据不可用 | 在线搜索功能不可用 | 数据转为内部留存，或通过下载内部数据方式使用 |
| **文件解析失败** | **上传功能不可用** | **返回明确错误提示，支持重试** |
