## 1. 安全目标与合规要求

> 明确本模块需遵循的安全目标和外部合规标准。投研场景尤其关注数据隐私与内部信息防泄露。

| 安全目标 | 说明 | 对应合规 |
|----------|------|----------|
| 数据不出域 | 所有用户数据、研报内容、问答记录禁止传输至外部服务 | 内部信息安全规范 |
| 最小权限原则 | 每个组件只拥有完成任务所需的最低权限 | 安全设计最佳实践 |
| **权限可控** | **基于角色的访问控制，无权限用户禁止访问** | **03 §3 "系统要设计权限功能"** |

## 2. 认证与授权

> 定义用户身份验证方式和权限控制模型。写出认证流程和角色划分。

### 2.1 认证机制

| 项目 | 规格 |
|------|------|
| 认证方式 | **基于角色的权限控制（RBAC），通过 user.role 字段验证** |
| **权限验证时机** | **每次 API 请求前验证 session_id 与用户权限绑定** |
| **权限拒绝响应** | **返回 403 PERMISSION_DENIED，前端禁用所有操作** |

## 3. 数据安全

> 定义数据分类分级、加密策略、存储安全规范。**投研场景核心关注点**。

### 3.1 数据分类与分级

| 数据类型 | 安全等级 | 示例 | 保护措施 |
|----------|----------|------|----------|
| 研报原文 | **机密** | PDF/HTML 研报文件 | 加密存储，访问审计 |
| 问答记录 | **内部** | 用户提问与AI回答 | 存储加密，定期清理 |
| 用户信息 | **内部** | 用户名、角色、操作日志 | 脱敏展示，最小采集 |
| 系统配置 | 一般 | 模型参数、界面配置 | 版本控制 |

### 3.2 加密策略

| 场景 | 加密方式 | 说明 |
|------|----------|------|
| 传输加密 | **HTTPS/TLS 1.2+** | **所有 API 通信强制 HTTPS** |
| 存储加密 | **JSON 文件权限 600** | **仅 owner 可读写，防止未授权访问** |
| 密钥管理 | **环境变量 `.env`** | **密钥不硬编码，不入代码仓库** |

## 4. 接口安全

> 与 `09` API 规格配合，定义 API 层面的安全防护措施。

| 防护措施 | 实现方式 | 说明 |
|----------|----------|------|
| 输入校验 | 服务端白名单校验 | 所有用户输入进行类型、长度、格式校验（对齐 09 §11） |
| **文件上传校验** | **格式白名单 + 大小限制** | **仅允许 PDF/Word/Excel，≤10MB** |
| XSS 防护 | 输出转义 + CSP | 研报内容渲染时防止脚本注入 |
| **CSRF 防护** | **SameSite Cookie + CORS 白名单** | **状态变更接口需验证来源** |
| 速率限制 | **100 req/min/user** | 防止接口滥用，超出返回 429 |

## 5. LLM / AI 安全

> 针对大模型集成的专项安全措施。投研场景数据敏感，需严格管控数据流向。

| 风险点 | 防护措施 | 验收标准 |
|--------|----------|----------|
| 数据外泄至第三方模型 | 本地部署模型 / 内网百炼服务，禁止调用外网 API | 网络出口审计零外传记录 |
| Prompt 注入攻击 | 系统 Prompt 隔离，用户输入预处理过滤 | **用户输入不得覆盖系统 Prompt** |
| 模型幻觉 / 错误信息 | 回答标注来源引用，标识 answer_source | **每条回答必须携带 answer_source 字段** |
| 敏感信息泄露（模型回复） | 输出过滤层，正则匹配敏感信息并脱敏 | **返回内容不包含 API Key/密码等敏感信息** |

## 6. 审计与日志

> 定义安全审计日志的记录范围、保留策略。

| 事件类型 | 记录内容 | 保留期限 | 告警 |
|----------|----------|----------|------|
| **权限验证失败** | **用户ID、时间、IP、请求端点** | **180天** | **连续失败 ≥5 次告警** |
| **文件上传** | **用户ID、文件名、大小、处理结果** | **365天** | **大文件（>5MB）上传告警** |
| **降级触发** | **降级原因、切换时间、provider** | **365天** | **连续降级到 demo 模式告警** |
| 系统配置变更 | 变更人、变更前后值 | 永久 | 关键配置变更即时通知 |

## 7. 安全威胁清单（STRIDE 简表）

> 基于 STRIDE 模型，列出主要安全威胁与应对方案。

| 类型 | 威胁 | 风险等级 | 应对措施 | 负责人 |
|------|------|----------|----------|--------|
| S | 伪造用户身份访问研报 | **高** | **RBAC 权限校验 + session_id 绑定** | **后端开发** |
| T | 研报内容在传输中被篡改 | 中 | TLS + 文件哈希校验 | **运维** |
| I | 内部数据通过AI模型泄露 | **高** | **本地部署 + 输出过滤 + answer_source 标识** | **AI工程师** |
| D | 大量请求导致服务不可用 | 中 | 速率限制 + 三级降级策略 | **后端开发** |
| **E** | **越权访问他人会话** | **高** | **session_id 与用户权限绑定校验** | **后端开发** |
| **R** | **敏感数据被重放攻击** | **中** | **traceId 唯一性校验 + 时间戳过期** | **后端开发** |

## 8. 部署安全

> 定义部署架构中的安全要求。

- [x] 生产/开发环境**严格隔离**，数据不互通
- [x] 数据库访问仅限应用服务器 IP 白名单
- [x] 敏感配置（API Key、密码）通过环境变量注入，不入代码仓库
- [x] 依赖包定期安全扫描（`pip audit` / `npm audit`）
- [x] **JSON 文件权限 600，仅 owner 可读写**
- [x] **CORS 限定域名白名单，禁止全开放**
