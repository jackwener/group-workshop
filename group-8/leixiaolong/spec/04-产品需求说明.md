> **04 的定位**：`03` 说了"为什么做"，04 翻译成"做什么、不做什么、多重要"。`05` 再拆成用户故事和验收标准。

## 1. 愿景与目标

> 把 `03` §1 的痛点翻译成正面目标。格式："构建 XXX，帮助用户在 XXX 内完成 XXX"。

**示例 — 痛点→目标映射**：

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息分散：研报、新闻、数据分布在多个系统，无统一问答入口 | 统一会话问答入口，集成研报、新闻、数据的统一查询能力 |
| 研报阅读耗时：每天阅读10+份研报，每份30-50页，耗时2-3小时 | AI自动提取研报重点信息，减少人工阅读时间至30分钟内 |
| 研报数量太多，不容易对比：不知道怎样判断高质量研报，需要同时与股票分析结合 | 提供研报对比功能，支持多维度筛选和评分标签 |
| 深度研报格式格式不一，重复性累赘操作太麻烦 | 支持PDF/Word/Excel多格式上传，自动解析提取关键信息 |

## 2. 目标用户

> 把 `03` §2 的一句话展开成具体角色。思考：谁会用？用来做什么？多常用？

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 投研分析师 | 快速查询投研观点与市场解释，AI辅助研报重点提取 | 每天多次 |
| 高级分析师 | 对比多份研报质量，获取综合评价，辅助投资决策 | 每天1-2次 |
| 投资经理 | 查询股票信息，跟踪重要客户交易动态 | 每天多次 |

## 3. 核心业务场景

> 把 `03` §2 提案概要拆成 4~5 条用户路径。每条场景 = 一条用户操作动线。

**示例 — SC-01**：

**SC-01 新建会话并提问**：用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 新建会话并提问 | 用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库 |
| SC-02 | 上传研报并解析 | 用户选择PDF/Word/Excel文件（≤10MB）→ 上传至会话 → AI提取重点信息（评级、目标价）→ 返回结构化结果 |
| SC-03 | 查看与管理会话历史 | 用户打开首页 → 会话列表按时间降序展示 → 右键选择删除 → 二次确认后删除会话及关联记录 |
| SC-04 | 研报对比查询 | 用户进入研报对比页面 → 按公司/行业/发布人/时间检索 → 查看评分标签 → 分页浏览（每页10条）→ 选择多份研报对比 |

## 4. 产品规则

> 把 `03` §4 成功标准 + §3 范围约束展开成可落地的规则。参考方向：输入约束、返回字段、状态管理、降级策略。

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 每条提问必须绑定 `session_id`，无会话ID的请求返回400错误 | 03 §2 "会话式问答" |
| R-02 | `query` 长度 1～500 字符，为空或超长返回 `EMPTY_QUERY` 错误 | 03 §4 "P0 全部可测" |
| R-03 | 回答必须携带 `answer`、`answer_source`（copaw/bailian/demo）、`traceId` 字段 | 03 §5 "三级降级策略" |
| R-04 | 三级降级策略：CoPaw → 百炼 → Demo，LLM不可用时自动降级并返回 `answer_source` 标识 | 03 §5 "风险应对" |
| R-05 | 会话列表按 `created_at` 降序排列，新建会话后自动出现在列表首位 | 05 US-001 AC-001-02 |
| R-06 | 上传文件格式限制：仅支持 PDF/Word/Excel，文件大小 ≤10MB，超限返回 `FILE_TOO_LARGE` | 05 US-002 AC-002-01/02/03 |
| R-07 | 权限控制：无权限用户访问会话列表或提交问答时返回 `PERMISSION_DENIED` (403) | 03 §3 "系统要设计权限功能" |
| R-08 | 研报对比查询支持分页，默认 `page_size=10`，支持按公司/行业/发布人/时间检索 | 05 US-003 AC-003-02 |

## 5. 能力与优先级

> `03` §3 范围表写了"做什么"，04 按 P0/P1 排优先级。P0 = 必须实现，阻塞发布；P1 = 应当实现，不阻塞首版。

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 会话管理（列表 / 新建 / 删除） | **P0** | SC-01, SC-03 |
| 问答提交与三级降级 | **P0** | SC-01 |
| 研报上传与解析（PDF/Word/Excel） | **P0** | SC-02 |
| 研报对比查询（多维度检索+分页） | **P0** | SC-04 |
| 权限控制与访问限制 | **P0** | SC-01, SC-02, SC-03, SC-04 |
| 健康检查与组件状态监控 | **P1** | 运维监控 |

## 6. 验收与成功标准（PRD 层）

> 从 `03` §4 可度量标准出发，加上演示条件。
> **参考句式**："种子数据 ≥ N 条下，XXX 在 N 分钟内完成"

| 标准 | 度量 |
|------|------|
| 可演示 | 种子数据 ≥ 10 条下，主路径 + 历史 + 能力状态 **3 分钟内**演示完毕 |
| 离线可用 | 未配置密钥时系统仍返回离线演示回复（`answer_source=demo`） |
| 权限可验证 | 不同用户访问，无权限用户收到 403 `PERMISSION_DENIED` 错误提示 |
| 数据可溯源 | 用户获取的研究报告可在指定官网查证，回答携带 `answer_source` 标识来源 |

## 7. 与 05 用户故事的关系

> **04 定"做什么、多重要"；05 定"谁要什么、怎么验收"。** 填写完本文后，下一步进入 `05` 将场景拆成 US + AC。

| 本文（PRD） | 作用 | 05 中落地 |
|-------------|------|-----------|
| §3 核心场景 | 一条叙事场景 → 一条或多条 US | SC-01 → US-001 + US-002 |
| §4 产品规则 | 字段/状态/错误口径 | 拆入各 US 的 AC |
| §5 能力优先级 | P0 / P1 | 与各 US 优先级一致 |
