## 1. 架构总览

### 1.1 系统上下文

```
┌─────────────────────────────────┐
│       用户浏览器 React SPA       │
│       http://localhost:5173     │
└──────────────┬──────────────────┘
               │ HTTP  /api/v1/report/*
               ▼
┌─────────────────────────────────┐
│     Flask Backend (WSGI)        │
│     http://localhost:5000       │
│  ┌────────────────────────────┐ │
│  │  report_bp — API 端点      │ │
│  │    ↓          ↓         ↓  │ │
│  │ ReportAgent Storage Parser │ │
│  └────┬──────────┬────────────┘ │
│       ▼          ▼              │
│  ┌────────┐ ┌──────────┐       │
│  │ LLM 层 │ │ 文件系统  │       │
│  │百炼    │ │ ./data/  │       │
│  │Demo    │ │ *.json   │       │
│  └────────┘ └──────────┘       │
└─────────────────────────────────┘
```

### 1.2 架构风格

> 选择架构风格时思考：教学场景需要什么样的复杂度？分层带来什么好处？

| 决策 | 选型 | 理由 |
|------|------|------|
| **前后端分离** | React SPA + Flask REST API | 教学清晰度：前端独立开发服务器 |
| **单体部署** | 前后端各一个进程 | 不引入微服务复杂度 |
| **分层架构** | Route → Agent → Storage/Parser | 替换存储引擎时上层零改动 |
| **外部LLM** | 支持百炼等外部服务 | 获得更智能分析能力 |

## 2. 后端分层结构

> 每层写清"允许做什么、禁止做什么"。

| 层 | 文件 | 允许做 | 禁止做 |
|----|------|--------|--------|
| **Route** | `report_bp.py` | 参数校验、HTTP 状态码、traceId | 直接读写文件、调用 LLM |
| **Agent** | `agent.py` | 降级编排、结果组装 | 感知 HTTP 请求/响应 |
| **Provider** | `local_llm.py` / `bailian_qa.py` | HTTP 调用外部 API | 操作本地存储 |
| **Parser** | `parser.py` | PDF/HTML/Word/PPT解析、URL抓取、信息提取 | 调用外部 API |
| **Storage** | `storage.py` | 文件 CRUD、数据校验 | 调用外部 API |

## 3. 前端架构

### 3.1 技术选型

| 项 | 选型 | 理由 |
|----|------|------|
| UI 框架 | React（Hooks）≥ 18 | 教学通用性最高 |
| 构建工具 | Vite ≥ 5 | 极快 HMR，零配置启动 |
| 状态管理 | `useState` + `useEffect` | 8 个 state 变量足够 |
| HTTP 客户端 | `fetch` API | 浏览器原生，不引入 axios |
| 样式方案 | CSS Modules | 组件级样式隔离 |

### 3.2 视觉风格（南方基金风格）

> 前端视觉设计与南方基金官网保持一致，详见 `06` §0 视觉设计规范。

| 设计要素 | 规格 |
|----------|------|
| **主色调** | `#004098`（南方基金蓝） |
| **背景色** | Header `#004098`，Sidebar `#EFF4F9`，Main `#FFFFFF` |
| **字体** | 系统字体栈，正文 14px |
| **圆角** | 按钮/输入框 8px，卡片 0px（直角） |
| **阴影** | 轻微阴影 `0 2px 8px rgba(0,0,0,0.08)` |

### 3.3 组件库策略

| 策略 | 说明 |
|------|------|
| **基础组件** | 手写 CSS，严格遵循南方基金色彩规范 |
| **布局组件** | 使用 CSS Flexbox/Grid 自定义实现 |
| **图标** | 使用 Lucide React 或 Heroicons，保持简洁线性风格 |
| **无重型UI库** | 不引入 Ant Design / Material UI，保持轻量定制 |

## 7. ADR（架构决策记录）

> 每条 ADR 记录一个"为什么选 A 而不选 B"的决策。至少写 2 条。

| ADR | 决策 | 核心理由 |
|-----|------|----------|
| ADR-001 | Flask 而非 FastAPI | 学习曲线低，教学更适合 |
| ADR-002 | JSON文件而非数据库 | 部署简单，满足教学场景 |
| ADR-003 | 外部LLM优先 | 获得更智能的分析能力 |
| ADR-004 | 南方基金风格设计系统 | 保持与母公司品牌一致性，传递专业金融形象 |

## 8. 安全架构

> 对齐 `07` 4 安全需求。当前教学版与生产需求的差距。
