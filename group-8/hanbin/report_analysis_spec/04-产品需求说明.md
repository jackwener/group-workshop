> **04 的定位**：`03` 说了"为什么做"，04 翻译成"做什么、不做什么、多重要"。`05` 再拆成用户故事和验收标准。

## 1. 愿景与目标

> 把 `03` §1 的痛点翻译成正面目标。格式："构建 XXX，帮助用户在 XXX 内完成 XXX"。

**示例 — 痛点→目标映射**：

| 03 痛点 | 04 目标 |
|---------|---------|
| 研报阅读耗时 | 研报智能解析，3分钟内提取关键信息 |
| 关键信息提取不完整 | 自动提取评级、目标价、核心观点，准确率≥85% |
| 多份研报对比困难 | 一键生成多份研报对比表 |
| 外部大模型支持 | 使用百炼等外部LLM服务 |

## 2. 目标用户

> 把 `03` §2 的一句话展开成具体角色。思考：谁会用？用来做什么？多常用？

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 投研分析师 | 快速解析研报、提取关键信息、多份对比 | 每天多次 |
| 高级研究员 | 深度研报问答、核心观点溯源 | 每天多次 |
| 投资经理 | 快速浏览研报摘要、获取评级信息 | 每周多次 |

## 3. 核心业务场景

> 把 `03` §2 提案概要拆成 4~5 条用户路径。每条场景 = 一条用户操作动线。

**示例 — SC-01**：

**SC-01 上传研报并提取信息**：用户点击“上传研报” → 选择PDF/HTML/Word/PPT文件或输入URL链接 → 系统自动提取标题、评级、目标价、核心观点 → 展示提取结果

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 上传研报并提取信息 | （见上方示例） |
| SC-02 | 研报问答交互 | 用户在研报详情页输入问题 → 系统基于研报内容回答 → 展示答案及原文引用 |
| SC-03 | 多份研报对比 | 用户选择2-3份研报 → 点击"生成对比" → 系统生成关键指标对比表 |
| SC-04 | 会话管理 | 用户创建新会话 → 上传研报 → 进行问答 → 查看历史会话列表 |

## 4. 产品规则

> 把 `03` §4 成功标准 + §3 范围约束展开成可落地的规则。参考方向：输入约束、返回字段、状态管理、降级策略。

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 研报文件格式限制为PDF、HTML、Word、PPT或URL链接，单文件大小≤50MB | 03 §3 范围边界 |
| R-02 | 提取的关键信息必须包含：标题、评级、目标价、核心观点 | 03 §4 成功标准 |
| R-03 | 问答必须基于已上传研报内容，禁止虚构信息 | 03 §2 提案概要 |
| R-04 | 多份研报对比最多支持3份，对比维度包括评级、目标价、核心观点 | 03 §3 范围边界 |
| R-05 | 系统支持使用外部大模型服务 | 03 §3 范围边界 |

## 5. 能力与优先级

> `03` §3 范围表写了"做什么"，04 按 P0/P1 排优先级。P0 = 必须实现，阻塞发布；P1 = 应当实现，不阻塞首版。

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 研报解析（PDF/HTML/Word/PPT/URL提取） | **P0** | SC-01 |
| 研报问答（基于内容问答） | **P0** | SC-02 |
| 会话管理（列表 / 新建 / 删除） | **P0** | SC-04 |
| 多份研报对比 | **P1** | SC-03 |
| 原文引用展示 | **P1** | SC-02 |

## 6. 验收与成功标准（PRD 层）

> 从 `03` §4 可度量标准出发，加上演示条件。
> **参考句式**："种子数据 ≥ N 条下，XXX 在 N 分钟内完成"

| 标准 | 度量 |
|------|------|
| 可演示 | 种子数据 ≥ 3 份研报下，主路径 + 问答 + 对比 **5 分钟内**演示完毕 |
| 提取准确率 | 关键字段（评级、目标价、核心观点）提取准确率 ≥ 85% |
| 降级可用 | 外部LLM不可用时自动降级到Demo模式 |
| 对比响应 | 3份以内研报对比响应时间 < 10 秒 |

## 7. 与 05 用户故事的关系

> **04 定"做什么、多重要"；05 定"谁要什么、怎么验收"。** 填写完本文后，下一步进入 `05` 将场景拆成 US + AC。

| 本文（PRD） | 作用 | 05 中落地 |
|-------------|------|-----------|
| §3 核心场景 | 一条叙事场景 → 一条或多条 US | SC-01 → US-001 + US-002 |
| §4 产品规则 | 字段/状态/错误口径 | 拆入各 US 的 AC |
| §5 能力优先级 | P0 / P1 | 与各 US 优先级一致 |
