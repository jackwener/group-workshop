## 1. 背景与问题

> 描述用户遇到的问题，至少写 2~3 条痛点。参考：信息获取、历史记录、可追溯性、系统可用性。

| 痛点 | 来源 |
|------|------|
| 研报阅读耗时：每天阅读10+份研报，每份30-50页，耗时2-3小时 | S-01 会议纪要 |
| 关键信息提取不完整：需手动提取评级、目标价、核心观点 | S-02 邮件沟通 |
| 多份研报对比困难：各家格式不同，需手动整理到Excel | S-03 用户访谈 |
| 研报处理效率低：手动提取信息耗时耗力 | S-03 用户访谈 |

## 2. 提案概要

> 用 3~5 句话概括要做什么。参考格式："在 XXX 应用内交付 YYY 能力"。要素：会话式问答 · 能力降级 · 可追溯

在投研工作场景内交付研报智能分析能力。支持PDF/HTML/Word/PPT格式研报上传及URL链接输入，自动提取关键信息（标题、评级、目标价、核心观点）。提供基于研报内容的自然语言问答，支持引用原文。支持多份研报关键指标自动对比生成对比表。系统支持使用外部大模型服务（如百炼）进行智能分析。

## 3. 范围边界

> 明确"做什么"和"不做什么"，避免范围蔓延。各写 3~4 条。

| 做（范围内） | 不做（范围外） |
|-------------|---------------|
| 研报解析：支持PDF/HTML/Word/PPT格式及URL链接，提取标题、评级、目标价、核心观点 | 实时股票行情数据接入 |
| 研报问答：基于上传研报内容的自然语言问答 | 研报自动采集/爬虫功能 |
| 研报对比：多份研报关键指标自动生成对比表 | 多租户/行级数据权限 |
| 外部大模型：支持百炼等外部LLM服务 | 本地模型部署 |
| 会话管理：创建、列表、删除研报分析会话 | 研报原文编辑功能 |

## 4. 成功标准（可度量）

> 写出 3~4 条可量化的验收标准。句式：用户在 X 分钟内完成 XXX 全链路 / 未配置外部模型时返回 XXX

| 标准 | 度量方式 |
|------|----------|
| 主路径可走通 | 用户在 5 分钟内完成"上传研报 → 提取关键信息 → 问答交互"全链路 |
| 信息提取完整度 | 关键字段（评级、目标价、核心观点）提取准确率 ≥ 85% |
| 降级可用 | 外部LLM不可用时自动降级到Demo模式 |
| 对比功能可用 | 3份以内研报对比响应时间 < 10 秒 |

## 5. 风险（简表）

> 列出 2~3 个主要风险。常见方向：外部依赖不可用、数据存储并发、模块间契约延期。

| 风险 | 影响 | 应对 |
|------|------|------|
| 外部 LLM 不可用 | 问答功能降级 | 二级降级：百炼 → Demo 模式兜底 |
| PDF解析格式不统一 | 关键信息提取失败 | 支持多种解析策略，失败时提示用户确认 |
| 外部LLM服务不可用 | 问答功能降级 | 二级降级策略兜底 |

- ☐ 后端与前端可独立启动
- ☐ 演示数据目录可读写
- ☐ PDF解析库（如PyPDF2/pdfplumber）可用
- ☐ 外部LLM API密钥配置就绪
