## 1. 里程碑（S1～S4）

> **切分原则**：每刀切出一个**可演示的用户价值**。不是"接口写好了"，而是"能给业务看什么"。

**S1 会话管理**：创建/列表/删除会话 API + 前端会话侧栏 → 满足 REQ-003 部分 → 验证 TC-M8RA-007~010

| 阶段 | 交付要点（可演示） | 满足的 REQ/US | 验证 TC |
|------|-------------------|---------------|---------|
| **S1** 会话管理 | 会话 CRUD API + 前端侧栏 | REQ-003 部分 | TC-M8RA-007~010 |
| **S2** 研报解析 | 研报上传 + PDF解析 + 关键信息提取 | REQ-001 | TC-M8RA-001~003 |
| **S3** 问答核心 | 基于研报内容的问答 + 三级降级 | REQ-002 | TC-M8RA-004~006 |
| **S4** 对比与发布 | 多份研报对比 + 完整测试 + 文档 | REQ-004 | TC-M8RA-011~015 |

## 2. WBS 任务拆分

> **拆分原则**：按**工程职责**切（路由、存储、Agent、前端），不按功能切。一个 W 可跨多个 S 迭代推进。

| 任务ID | 任务名称 | 具体内容 | DoD（指向 Spec） | 推进阶段 |
|--------|----------|----------|------------------|----------|
| W1 | 路由实现 | `report_bp.py` 端点注册、参数校验 | 对齐 `09` 端点与错误码 | S1 起贯穿 S4 |
| W2 | 存储层 | `storage.py` JSON CRUD | 对齐 `10` 数据模型 | S1～S2 |
| W3 | 研报解析 | `parser.py` PDF/HTML/Word/PPT解析、URL抓取、信息提取 | 对齐 `09` /upload 响应 | S2 |
| W4 | Agent编排 | `agent.py` 二级降级、问答组装 | 对齐 `07` §1.2 降级策略 | S3 |
| W5 | 前端视图 | React组件、状态管理、UI交互 | 对齐 `06` FSD | S1～S4 |
| W6 | 测试门禁 | pytest单元/集成测试、E2E测试 | 对齐 `13` 测试策略 | S2～S4 |

## 5. 依赖与风险

**依赖链**：

**S1 会话管理** → **S2 研报解析**（必须先有会话才能上传研报）→ **S3 问答核心**（必须先有研报才能问答）→ **S4 对比与发布**

| 风险 | 影响 | 应对 |
|------|------|------|
| 外部LLM服务不可用 | 问答降级 | Demo 模式兜底 |
| PDF解析失败 | 研报无法提取 | 多种解析策略，失败提示 |
| 本地存储空间不足 | 无法上传大文件 | 文件大小限制50MB |
