> **04 的定位**：`03` 说了"为什么做"，04 翻译成"做什么、不做什么、多重要"。`05` 再拆成用户故事和验收标准。

## 1. 愿景与目标

> 把 `03` §1 的痛点翻译成正面目标。格式："构建 XXX，帮助用户在 XXX 内完成 XXX"。

**示例 — 痛点→目标映射**：

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息分散、无统一入口 | 统一研报分析入口，支持多源数据整合 |
| 快速提取关键信息困难 | 智能提取研报标题、评级、核心观点 |
| 自动对比分析缺失 | 支持多家研报自动对比分析 |
| 本地部署需求 | 支持私有化部署，保障数据安全 |

## 2. 目标用户

> 把 `03` §2 的一句话展开成具体角色。思考：谁会用？用来做什么？多常用？

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 投研分析师 | 快速提取研报关键信息和对比内容 | 每天多次 |
| 基金经理 | 追踪历史分析过程作为参考 | 每天 1-2 次 |
| 研究员 | 查看历史对话，复盘分析过程 | 每周多次 |

## 3. 核心业务场景

> 把 `03` §2 提案概要拆成 4~5 条用户路径。每条场景 = 一条用户操作动线。

**示例 — SC-01**：

**SC-01 新建会话并上传研报**：用户点击"新会话" → 上传 PDF/Word 研报文件 → 系统解析文件 → 显示解析进度 → 解析完成进入问答界面

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 新建会话并上传研报 | （见上方示例） |
| SC-02 | 研报问答交互 | 用户输入问题 → 系统返回结构化回答（含关键数据对比、核心观点等）→ 回答自动落库 |
| SC-03 | 查看历史记录 | 用户点击历史记录 → 查看该会话所有历史问答记录 → 按时间倒序排列 |
| SC-04 | 会话管理 | 用户查看会话列表 → 展示所有会话历史（标题、内容、创建时间）→ 支持删除会话 |

## 4. 产品规则

> 把 `03` §4 成功标准 + §3 范围约束展开成可落地的规则。参考方向：输入约束、返回字段、状态管理、降级策略。

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 每条提问必须绑定 `session_id` | 03 §2 "会话式问答" |
| R-02 | 上传文件大小 ≤ 100MB，格式支持 PDF/Word | 03 §3 范围边界 |
| R-03 | 文件解析 5s 内完成，显示解析进度 | 03 §4 成功标准 |
| R-04 | 回答必须携带：标题、评级、核心观点、关键数据对比 | 03 §2 提案概要 |
| R-05 | 异常提示：上传文件格式不支持/文件大小超限/问题与当前文档不匹配 | 03 §3 范围边界 |
| R-06 | 三级降级：CoPaw → 百炼 → Demo 模式兜底 | 03 §5 风险应对 |

## 5. 能力与优先级

> `03` §3 范围表写了"做什么"，04 按 P0/P1 排优先级。P0 = 必须实现，阻塞发布；P1 = 应当实现，不阻塞首版。

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 会话管理（列表 / 新建 / 删除） | **P0** | SC-01, SC-04 |
| 文件上传与解析（PDF/Word） | **P0** | SC-01 |
| 问答提交与智能回答 | **P0** | SC-02 |
| 历史记录查看 | **P0** | SC-03 |
| 健康检查与降级策略 | **P1** | - |

## 6. 验收与成功标准（PRD 层）

> 从 `03` §4 可度量标准出发，加上演示条件。
> **参考句式**："种子数据 ≥ N 条下，XXX 在 N 分钟内完成"

| 标准 | 度量 |
|------|------|
| 可演示 | 种子数据 ≥ 10 条下，主路径 + 历史 + 能力状态 **3 分钟内**演示完毕 |
| 文件解析性能 | 单文件 ≤ 100MB，解析时间 ≤ 5s |
| 数据提取准确率 | 关键信息提取准确率 ≥ 95% |
| 离线可用 | 未配置密钥时系统仍返回离线演示回复（`answer_source=demo`） |

## 7. 与 05 用户故事的关系

> **04 定"做什么、多重要"；05 定"谁要什么、怎么验收"。** 填写完本文后，下一步进入 `05` 将场景拆成 US + AC。

| 本文（PRD） | 作用 | 05 中落地 |
|-------------|------|-----------|
| §3 核心场景 | 一条叙事场景 → 一条或多条 US | SC-01 → US-001 + US-002 |
| §4 产品规则 | 字段/状态/错误口径 | 拆入各 US 的 AC |
| §5 能力优先级 | P0 / P1 | 与各 US 优先级一致 |
