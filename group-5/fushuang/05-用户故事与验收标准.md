> **本文只做一件事**：按用户能理解的子场景拆成多条 **User Story**，并为每条写清 **REQ-ID**、**验收标准（AC）**。

## 字段说明 — 每条 UserStory 必须包含以下字段

| 字段 | 填写说明 | 数据来源 ← | 流向下游 → |
|------|----------|------------|-----------|
| **需求编号** | 唯一编号，如 REQ-M5RA-001 | ← `02` 采集编号 | → `14` 追踪矩阵首列 |
| **故事** | 作为【角色】，我希望【行为】，以便【价值】 | ← `04` PRD 场景拆解 | → `06` FSD 功能点 |
| **优先级** | P0（必须）/ P1（应该）/ P2（可选） | ← `03` §4 成功标准 | → `12` 里程碑排期 |
| **来源** | 对应 03/04 哪一条需求 | ← `03` 范围 · `04` 场景 | |
| **前置条件** | 触发该故事的前提状态 | ← `04` 用户流程 | → `13` 测试前置 |
| **功能对齐** | 对应功能规格 + 非功能约束 | | → `06` FSD · `07` NFR |
| **设计对齐** | 对应架构、接口、数据、安全 | | → `08` 架构 · `09` API · `10` Data · `11` 安全 |
| **验证对齐** | 对应测试用例 + 追踪矩阵行 | | → `13` TC · `14` 追踪矩阵行 |
| **验收标准** | AC，每条可独立验证 | ← 故事 + `07` NFR | → `13` 测试用例依据 |

## US-001（P0）会话管理

| 字段 | 内容 |
|------|------|
| **需求编号** | REQ-M5RA-001 |
| **故事** | 作为投研分析师，我希望管理我的分析会话，以便快速开始新的研报分析或回顾历史分析 |
| **优先级** | P0 |
| **来源** | ← 03 §3 范围边界 / 04 §3 场景 SC-01, SC-04 |
| **前置条件** | 用户已登录系统 |
| **功能对齐** | → 06 §会话管理模块 · 07 §用户交互流程 |
| **设计对齐** | → 08 §会话列表页 · 09 会话创建/查询/删除 API · 10 会话表定义 · 11 §会话数据返回 |
| **验证对齐** | → 13 TC-001 · 14 第1行 |

| 验收标准 | 描述（每条可独立测试） |
|----------|----------------------|
| AC-001-01 | 新建会话：2s 内生成新会话并跳转成功 |
| AC-001-02 | 会话列表：1s 内展示所有会话历史（标题、内容、创建时间） |
| AC-001-03 | 删除会话：确认对话框 → 标记删除 |

## US-002（P0）问答提交

| 字段 | 内容 |
|------|------|
| **需求编号** | REQ-M5RA-002 |
| **故事** | 作为投研分析师，我希望上传研报并提问，以便快速获取研报关键信息和对比内容 |
| **优先级** | P0 |
| **来源** | ← 03 §3 范围边界 / 04 §3 场景 SC-02 |
| **前置条件** | 已创建会话 |
| **功能对齐** | → 06 §文件上传模块 · 07 §问答交互 |
| **设计对齐** | → 08 §文件上传区域/输入问题框样式 · 09 文件上传/问题提交 API · 10 问答记录表字段定义 · 11 文件解析结果和返回格式 |
| **验证对齐** | → 13 TC-002 · 14 第2行 |

| 验收标准 | 描述（每条可独立测试） |
|----------|----------------------|
| AC-002-01 | 上传单篇大小 ≤ 100MB 的 PDF/Word 文件，5s 内完成解析，显示解析进度 |
| AC-002-02 | 用户输入问题并提交，返回结构化回答（含关键数据对比、核心观点等） |
| AC-002-03 | 异常提示：上传文件格式不支持/文件大小超限/问题与当前文档不匹配 |
