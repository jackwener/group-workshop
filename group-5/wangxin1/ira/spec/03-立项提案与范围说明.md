## 1. 背景与问题

> 描述用户遇到的问题，至少写 2~3 条痛点。参考：信息获取、历史记录、可追溯性、系统可用性。

| 痛点 | 来源 |
|------|------|
| 信息分散：研报、新闻、数据分布在多个系统，无统一问答入口 | 用户访谈 S-03 |
| 研报阅读耗时：每天需阅读10+份研报，平均每份30-50页，耗时2-3小时 | 会议纪要 S-01 / 邮件 S-02 |
| 研报对比困难：对比不同券商对同一公司研报需手动复制粘贴，效率很低 | 会议纪要 S-01 / 邮件 S-02 |
| 关键信息提取不完整：难以快速获取评级、目标价、核心观点 | 会议纪要 S-01 |

## 2. 提案概要

> 用 3~5 句话概括要做什么。参考格式："在 XXX 应用内交付 YYY 能力"。要素：会话式问答 · 能力降级 · 可追溯

在投研工作平台内交付**智能问答助手**能力，支持基于研报内容的自然语言问答，帮助投研人员快速提取关键信息（评级、目标价、核心观点）。系统采用**三级降级策略**（CoPaw → 百炼 → Demo模式），确保外部LLM不可用时仍能提供服务。所有问答会话自动沉淀为历史记录，支持随时回看与追溯，满足合规审计要求。系统采用**本地部署**，确保投研数据不出域，符合数据安全要求。

## 3. 范围边界

> 明确"做什么"和"不做什么"，避免范围蔓延。各写 3~4 条。

| 做（范围内） | 不做（范围外） |
|-------------|---------------|
| 会话管理：创建、列表、删除 | 多租户/行级数据权限 |
| 研报问答：基于研报内容的自然语言问答 | 研报自动上传与解析（首期仅支持已解析数据） |
| 三级降级：CoPaw → 百炼 → Demo模式 | 多模态问答（图片、语音） |
| 历史记录：问答历史自动保存与查看 | 研报对比可视化图表（首期仅文本输出） |
| 健康检查：服务状态与模型可用性检测 | 用户权限管理与SSO集成 |

## 4. 成功标准（可度量）

> 写出 3~4 条可量化的验收标准。句式：用户在 X 分钟内完成 XXX 全链路 / 未配置外部模型时返回 XXX

| 标准 | 度量方式 |
|------|----------|
| 主路径可走通 | 用户在 3 分钟内完成"新建会话 → 提问 → 查看历史"全链路 |
| 降级可用 | 未配置外部LLM密钥时，系统返回 Demo 模式回复（`answer_source=demo`） |
| 响应及时 | 正常网络下，问答响应时间 ≤ 5 秒（不含LLM生成时间） |
| 数据可追溯 | 100% 的问答记录持久化存储，支持按会话ID精确查询 |

## 5. 风险（简表）

> 列出 2~3 个主要风险。常见方向：外部依赖不可用、数据存储并发、模块间契约延期。

| 风险 | 影响 | 应对 |
|------|------|------|
| 外部 LLM 不可用 | 问答功能降级 | 三级降级：CoPaw → 百炼 → Demo 模式兜底 |
| JSON文件存储并发冲突 | 数据丢失或不一致 | 单进程访问 + 文件锁机制 + 定期备份 |
| 研报数据格式不统一 | 解析失败或信息提取不全 | 定义标准数据格式 + 异常数据人工标注 |

## 6. 立项前置条件（Go / No-Go）

- ☐ 后端与前端可独立启动
- ☐ 演示数据目录可读写
- ☐ 至少一个LLM服务可用（CoPaw或百炼）或 Demo 模式配置完成
- ☐ 种子研报数据 ≥ 10 条已准备就绪
