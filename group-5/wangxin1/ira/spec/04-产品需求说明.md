> **04 的定位**：`03` 说了"为什么做"，04 翻译成"做什么、不做什么、多重要"。`05` 再拆成用户故事和验收标准。

## 1. 愿景与目标

> 把 `03` §1 的痛点翻译成正面目标。格式："构建 XXX，帮助用户在 XXX 内完成 XXX"。

**示例 — 痛点→目标映射**：

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息分散、无统一入口 | 统一会话问答入口 |
| 复盘成本高 | 会话历史自动沉淀，随时回看 |

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息分散：研报、新闻、数据分布在多个系统，无统一问答入口 | 构建统一会话问答入口，整合研报信息查询 |
| 研报阅读耗时：每天需阅读10+份研报，耗时2-3小时 | 智能提取研报关键信息，阅读时间缩短50%以上 |
| 研报对比困难：对比不同券商研报需手动整理 | 支持多研报关键指标自动对比 |
| 关键信息提取不完整：难以快速获取评级、目标价 | 结构化提取评级、目标价、核心观点 |

## 2. 目标用户

> 把 `03` §2 的一句话展开成具体角色。思考：谁会用？用来做什么？多常用？

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 投研分析师 | 快速查询投研观点、评级、目标价 | 每天多次 |
| 高级研究员 | 对比多份研报核心观点与预测数据 | 每周多次 |
| 投资经理 | 快速了解市场舆情与研报共识 | 每天1-2次 |

## 3. 核心业务场景

> 把 `03` §2 提案概要拆成 4~5 条用户路径。每条场景 = 一条用户操作动线。

**示例 — SC-01**：

**SC-01 新建会话并提问**：用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 新建会话并提问 | 用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库 |
| SC-02 | 查看历史会话 | 用户进入历史列表 → 点击会话标题 → 查看完整问答记录 |
| SC-03 | 删除会话 | 用户在会话列表点击删除 → 确认删除 → 会话及关联记录移除 |
| SC-04 | 研报对比查询 | 用户输入对比指令（如"对比A公司和B公司的研报"）→ 系统返回对比结果表 |
| SC-05 | 服务健康检查 | 用户/管理员查看服务状态 → 了解各LLM模型可用性状态 |

## 4. 产品规则

> 把 `03` §4 成功标准 + §3 范围约束展开成可落地的规则。参考方向：输入约束、返回字段、状态管理、降级策略。

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 每条提问必须绑定 `session_id` | 03 §2 "会话式问答" |
| R-02 | `query` 长度 1～500 字符，为空或超长返回明确错误 | 03 §4 "P0 全部可测" |
| R-03 | 回答必须携带 `answer`、`answer_source`、`references` 字段 | 03 §2 "可追溯" |
| R-04 | 三级降级策略：优先CoPaw，其次百炼，最后Demo模式 | 03 §3 范围边界 |
| R-05 | 会话删除为软删除，保留审计痕迹 | 03 §4 "数据可追溯" |
| R-06 | 所有问答记录必须包含时间戳与用户标识 | 合规要求 |

## 5. 能力与优先级

> `03` §3 范围表写了"做什么"，04 按 P0/P1 排优先级。P0 = 必须实现，阻塞发布；P1 = 应当实现，不阻塞首版。

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 会话管理（列表 / 新建 / 删除） | **P0** | SC-01, SC-02, SC-03 |
| 问答提交与三级降级 | **P0** | SC-01 |
| 历史记录查看 | **P0** | SC-02 |
| 研报对比查询 | **P1** | SC-04 |
| 服务健康检查 | **P1** | SC-05 |

## 6. 验收与成功标准（PRD 层）

> 从 `03` §4 可度量标准出发，加上演示条件。
> **参考句式**："种子数据 ≥ N 条下，XXX 在 N 分钟内完成"

| 标准 | 度量 |
|------|------|
| 可演示 | 种子数据 ≥ 10 条下，主路径 + 历史 + 能力状态 **3 分钟内**演示完毕 |
| 离线可用 | 未配置密钥时系统仍返回离线演示回复（`answer_source=demo`） |
| 响应及时 | 正常网络下，问答响应时间 ≤ 5 秒（不含LLM生成时间） |
| 数据完整 | 100% 问答记录持久化，支持按会话ID查询 |

## 7. 与 05 用户故事的关系

> **04 定"做什么、多重要"；05 定"谁要什么、怎么验收"。** 填写完本文后，下一步进入 `05` 将场景拆成 US + AC。

| 本文（PRD） | 作用 | 05 中落地 |
|-------------|------|-----------|
| §3 核心场景 | 一条叙事场景 → 一条或多条 US | SC-01 → US-001 + US-002 |
| §4 产品规则 | 字段/状态/错误口径 | 拆入各 US 的 AC |
| §5 能力优先级 | P0 / P1 | 与各 US 优先级一致 |
