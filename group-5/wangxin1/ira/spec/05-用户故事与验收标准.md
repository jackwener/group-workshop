> **本文只做一件事**：按用户能理解的子场景拆成多条 **User Story**，并为每条写清 **REQ-ID**、**验收标准（AC）**。

## 字段说明 — 每条 UserStory 必须包含以下字段

| 字段 | 填写说明 | 数据来源 ← | 流向下游 → |
|------|----------|------------|-----------|
| **需求编号** | 唯一编号，如 REQ-M1QA-001 | ← `02` 采集编号 | → `14` 追踪矩阵首列 |
| **故事** | 作为【角色】，我希望【行为】，以便【价值】 | ← `04` PRD 场景拆解 | → `06` FSD 功能点 |
| **优先级** | P0（必须）/ P1（应该）/ P2（可选） | ← `03` §4 成功标准 | → `12` 里程碑排期 |
| **来源** | 对应 03/04 哪一条需求 | ← `03` 范围 · `04` 场景 | |
| **前置条件** | 触发该故事的前提状态 | ← `04` 用户流程 | → `13` 测试前置 |
| **功能对齐** | 对应功能规格 + 非功能约束 | | → `06` FSD · `07` NFR |
| **设计对齐** | 对应架构、接口、数据、安全 | | → `08` 架构 · `09` API · `10` Data · `11` 安全 |
| **验证对齐** | 对应测试用例 + 追踪矩阵行 | | → `13` TC · `14` 追踪矩阵行 |
| **验收标准** | AC，每条可独立验证 | ← 故事 + `07` NFR | → `13` 测试用例依据 |

## US-001（P0）会话管理

| 字段 | 内容 |
|------|------|
| **需求编号** | REQ-M1IRA-001 |
| **故事** | 作为投研分析师，我希望创建、查看和删除问答会话，以便管理我的投研问答历史 |
| **优先级** | P0 |
| **来源** | ← 03 §3 范围边界 / 04 §3 SC-01, SC-02, SC-03 |
| **前置条件** | 用户已打开投研问答助手界面 |
| **功能对齐** | → 06 §3.1 会话管理 · 07 §2 性能要求 |
| **设计对齐** | → 08 §3 组件设计 · 09 /sessions API · 10 sessions表 · 11 §4 数据安全 |
| **验证对齐** | → 13 TC-001 ~ TC-003 · 14 第1行 |

| 验收标准 | 描述（每条可独立测试） |
|----------|----------------------|
| AC-001-01 | 用户点击"新会话"按钮后，系统创建新会话并返回唯一 session_id |
| AC-001-02 | 用户可查看会话列表，列表按时间倒序排列，显示会话标题和最后更新时间 |
| AC-001-03 | 用户点击删除会话后，系统软删除该会话（标记deleted=true），保留审计痕迹 |

## US-002（P0）问答提交

| 字段 | 内容 |
|------|------|
| **需求编号** | REQ-M1IRA-002 |
| **故事** | 作为投研分析师，我希望基于研报内容进行自然语言提问并获得回答，以便快速获取投研信息 |
| **优先级** | P0 |
| **来源** | ← 03 §3 范围边界 / 04 §3 SC-01 |
| **前置条件** | 已创建会话（拥有有效的 session_id） |
| **功能对齐** | → 06 §3.2 问答提交 · 07 §2 性能要求 · 07 §3 降级策略 |
| **设计对齐** | → 08 §3 组件设计 · 09 /query API · 10 qa_records表 · 11 §2 传输安全 |
| **验证对齐** | → 13 TC-004 ~ TC-007 · 14 第2行 |

| 验收标准 | 描述（每条可独立测试） |
|----------|----------------------|
| AC-002-01 | 用户输入1~500字符的问题，系统正常接收并返回回答，回答包含answer、answer_source、references字段 |
| AC-002-02 | 当CoPaw可用时，answer_source=copaw；CoPaw不可用时自动降级到百炼，answer_source=bailian |
| AC-002-03 | 当所有外部LLM不可用时，系统返回Demo模式回答，answer_source=demo，回答内容包含友好提示 |
| AC-002-04 | 问答响应时间 ≤ 5 秒（不含LLM生成时间），超时返回明确错误信息 |

## US-003（P0）历史记录

| 字段 | 内容 |
|------|------|
| **需求编号** | REQ-M1IRA-003 |
| **故事** | 作为投研分析师，我希望查看历史问答记录，以便回顾和追溯之前的投研分析 |
| **优先级** | P0 |
| **来源** | ← 03 §3 范围边界 / 04 §3 SC-02 |
| **前置条件** | 已有问答记录（qa_records表中有数据） |
| **功能对齐** | → 06 §3.3 历史记录 · 07 §2 性能要求 |
| **设计对齐** | → 08 §3 组件设计 · 09 /sessions/{id}/history API · 10 qa_records表 · 11 §4 数据安全 |
| **验证对齐** | → 13 TC-008 ~ TC-009 · 14 第3行 |

| 验收标准 | 描述（每条可独立测试） |
|----------|----------------------|
| AC-003-01 | 用户点击会话后，系统显示该会话下所有问答记录，按时间正序排列 |

| AC-003-03 | 100% 的问答记录被持久化存储，系统重启后数据不丢失 |
