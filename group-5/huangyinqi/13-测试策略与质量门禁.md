## 一、测试分层

> 共 4 层，写测试前先搞清楚每层验什么。

| 层级 | 工具 | 覆盖对象 | 说明 |
|------|------|----------|------|
| **L1 Unit** | pytest | 单个函数/类的逻辑 | 不依赖网络，最快 |
| **L2 Integration** | pytest + Flask test_client | API 端点 + 存储 | 模拟 HTTP 请求 |
| **L3 Contract** | pytest + schema 断言 | 响应体结构与 `09` 一致 | 验字段名、类型 |
| **L4 E2E** | Playwright / Cypress | 完整用户旅程 | 浏览器级操作 |

## 二、用例拆分原则

> **核心理念：数"可独立失败的点"** — 每条 TC 只回答一个问题，失败时不看代码就知道哪里坏了。

| 来源 | 计数方法 | 示例 |
|------|----------|------|
| 正常路径 | 每个端点的 happy path = 1 条 | `POST /ask → 200` = TC-001 |
| 错误码 | 每个 distinct error code = 1 条 | `EMPTY_QUERY` = TC-002 |
| 分支路径 | 每个 if/else 降级分支 = 1 条 | 无 API Key → demo = TC-004 |
| 类型约束 | Spec `09` 约定的字段类型 = 1 条 | `llm_used` 必须 bool = TC-006 |

## 四、质量门禁

| Gate-ID | 条件 | 阈值 | 阻塞合并 |
|---------|------|------|----------|
| **G-LINT** | `black --check` + `flake8` 通过 | 代码格式零警告 | **是** |
| **G-UNIT** | L1 Unit 测试通过率 | **100%** | **是** |
| **G-INT** | L2 Integration 测试通过率 | **≥ 95%**，P0用例100%通过 | **是** |
| **G-CONTRACT** | L3 Contract 测试通过率 | **100%** | **是** |
| **G-AC** | P0 验收标准全覆盖 | 所有 P0 AC 有对应 TC 且通过 | **是** |
| **G-COVERAGE** | 代码覆盖率 | **≥ 80%** 行覆盖率 | 否（warning） |
| **G-PERF** | 性能测试 | `response_time_ms < 5000` (P95) | 否（warning） |

### 执行命令

```bash
# 后端测试
cd groups/Group-X/NN/backend
python -m pytest tests/ -q

# 后端测试 + 覆盖率
python -m pytest tests/ -q --cov=. --cov-report=term-missing

# 仅运行 P0 测试
python -m pytest tests/ -q -m "p0"

# 运行特定层级测试
python -m pytest tests/unit/ -q          # L1
python -m pytest tests/integration/ -q   # L2
python -m pytest tests/contract/ -q      # L3
python -m pytest tests/e2e/ -q           # L4
```

## 五、TDD 适用场景

| 场景 | TDD 价值 | 建议 |
|------|----------|------|
| 简单 CRUD（列表、删除） | 低 | 写完补测试 |
| 参数校验 / 错误码 | 中 | 建议 TDD |
| 多级降级 / 状态机 | **高** | **强烈建议 TDD** |
| 研报解析 / 数据提取 | **高** | **强烈建议 TDD** |
| 金融计算 / 风险判定 | **极高** | **必须 TDD** |
