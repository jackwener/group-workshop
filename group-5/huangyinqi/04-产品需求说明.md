> **04 的定位**：`03` 说了"为什么做"，04 翻译成"做什么、不做什么、多重要"。`05` 再拆成用户故事和验收标准。

## 1. 愿景与目标

> 把 `03` §1 的痛点翻译成正面目标。格式："构建 XXX，帮助用户在 XXX 内完成 XXX"。

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息分散：研报、新闻、数据分布在多个系统，无统一问答入口 | 统一投研问答入口，实现研报解析与智能问答一体化 |
| 研报分析效率低：人工阅读研报耗时，关键信息提取困难 | 自动解析研报核心要素（标题/评级/目标价/观点），提升分析效率 |
| 历史记录难追溯：过往问答和研报查阅记录分散 | 会话历史自动沉淀，支持模糊搜索和快速回溯 |

## 2. 目标用户

> 把 `03` §2 的一句话展开成具体角色。思考：谁会用？用来做什么？多常用？

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 研究员 | 上传研报进行智能解析，快速获取核心投资观点 | 每天多次 |
| 基金经理 | 查阅历史研报解析记录，为投资决策提供参考 | 每天1-2次 |
| 投研助理 | 管理会话和研报文档，协助团队知识沉淀 | 每周多次 |

## 3. 核心业务场景

> 把 `03` §2 提案概要拆成 4~5 条用户路径。每条场景 = 一条用户操作动线。

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 新建会话并提问 | 用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库 |
| SC-02 | 上传研报并解析 | 用户选择PDF/HTML研报 → 上传文件 → 系统解析提取要素 → 展示解析结果 |
| SC-03 | 切换会话继续对话 | 用户从侧边栏选择历史会话 → 加载历史记录 → 继续提问或上传新研报 |
| SC-04 | 查阅历史研报 | 用户输入关键词 → 模糊搜索研报 → 查看研报详情和解析内容 |
| SC-05 | 删除会话和研报 | 用户选择会话/研报 → 确认删除 → 级联删除关联数据 |

## 4. 产品规则

> 把 `03` §4 成功标准 + §3 范围约束展开成可落地的规则。参考方向：输入约束、返回字段、状态管理、降级策略。

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 每条提问必须绑定 `session_id` | 03 §2 "会话式问答" |
| R-02 | `query` 长度 1～500 字符，为空或超长返回明确错误 | 03 §4 "P0 全部可测" |
| R-03 | 回答必须携带 `answer`、`llm_used`、`model`、`response_time_ms`、`answer_source` 字段 | 09 API 规格 |
| R-04 | 三级降级策略：CoPaw → 百炼 → Demo，任一级别失败自动降级 | 03 §5 风险应对 |
| R-05 | 会话删除时级联删除该会话下所有问答记录和关联研报 | 03 §3 范围边界 |
| R-06 | 仅支持 PDF/HTML 格式研报上传，其他格式直接拒绝 | 03 §3 范围边界 |
| R-07 | 研报解析结果必须包含标题、评级、目标价、核心观点四要素 | 05 US-002 AC |
| R-08 | 首次问答后自动将会话标题设为问题前20字 | 05 US-001 AC |

## 5. 能力与优先级

> `03` §3 范围表写了"做什么"，04 按 P0/P1 排优先级。P0 = 必须实现，阻塞发布；P1 = 应当实现，不阻塞首版。

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 会话管理（列表 / 新建 / 删除 / 切换） | **P0** | SC-01, SC-03, SC-05 |
| 问答提交与三级降级 | **P0** | SC-01 |
| 研报上传与解析（PDF/HTML） | **P0** | SC-02 |
| 历史记录查看与模糊搜索 | **P0** | SC-04 |
| 能力状态展示（在线/离线） | **P0** | SC-01 |
| 研报删除与权限管控 | **P1** | SC-05 |
| 订阅舆情监控（行内/宏观/公司） | **P1** | - |
| 健康检查接口 | **P1** | - |

## 6. 验收与成功标准（PRD 层）

> 从 `03` §4 可度量标准出发，加上演示条件。
> **参考句式**："种子数据 ≥ N 条下，XXX 在 N 分钟内完成"

| 标准 | 度量 |
|------|------|
| 可演示 | 种子数据 ≥ 10 条下，主路径 + 历史 + 能力状态 **3 分钟内**演示完毕 |
| 离线可用 | 未配置密钥时系统仍返回离线演示回复（`answer_source=demo`） |
| 研报解析准确率 | PDF/HTML研报成功解析率 ≥ 90%，四要素提取完整 |
| 响应性能 | 问答响应时间 < 5秒（不含LLM延迟），列表查询 < 1秒 |
| 并发支持 | 单用户多会话切换无状态丢失，上下文保持连续 |

## 7. 与 05 用户故事的关系

> **04 定"做什么、多重要"；05 定"谁要什么、怎么验收"。** 填写完本文后，下一步进入 `05` 将场景拆成 US + AC。

| 本文（PRD） | 作用 | 05 中落地 |
|-------------|------|-----------|
| §3 核心场景 | 一条叙事场景 → 一条或多条 US | SC-01 → US-001 + US-002 |
| §4 产品规则 | 字段/状态/错误口径 | 拆入各 US 的 AC |
| §5 能力优先级 | P0 / P1 | 与各 US 优先级一致 |

**场景到用户故事映射**：

| 场景 | 用户故事 |
|------|----------|
| SC-01 新建会话并提问 | US-001 会话管理 + US-002 问答提交 |
| SC-02 上传研报并解析 | US-002 问答提交（研报上传） |
| SC-03 切换会话继续对话 | US-001 会话管理 |
| SC-04 查阅历史研报 | US-003 历史记录 |
| SC-05 删除会话和研报 | US-001 会话管理 + US-002 问答提交 |
