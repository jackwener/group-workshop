## 1. 里程碑（S1～S4）

|------|-------------------|---------------|---------|
| **S1** 会话管理 | 会话 CRUD API + 前端会话侧栏，支持创建/删除/列表展示 | REQ-M1QA-001（US-001） | TC-M01-020～025 |
| **S2** 问答核心 | 研报上传分析 + 股票查询 + 消息发送，LLM 三级降级可用 | REQ-M1QA-002（US-002） | TC-M01-001～004, TC-M01-030～035 |
| **S3** 历史与追溯 | 历史会话详情 + 消息记录查看 + 上下文追溯 | REQ-M1QA-003（US-003） | TC-M01-040～045 |

## 2. WBS 任务拆分

> **拆分原则**：按**工程职责**切（路由、存储、分析服务、前端），不按功能切。一个 W 可跨多个 S 迭代推进。

| 任务ID | 任务名称 | 具体内容 | DoD（指向 Spec） | 推进阶段 |
|--------|----------|----------|------------------|----------|
| W1 | 路由实现 | API 端点注册、参数校验、错误码返回 | 对齐 `09` 全部 9 个端点与错误码 | S1 起贯穿 S4 |
| W2 | 存储层 | Session/Message/Analysis/Report JSON CRUD | 对齐 `10` 数据模型，级联删除 | S1～S3 |
| W3 | 分析服务 | 研报分析（文件提取 + LLM）、股票查询（数据源 + LLM）、降级策略 | 对齐 `08` 架构降级、`09` API-005/006 | S2～S3 |
| W4 | 前端视图 | 会话侧栏、问答区域、结果展示、文件上传、报告下载 | 对齐 `06` 界面交互规格 | S1～S4 |
| W5 | 报告生成 | 分析结果转 PDF、报告下载接口 | 对齐 `09` API-008 | S4 |
| W6 | 测试门禁 | pytest 单元测试 + 集成测试 + 质量门禁 | 对齐 `13` 测试策略 | S1 起贯穿 S4 |

## 5. 依赖与风险

**依赖链**：

**S1 会话管理** → **S2 问答核心**（必须先有会话才能提问）→ **S3 历史与追溯**（必须有问答记录才能查看历史）→ **S4 报告与收口**（必须有分析结果才能生成报告）

| 风险 | 影响 | 应对 |
|------|------|------|
| 上游 LLM（CoPaw）不可用 | 研报分析和股票查询降级 | 三级降级：CoPaw → 百炼 → Demo 模式兜底 |
| 数据源超时 | 股票查询延迟或失败 | 重试机制（最多2次），超时后缓存数据 + 提示用户 |
| PDF生成依赖库不稳定 | 报告下载功能异常 | 兜底返回 JSON 格式数据 |
| 研报文件过大 | 分析超时 | 分批处理，返回 processing 状态支持轮询 |
