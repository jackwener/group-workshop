## 4. 接口设计原则

### 4.1 RESTful设计

| 原则 | 说明 |
|------|------|
| 资源导向 | URL表示资源，如/sessions、/reports |
| HTTP方法 | GET查询、POST创建、DELETE删除 |
| 状态码 | 200成功、201创建、400错误、404不存在 |
| 版本控制 | URL中包含版本号，如/api/v1/ |

### 4.2 降级策略

```
┌─────────────────────────────────────────┐
│           LLM调用服务                   │
├─────────────────────────────────────────┤
│  Level 0: CoPaw (主服务)                │
│     ↓ 失败                              │
│  Level 1: 百炼 (备用服务)               │
│     ↓ 失败                              │
│  Level 2: Demo模式 (本地模拟)           │
└─────────────────────────────────────────┘
```

## 6. 关键技术决策

### 6.1 决策记录

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 数据存储 | JSON文件 | 简单、无需数据库部署 |
| LLM调用 | 三级降级 | 保证服务可用性 |
| 文件上传 | 本地存储 | 研报数据不外传 |
| 会话管理 | 文件存储 | 便于追溯和备份 |

### 6.2 约束条件

- 不实现多租户/行级数据权限
- 不实现AI总结报告核心功能
- 研报数据本地处理，不外传
- 未公开数据不获取
