## 1. 架构总览

### 1.1 系统上下文

```
┌─────────────────────────────────┐
│       用户浏览器 React SPA       │
│       http://localhost:5173     │
└──────────────┬──────────────────┘
               │ HTTP  /api/v1/agent/*
               ▼
┌─────────────────────────────────┐
│     Flask Backend (WSGI)        │
│     http://localhost:5000       │
│  ┌────────────────────────────┐ │
│  │  agent_bp — 6 个 API 端点  │ │
│  │    ↓          ↓         ↓  │ │
│  │ CoPawAgent  Storage  _ok() │ │
│  └────┬──────────┬────────────┘ │
│       ▼          ▼              │
│  ┌────────┐ ┌──────────┐       │
│  │ LLM 层 │ │ 文件系统  │       │
│  │CoPaw   │ │ ./data/  │       │
│  │百炼    │ │ *.json   │       │
│  │Demo    │ └──────────┘       │
│  └────────┘                    │
└─────────────────────────────────┘
```

### 1.2 架构风格

| 决策 | 选型 | 理由 |
|------|------|------|
| **前后端分离** | React SPA + Flask REST API | 教学清晰度：前端独立开发服务器，职责边界清晰 |
| **单体部署** | 前后端各一个进程 | 不引入微服务复杂度，本地一键启动 |
| **分层架构** | Route → Agent → Storage | 替换存储引擎时上层零改动；各层可独立测试 |
| **本地文件存储** | JSON 文件（`./data/*.json`） | 无需数据库安装配置，教学环境开箱即用；Storage 层抽象保障后续可迁移 |

## 2. 后端分层结构

> 每层写清"允许做什么、禁止做什么"。

| 层 | 文件 | 允许做 | 禁止做 |
|----|------|--------|--------|
| **Route** | `agent_bp.py` | 参数校验、HTTP 状态码、traceId 注入、请求/响应序列化 | 直接读写文件、调用 LLM、业务逻辑 |
| **Agent** | `agent.py` | 降级编排、结果组装、`answer_source` 标识 | 感知 HTTP 请求/响应、直接操作文件 |
| **Provider** | `copaw_bridge.py` / `bailian_qa.py` | HTTP 调用外部 LLM API、超时控制、错误静默 | 操作本地存储、感知降级逻辑 |
| **Storage** | `storage.py` | 文件 CRUD、数据结构校验、软删除标记、`query_count` 累加 | 调用外部 API、感知业务规则 |

## 3. 前端架构

| 项 | 选型 | 理由 |
|----|------|------|
| UI 框架 | React（Hooks）≥ 18 | 教学通用性最高，`useState` / `useEffect` 覆盖全部状态场景 |
| 构建工具 | Vite ≥ 5 | 极快 HMR，零配置启动，教学环境无需 webpack 调优 |
| 状态管理 | `useState` + `useEffect` | 8 个 state 变量足够，不引入 Redux / Zustand 复杂度 |
| HTTP 客户端 | `fetch` API | 浏览器原生，不引入 axios，减少依赖数量 |
| 样式方案 | CSS Modules + 内联样式 | 无需配置 CSS-in-JS 工具链；组件样式隔离，教学可读性高 |

**前端组件树（顶层）**：

```
<App>
  ├── <Header>          能力芯片展示
  ├── <Sidebar>         会话列表管理
  └── <MainContent>
        ├── <EmptyState>       A 态
        ├── <WelcomeGrid>      B 态（常见问题）
        ├── <RecordList>       C 态（对话历史）
        └── <InputArea>        问题输入与提交
```

## 4. 三级降级编排

> 对齐 `07` §1.2 降级策略。

```
ask(query, session_id)
  ├─[1] CoPaw  → {source:"copaw",  llm:true}
  ├─[2] 百炼   → {source:"bailian",llm:true}
  └─[3] Demo   → {source:"demo",   llm:false}
```

| 提供商 | 文件 | 配置检测 | 超时 | 错误处理 |
|--------|------|----------|------|----------|
| **CoPaw** | `copaw_bridge.py` | `IRA_COPAW_*_URL` 非空 | 4500ms | 返回 `None` 静默降级，记录 WARNING 日志 |
| **百炼** | `bailian_qa.py` | `DASHSCOPE_API_KEY` 非空 | 4500ms | 区分 `AuthenticationError` / `RateLimitError` / 超时，均返回 `None` 静默降级 |
| **Demo** | `agent.py` | 始终可用 | 0ms | 纯字符串拼接，`cited_passages=null`，不得抛出任何异常 |

**降级触发条件**：当前级返回 `None`（超时、异常、未配置）时自动进入下一级，不可跳级，不向上层抛出异常。

## 5. 数据存储架构

### 5.1 存储演进路线

| 阶段 | 存储 | 变更范围 | 说明 |
|------|------|----------|------|
| **P0（当前）** | JSON 文件（`./data/sessions.json` + `./data/records.json`） | — | 适合教学，零配置 |
| P1 | SQLite（`./data/app.db`） | 仅替换 `storage.py`，Route / Agent 层零改动 | 支持并发读写，适合多用户演示环境 |
| P2 | PostgreSQL（生产） | 替换 `storage.py` + 环境变量注入连接串 | 生产级可用性与事务保障，Storage 层抽象确保上层无感知 |

### 5.2 JSON 文件结构

```
./data/
  sessions.json   # Session 对象数组
  records.json    # Record 对象数组（以 session_id 关联）
```

启动时若文件不存在则自动初始化为空数组 `[]`；文件损坏（JSON 解析失败）则以空数组启动并写入 ERROR 日志，不崩溃（对齐 `07` §2 故障模式）。

## 6. 部署架构

| 服务 | 端口 | 启动命令 |
|------|------|----------|
| Flask Backend | **5000** | `python -m flask --app wsgi run --port 5000` |
| Vite Frontend | **5173** | `npm run dev` |

**环境变量（`.env`，不提交至版本控制）**：

| 变量名 | 必填 | 说明 |
|--------|------|------|
| `IRA_COPAW_ASK_URL` | 否 | CoPaw 问答接口地址，缺省时跳过该层 |
| `IRA_COPAW_CAPS_URL` | 否 | CoPaw 能力探测接口地址 |
| `DASHSCOPE_API_KEY` | 否 | 百炼 API Key，缺省时跳过该层 |
| `DASHSCOPE_MODEL` | 否 | 百炼模型标识，默认 `qwen-turbo` |
| `DATA_DIR` | 否 | JSON 存储目录，默认 `./data` |

## 7. ADR（架构决策记录）

| ADR | 决策 | 核心理由 |
|-----|------|----------|
| ADR-001 | Flask 而非 FastAPI | 学习曲线低，无需 async/await，学员 Python 基础即可上手；同步代码更易调试 |
| ADR-002 | JSON 文件而非 SQLite/数据库 | 教学环境零配置依赖；Storage 层抽象保障 P1 可无缝迁移至 SQLite，上层代码不变 |
| ADR-003 | 单文件组件而非深度拆分 | 教学阶段以可读性优先；组件树不超过 2 层，避免 props drilling 讨论分散学习焦点 |
| ADR-004 | `fetch` 而非 axios | 减少 `node_modules` 依赖；浏览器原生 API 教学价值更高；错误处理逻辑一致 |

## 8. 安全架构

> 对齐 `07` §4 安全需求。当前教学版与生产需求的差距。

| 层 | 当前措施 | 生产改进 |
|----|----------|----------|
| 认证 | 无（开放访问） | JWT Bearer Token，Route 层统一鉴权中间件 |
| CORS | 全开放（`*`） | 白名单，仅允许前端域名，禁止 `*` |
| 密钥管理 | 环境变量 `.env`，加入 `.gitignore` | HashiCorp Vault / 云厂商 Secrets Manager，禁止落盘 |
| 数据传输 | HTTP（教学环境） | 全链路 HTTPS，HSTS 头强制 |
| 日志脱敏 | `query` 截断前 50 字符 | 生产增加 PII 检测，敏感字段哈希后记录 |
