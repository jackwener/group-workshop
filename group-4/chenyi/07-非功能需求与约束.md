## 1. 性能需求

### 1.1 延迟 SLO

| 指标 | 目标值 | 度量方式 | 来源 |
|------|--------|----------|------|
| **问答端点 P95 延迟** | < **5000ms** | `response_time_ms` 字段 | `03` §4 |
| 会话管理端点延迟 | < 500ms | 服务端计时 | JSON I/O < 10ms |
| 研报解析端点延迟（单份 PDF） | < 30000ms | 服务端计时，超时返回 503 | `03` §4 "30 秒内生成对比表" |
| 健康检查端点延迟 | < 1000ms | 服务端计时 | `05` AC-004-01 |

### 1.2 降级策略

**三级降级链**：

```
CoPawAgent.ask(query, session_id)
  ├─[1] CoPaw 桥接 → answer_source='copaw', llm_used=True
  ├─[2] 百炼 DashScope → answer_source='bailian', llm_used=True
  └─[3] 离线演示兜底 → answer_source='demo', llm_used=False
```

| 约束 | 说明 |
|------|------|
| 三级降级**不可跳级** | 必须按 CoPaw → 百炼 → Demo 顺序尝试 |
| 降级**静默执行** | 不抛异常，通过 `answer_source` 标识当前层级 |
| Demo 模式**始终可用** | 无外部依赖，纯字符串拼接，不得因任何原因失败 |
| 每级超时阈值 | CoPaw / 百炼单次调用超时上限均为 4500ms，超时即触发下一级 |
| 降级状态前端可见 | `answer_source=demo` 时前端必须展示"离线演示"灰色标签，不得静默 |

## 2. 可用性需求

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 服务可用性 | **99%**（教学环境） | 单实例 Flask，不设 HA |
| MTTR | < 5 分钟 | 重启 Flask 进程即可恢复 |
| 故障模式：JSON 存储文件损坏 | 启动时检测，损坏则以空数据启动并写入告警日志，不崩溃 |
| 故障模式：LLM 全链路不可用 | 自动兜底至 Demo 模式，服务继续可用，`GET /capabilities` 返回 `degraded` |
| 故障模式：前端资源加载失败 | 不影响后端 API 可用性；前端独立部署，重启 Vite dev server 恢复 |

## 3. 可观测性需求

### 3.1 链路追踪

| 项 | 规格 |
|----|------|
| traceId 格式 | `tr_{uuid.hex}`（32 位十六进制） |
| 注入位置 | 所有成功响应顶层 + 错误响应 `error.traceId` |
| 上游透传 | 优先复用请求头 `X-Trace-Id`，缺省时本地生成 |
| 日志关联 | 每条服务端日志必须携带 `traceId`，格式：`[traceId=tr_xxx] <message>` |

### 3.2 错误码体系

| HTTP | `error.code` | 触发条件 |
|------|--------------|----------|
| 400 | `EMPTY_QUERY` | query 为空/空白/null |
| 400 | `INVALID_QUERY` | query > 500 字符 或 缺少 session_id |
| 404 | `SESSION_NOT_FOUND` | session_id 不存在或已软删除 |
| 422 | `MISSING_FIELD` | 必填字段缺失，`details.field` 指明缺失字段名 |
| 500 | `UPSTREAM_ERROR` | Agent 编排内部异常 |
| 503 | `LLM_UNAVAILABLE` | 所有降级层级均失败，Demo 模式也不可用 |

### 3.3 结构化日志

| 级别 | 触发场景 | 必含字段 |
|------|----------|----------|
| `INFO` | 请求进入、响应返回、降级切换 | `traceId`、`endpoint`、`duration_ms` |
| `WARNING` | 单级降级触发、JSON 文件写入重试 | `traceId`、`degraded_from`、`reason` |
| `ERROR` | 所有未处理异常、LLM 全链路失败 | `traceId`、`error_code`、`stack` |

## 4. 安全需求

| 项 | 当前实现 | 说明 |
|----|----------|------|
| API 认证 | 无（开放访问） | Workshop 教学版；生产须接入认证中间件 |
| CORS | 全开放 | 生产需白名单，仅允许前端域名 |
| 速率限制 | 无 | 教学场景不限速；生产建议 60 req/min/IP |
| 数据传输 | HTTP（教学环境） | 生产须启用 HTTPS，禁止明文传输 |

### 4.1 敏感数据保护

| 数据类型 | 保护方式 |
|----------|----------|
| LLM API Key（CoPaw / 百炼） | 环境变量存储（`.env`），禁止硬编码，`.env` 加入 `.gitignore` |
| 用户查询内容 | 仅存储在本地 JSON 文件，不传输至第三方（LLM 调用除外）；本地文件不得对外暴露 |
| 研报文件内容 | 仅在本地解析，解析结果存于本地，禁止上传至任何外部服务 |
| 日志中的查询内容 | 日志记录 `query` 时截断至前 50 字符，不记录完整原文 |

## 5. 数据约束

### 5.1 输入约束

| 约束 | 规格 | 来源 |
|------|------|------|
| `query` 最小长度 | 1 字符（空白字符不计） | `04` R-02 |
| `query` 最大长度 | 500 字符 | `04` R-02 |
| `session_id` 必填 | 非空 UUID 字符串 | `04` R-01 |
| 会话标题默认值 | 未传入时服务端填充 `"新会话"` | `09` §4 POST /sessions |
| 会话标题最大长度 | 100 字符，超长返回 400 `INVALID_QUERY` | `09` §8 参数校验 |

### 5.2 类型约束

| 字段 | 类型 | 约束 |
|------|------|------|
| `llm_used` | `boolean` | 必须为 `true` / `false`，不得为字符串 `"true"` |
| `answer_source` | `string` | 枚举值：`copaw` \| `bailian` \| `demo`，不得为其他值 |
| `response_time_ms` | `integer` | 非负整数，单位毫秒，不得为浮点数 |
| `created_at` / `deleted_at` | `string` | ISO 8601 格式，含时区（UTC），如 `2026-04-14T10:00:00Z` |
| `query_count` | `integer` | 非负整数，随问答记录新增自动累加，不得手动写入 |
