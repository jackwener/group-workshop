## 1. 概念模型

```
Session（会话）1 ── * QARecord（问答记录）
   │                      │
   │  session_id (PK)     │  id (PK)
   │  title               │  session_id (FK → Session)
   │  query_count          │  query / answer / llm_used
   │  created_at           │  response_time_ms / answer_source
   └  updated_at           └  timestamp
```

> **核心关系**：一个 Session 可包含零到多条 QARecord。外键通过 `session_id` 字段逻辑引用。

## 2. 存储引擎

| 项 | 说明 |
|----|------|
| 引擎 | JSON 文件（`json` 标准库） |
| 编码 | UTF-8，缩进 2 空格 |
| 读写模式 | RMW（全量读入 → 修改 → 全量写回） |
| 并发安全 | 无锁，不支持并发写入 |
| 文件布局 | `{DATA_DIR}/sessions.json` + `qa_records.json` |
| 初始化行为 | 启动时文件不存在则自动创建并写入 `[]`；JSON 解析失败则以 `[]` 启动并写入 ERROR 日志，不崩溃 |
| 备份策略 | 教学环境不做自动备份；生产迁移至 SQLite/PostgreSQL 时由 Storage 层封装，上层零感知 |

## 3. 实体定义 — Session

| 字段 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| `session_id` | `string` (UUID) | 是 | **PK**，全局唯一 | 会话唯一标识，由 `uuid.uuid4().hex` 生成 |
| `title` | `string` | 是 | ≤ 100 字符，默认 `"新会话"` | 创建时由调用方传入或取默认值；首次问答后自动重命名（见 §6） |
| `created_at` | `string` (ISO-8601) | 是 | UTC，格式 `2026-04-14T10:00:00Z` | 创建时间，写入后不可变 |
| `updated_at` | `string` (ISO-8601) | 是 | UTC，每次写入记录时更新 | 最后更新时间 |
| `query_count` | `integer` | 是 | ≥ 0，每次 `add_record` 自动 +1 | 累计问答次数，不可手动写入 |
| `status` | `string` | 是 | 枚举：`active` \| `deleted` | 软删除标记，默认 `active`；删除时置为 `deleted`，不物理清除 |

**Session JSON 示例**：

```json
{
  "session_id": "550e8400e29b41d4a716446655440000",
  "title": "宁德时代研报分析",
  "created_at": "2026-04-14T09:30:00Z",
  "updated_at": "2026-04-14T09:45:00Z",
  "query_count": 3,
  "status": "active"
}
```

## 4. 实体定义 — QARecord

| 字段 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| `id` | `string` | 是 | **PK**，格式 `rec_{timestamp_ms}` | 基于毫秒时间戳生成，同毫秒追加随机 4 位后缀避免碰撞 |
| `session_id` | `string` | 是 | **FK** → Session.session_id | 所属会话，写入后不可变 |
| `query` | `string` | 是 | 1–500 字符，不可为空白 | 用户提问原文 |
| `answer` | `string` | 是 | 非空 | LLM 或 Demo 返回的答案文本 |
| `llm_used` | `boolean` | 是 | `true` / `false`，不得为字符串 | 是否使用真实 LLM（对齐 `07` §5.2） |
| `model` | `string\|null` | 是 | Demo 模式时为 `null` | 模型标识，如 `qwen-turbo` |
| `response_time_ms` | `integer` | 是 | ≥ 0，SLO < 5000ms | 响应耗时（毫秒），Demo 模式记录实际耗时 |
| `answer_source` | `string` | 是 | 枚举：`copaw` \| `bailian` \| `demo` | 实际使用的答案来源层级 |
| `cited_passages` | `array\|null` | 是 | Demo 模式时为 `null` | 原文引用段落列表（见 §4.1） |
| `created_at` | `string` (ISO-8601) | 是 | UTC，写入后不可变 | 记录创建时间 |

### 4.1 cited_passages 子项结构

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `text` | `string` | 是 | 引用的原文段落内容 |
| `page` | `integer\|null` | 是 | 来源页码；HTML 格式研报时为 `null` |
| `source_file` | `string` | 是 | 来源研报文件名，如 `CATL_20260410_招商证券.pdf` |

**QARecord JSON 示例**：

```json
{
  "id": "rec_1744624200000_a3f2",
  "session_id": "550e8400e29b41d4a716446655440000",
  "query": "这份研报对宁德时代的评级是什么？",
  "answer": "该研报给出"买入"评级，目标价 320 元，核心逻辑为动力电池市占率稳固、固态电池技术领先。",
  "llm_used": true,
  "model": "qwen-turbo",
  "response_time_ms": 1832,
  "answer_source": "bailian",
  "cited_passages": [
    {
      "text": "维持买入评级，目标价 320 元，较当前股价上涨空间约 25%。",
      "page": 3,
      "source_file": "CATL_20260410_招商证券.pdf"
    }
  ],
  "created_at": "2026-04-14T09:35:00Z"
}
```

## 5. Storage 方法清单

> 列出 Storage 类的全部公开方法。每个方法标注关联的 TC 编号（来自 `13`）。

### 5.1 会话管理

| 方法 | 签名 | 行为 | 关联 TC |
|------|------|------|---------|
| `create_session` | `(session_id: str, title: str) → dict` | 创建新 Session，写入 `sessions.json`，返回完整 Session 对象 | TC-M01-041 |
| `get_sessions` | `() → list[dict]` | 返回全部 `status=active` 的会话，按 `created_at` 倒序排列 | TC-M01-042 |
| `delete_session` | `(session_id: str) → None` | 将 Session `status` 置为 `deleted`（软删除），同步调用 `delete_records_by_session` 级联处理关联记录 | TC-M01-043 |
| `update_session` | `(session_id: str, **kwargs) → dict` | 按传入字段更新 Session（如 `title`、`updated_at`、`query_count`），返回更新后完整对象；不可更新 `session_id`、`created_at` | TC-M01-046 |

### 5.2 问答记录管理

| 方法 | 签名 | 行为 | 关联 TC |
|------|------|------|---------|
| `add_record` | `(session_id: str, query: str, answer: str, llm_used: bool, model: str\|None, response_time_ms: int, answer_source: str, cited_passages: list\|None) → dict` | 写入新 QARecord，同时调用 `update_session` 将 `query_count +1`、`updated_at` 更新为当前时间；若为首次问答（`query_count` 从 0→1）则触发自动命名逻辑 | TC-M01-044 |
| `get_records_by_session` | `(session_id: str) → list[dict]` | 按 `session_id` 过滤返回该会话全部记录，按 `created_at` 正序排列；若会话不存在或已删除返回空列表 | TC-M01-045 |
| `delete_records_by_session` | `(session_id: str) → None` | 从 `qa_records.json` 中移除所有 `session_id` 匹配的记录；由 `delete_session` 内部调用，不对外暴露为独立 API | TC-M01-047 |

## 6. 关键业务逻辑

| 逻辑 | 触发条件 | 行为 |
|------|----------|------|
| 首次问答自动命名 | `add_record` 执行后 Session 的 `query_count` 从 0 → 1 | 截取 `query` 前 20 字符作为新标题，超 20 字符追加 `...`；仅首次触发，后续问答不再变更标题 |
| 级联软删除 | `delete_session` 被调用 | 调用 `delete_records_by_session` 物理删除关联 QARecord；Session 本身仅软删除（`status=deleted`），保留数据可追溯 |
| `query_count` 自增 | 每次 `add_record` 成功写入 | `query_count +1`，同步更新 `updated_at` 为当前 UTC 时间；写入失败时不自增，保持原值 |
| 文件损坏兜底 | `sessions.json` 或 `qa_records.json` JSON 解析失败 | 以空列表 `[]` 启动，写入 ERROR 日志（含文件路径与异常信息），不崩溃，不覆盖损坏文件 |

**首次问答自动命名实现参考**：

```python
if session["query_count"] == 1:
    session["title"] = query[:20] + ("..." if len(query) > 20 else "")
```

## 7. API 响应 DTO 概要

> 详细端点定义见 `09`。此处列出关键 DTO 与存储字段的映射关系。

| API 端点 | 核心 DTO 字段（来自存储） | 额外注入（非存储字段） |
|----------|--------------------------|----------------------|
| `POST /ask` | `answer`、`llm_used`、`model`、`response_time_ms`、`answer_source`、`cited_passages` | `traceId` |
| `POST /sessions` | `session_id`、`title`、`created_at`、`query_count`、`status` | `traceId` |
| `GET /sessions` | `sessions[]`（含各 Session 全字段，排除 `status=deleted`） | `traceId` |
| `DELETE /sessions/<id>` | `session_id`、`status`、`deleted_at`（即 `updated_at`） | `traceId` |
| `GET /sessions/<id>/records` | `records[]`（含各 QARecord 全字段） | `traceId` |
