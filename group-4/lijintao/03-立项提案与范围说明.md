## 1. 背景与问题

> 描述用户遇到的问题，至少写 2~3 条痛点。参考：信息获取、历史记录、可追溯性、系统可用性。

| 痛点 | 来源 |
|------|------|
| 信息分散：研报、新闻、数据分布在多个系统，无统一问答入口 | 用户访谈 |
| 信息阅读效率低：每天花费大量时间查找/整理关键信息，无法快速验证信息有效性 | 邮件沟通 |
| 历史记录难追溯：过往问答记录分散，无法快速回顾和复用 | 用户反馈 |

## 2. 提案概要

> 用 3~5 句话概括要做什么。参考格式："在 XXX 应用内交付 YYY 能力"。要素：会话式问答 · 能力降级 · 可追溯

在投研问答助手应用内，交付**"统一问答入口 + 关键信息验证"**能力，解决投研人员"多系统信息分散、信息验证效率低"的痛点，实现**会话式问答、能力降级（如 LLM 不可用时切换备用方案）、历史记录可追溯**的核心诉求，提升投研工作效率。

## 3. 范围边界

> 明确"做什么"和"不做什么"，避免范围蔓延。各写 3~4 条。

| 做（范围内） | 不做（范围外） |
|-------------|---------------|
| 会话管理：创建、列表、删除会话 | 多租户/行级数据权限（仅支持单租户基础权限） |
| 问答能力：基于 LLM 实现投研问题问答（支持文本/结构化数据问答） | 复杂数据可视化（仅支持文本/表格类信息展示） |
| 历史记录：会话历史存储、查询、搜索 | 第三方系统深度集成（仅支持内部数据源对接） |
| 系统监控：健康检查、状态监控 | 自动化运维、自动扩缩容 |

## 4. 成功标准（可度量）

> 写出 3~4 条可量化的验收标准。句式：用户在 X 分钟内完成 XXX 全链路 / 未配置外部模型时返回 XXX

| 标准 | 度量方式 |
|------|----------|
| 主路径可走通 | 用户在 3 分钟内完成"新建会话 → 提问 → 查看历史"全链路 |
| 问答准确率 | 投研问题问答的准确率 ≥ 85%（基于 100 条典型问题的测试） |
| 历史记录查询效率 | 用户查询历史会话的响应时间 ≤ 2 秒（95% 场景下） |
| 离线可用 | 未配置密钥时系统仍返回离线演示回复（`is_degraded=true`） |

## 5. 风险（简表）

> 列出 2~3 个主要风险。常见方向：外部依赖不可用、数据存储并发、模块间契约延期。

| 风险 | 影响 | 应对 |
|------|------|------|
| 外部 LLM 不可用（如 API 限流、服务中断） | 问答功能降级（无法调用外部模型） | 四级降级：Azure OpenAI → OpenAI → Claude → 本地模型兜底 |
| 数据存储并发过高（多用户同时读写历史记录） | 系统响应变慢、数据丢失/冲突 | 1. 优化数据库索引，提升读写性能；2. 引入 Redis 缓存；3. 数据库连接池管理 |
| 系统可用性风险（单点故障） | 服务完全不可用 | 1. 无状态设计支持水平扩展；2. 健康检查与自动恢复；3. 数据备份策略 |

## 6. 立项前置条件（Go / No-Go）

- ☐ 后端与前端可独立启动（开发环境验证通过）
- ☐ 数据库可连接并正常读写
- ☐ Redis 缓存服务可连接
- ☐ LLM 接口联调成功（至少一个 Provider）
- ☐ 演示数据目录可读写（数据初始化、测试通过）
