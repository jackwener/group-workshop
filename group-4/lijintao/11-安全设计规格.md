## 1. 安全目标与合规要求

> 明确本模块需遵循的安全目标和外部合规标准。投研场景尤其关注数据隐私与内部信息防泄露。

| 安全目标 | 说明 | 对应合规 |
|----------|------|----------|
| 数据不出域 | 所有用户数据、问答记录禁止传输至外部服务（LLM 除外） | 内部信息安全规范 |
| 最小权限原则 | 每个组件只拥有完成任务所需的最低权限 | 安全设计最佳实践 |
| 审计可追溯 | 所有敏感操作记录审计日志，支持事后追溯 | 合规审计要求 |
| 传输加密 | 所有数据传输使用 TLS 1.3 加密 | 网络安全规范 |

## 2. 认证与授权

> 定义用户身份验证方式和权限控制模型。写出认证流程和角色划分。

### 2.1 认证机制

| 项目 | 规格 |
|------|------|
| 认证方式 | JWT Token (Access Token + Refresh Token) |
| Token 有效期 | Access Token: 15分钟, Refresh Token: 7天 |
| 密码策略 | 最少8位，含大小写+数字+特殊字符，90天强制更换 |
| 多因素认证 | P1 阶段支持，通过短信/邮件验证码触发 |
| Token 存储 | HttpOnly Cookie + Secure 标志 |

### 2.2 角色与权限矩阵

| 角色 | 会话管理 | 问答交互 | 历史查看 | 历史搜索 | 系统管理 |
|------|----------|----------|----------|----------|----------|
| 普通用户 | ✓ | ✓ | ✓ | ✓ | ✗ |
| 管理员 | ✓ | ✓ | ✓ | ✓ | ✓ |

**数据隔离原则**：用户只能访问自己的会话和消息数据，通过 `user_id` 进行行级隔离。

## 3. 数据安全

> 定义数据分类分级、加密策略、存储安全规范。**投研场景核心关注点**。

### 3.1 数据分类与分级

| 数据类型 | 安全等级 | 示例 | 保护措施 |
|----------|----------|------|----------|
| 用户密码 | **机密** | bcrypt 哈希值 | 加密存储，禁止明文 |
| JWT Secret | **机密** | 签名密钥 | 环境变量注入，不入代码库 |
| LLM API Key | **机密** | OpenAI/Azure 密钥 | 密钥管理服务或环境变量 |
| 问答记录 | **内部** | 用户提问与AI回答 | 存储加密，定期清理（365天） |
| 用户信息 | **内部** | 用户名、角色、操作日志 | 脱敏展示，最小采集 |
| 会话元数据 | 一般 | 会话标题、创建时间 | 标准存储 |

### 3.2 加密策略

| 场景 | 加密方式 | 说明 |
|------|----------|------|
| 传输加密 | TLS 1.3 | 所有 API 通信强制 HTTPS |
| 存储加密 | AES-256 | 敏感字段（密码哈希已加密） |
| 密钥管理 | 环境变量 + Docker Secrets | 密钥不硬编码，定期轮转 |
| 数据库连接 | SSL/TLS | 数据库连接强制加密 |

## 4. 接口安全

> 与 `09` API 规格配合，定义 API 层面的安全防护措施。

| 防护措施 | 实现方式 | 说明 |
|----------|----------|------|
| 输入校验 | Pydantic 模型校验 | 所有用户输入进行类型、长度、格式校验 |
| SQL 注入防护 | SQLAlchemy ORM + 参数化查询 | 禁止字符串拼接 SQL |
| XSS 防护 | 输出转义 + CSP 策略 | 消息内容渲染时防止脚本注入 |
| CSRF 防护 | SameSite Cookie + CSRF Token | 状态变更接口需验证 |
| 速率限制 | 100 req/min/user，突发 150 | 防止接口滥用 |
| 文件上传校验 | 本系统无文件上传功能 | N/A |

### 4.1 速率限制规则

| 端点 | 限制 | 说明 |
|------|------|------|
| `POST /sessions/{id}/messages` | 30 req/min | 防止消息轰炸 |
| `POST /sessions` | 10 req/min | 防止会话创建滥用 |
| `GET /sessions` | 60 req/min | 正常浏览频率 |
| 其他 GET | 100 req/min | 标准限制 |

## 5. LLM / AI 安全

> 针对大模型集成的专项安全措施。投研场景数据敏感，需严格管控数据流向。

| 风险点 | 防护措施 | 验收标准 |
|--------|----------|----------|
| 数据外泄至第三方模型 | 1. 优先使用 Azure OpenAI（企业级）<br>2. 降级链路可控<br>3. 敏感数据过滤 | 审计日志无敏感数据外泄记录 |
| Prompt 注入攻击 | 1. 系统 Prompt 隔离<br>2. 用户输入预处理过滤<br>3. 特殊字符转义 | 通过 OWASP Prompt Injection 测试集 |
| 模型幻觉 / 错误信息 | 1. 回答标注来源引用<br>2. 显示 `is_degraded` 状态<br>3. 免责声明 | 界面显示"AI 生成内容仅供参考" |
| 敏感信息泄露（模型回复） | 1. 输出过滤层<br>2. 正则匹配敏感信息并脱敏<br>3. 人工复核机制 | 敏感信息识别率 ≥ 95% |

### 5.1 敏感信息过滤规则

| 类型 | 匹配规则 | 处理方式 |
|------|----------|----------|
| 身份证号 | `\d{17}[\dXx]` | 替换为 `****` |
| 手机号 | `1[3-9]\d{9}` | 替换为 `1****` |
| 银行卡号 | `\d{16,19}` | 替换为 `****` |
| 邮箱 | `[\w.-]+@[\w.-]+` | 替换为 `***@***.com` |

## 6. 审计与日志

> 定义安全审计日志的记录范围、保留策略。

| 事件类型 | 记录内容 | 保留期限 | 告警 |
|----------|----------|----------|------|
| 登录 / 登出 | 用户ID、时间、IP、设备、结果 | 180天 | 连续失败 ≥5 次告警 |
| 会话操作 | 创建/删除会话、会话ID | 90天 | 批量删除告警（>10/小时） |
| 消息发送 | 消息ID、会话ID、Token数（不含内容） | 90天 | 异常频率告警 |
| 降级事件 | 降级原因、目标 Provider | 365天 | 每次降级即时通知 |
| 系统配置变更 | 变更人、变更项、变更前后值 | 永久 | 关键配置变更即时通知 |

### 6.1 日志安全要求

| 要求 | 实现 |
|------|------|
| 日志脱敏 | 不包含密码、Token、API Key |
| 日志完整性 | 只追加，不修改 |
| 日志访问控制 | 仅管理员可查看 |
| 日志备份 | 每日备份至独立存储 |

## 7. 安全威胁清单（STRIDE 简表）

> 基于 STRIDE 模型，列出主要安全威胁与应对方案。

| 类型 | 威胁 | 风险等级 | 应对措施 | 负责人 |
|------|------|----------|----------|--------|
| S - 伪造身份 | 伪造用户身份访问会话数据 | **高** | JWT 签名验证 + Token 过期机制 | 后端开发 |
| T - 篡改 | 消息内容在传输中被篡改 | 中 | TLS 1.3 + 消息签名 | 后端开发 |
| R - 抵赖 | 用户否认发送过某消息 | 中 | 审计日志 + 数字签名 | 后端开发 |
| I - 信息泄露 | 内部数据通过AI模型泄露 | **高** | 本地模型兜底 + 输出过滤 + 敏感数据检测 | 后端开发 |
| D - 拒绝服务 | 大量请求导致服务不可用 | 中 | 速率限制 + 降级策略 + 熔断器 | 后端开发 |
| E - 权限提升 | 普通用户获取管理员权限 | **高** | RBAC 权限控制 + 接口鉴权 | 后端开发 |

## 8. 部署安全

> 定义部署架构中的安全要求。

- [x] 生产/开发环境**严格隔离**，数据不互通
- [x] 数据库访问仅限应用服务器 IP 白名单
- [x] 敏感配置（API Key、密码）通过环境变量注入，不入代码仓库
- [x] 依赖包定期安全扫描（`pip-audit` / `npm audit`）
- [x] 容器镜像使用非 root 用户运行
- [x] 网络隔离：数据库、Redis 不暴露公网
- [x] 定期漏洞扫描（每月一次）
