## 1. 里程碑（S1～S4）

> **切分原则**：每刀切出一个**可演示的用户价值**。不是"接口写好了"，而是"能给业务看什么"。

| 阶段 | 交付要点（可演示） | 满足的 REQ/US | 验证 TC |
|------|-------------------|---------------|---------|
| **S1** 基础架构与会话管理 | 项目初始化 + 数据库设计 + 会话 CRUD API + 前端基础布局 + 会话侧栏 | REQ-M1QA-001 | TC-001~003 |
| **S2** 问答核心功能 | LLM 集成 + 问答 API + 流式响应 + 降级策略 + 消息展示 | REQ-M1QA-002 | TC-004~008 |
| **S3** 历史与搜索 | 历史记录分页加载 + 关键词搜索 + 消息持久化 + 缓存优化 | REQ-M1QA-003 | TC-009~012 |
| **S4** 监控与发布 | 健康检查 + 系统监控 + 性能优化 + 安全加固 + 文档完善 | REQ-M1QA-004 | TC-013~016 |

### 里程碑详细说明

**S1 基础架构与会话管理（Week 1-2）**
- 后端：FastAPI 项目搭建、数据库模型、会话 API 实现
- 前端：Next.js 项目搭建、基础布局、Sidebar 组件
- 可演示：创建/查看/删除会话

**S2 问答核心功能（Week 3-4）**
- 后端：LLM Provider 集成、消息 API、SSE 流式响应、降级逻辑
- 前端：输入区域、消息气泡、流式渲染、来源标签
- 可演示：完整问答流程，包括降级场景

**S3 历史与搜索（Week 5-6）**
- 后端：历史记录查询、全文搜索、Redis 缓存
- 前端：历史消息加载、搜索框、高亮显示
- 可演示：历史记录查看与搜索

**S4 监控与发布（Week 7-8）**
- 后端：健康检查端点、监控指标、日志完善
- 前端：系统状态指示器
- 可演示：系统健康状态监控

## 2. WBS 任务拆分

> **拆分原则**：按**工程职责**切（路由、存储、LLM、前端），不按功能切。一个 W 可跨多个 S 迭代推进。

| 任务ID | 任务名称 | 具体内容 | DoD（指向 Spec） | 推进阶段 |
|--------|----------|----------|------------------|----------|
| W1 | 路由与 API 层 | FastAPI 路由注册、依赖注入、参数校验、错误处理 | 对齐 `09` 端点与错误码 | S1 起贯穿 S4 |
| W2 | 数据存储层 | SQLAlchemy 模型、Repository 模式、PostgreSQL 操作、Redis 缓存 | 对齐 `10` 数据模型 | S1~S3 |
| W3 | LLM 服务层 | Provider 抽象、Azure/OpenAI/Claude/本地模型集成、降级策略 | 对齐 `08` 架构、`09` API | S2~S4 |
| W4 | 前端基础架构 | Next.js 项目结构、状态管理（Zustand）、API 客户端、路由 | 对齐 `08` 前端架构 | S1 起贯穿 S4 |
| W5 | 前端视图组件 | Sidebar、MessageList、InputArea、Header 组件实现 | 对齐 `06` 功能规格 | S1~S3 |
| W6 | 测试与质量 | 单元测试、集成测试、E2E 测试、性能测试 | 对齐 `13` 测试策略 | S1~S4 |

## 5. 依赖与风险

**依赖链**：

**S1 基础架构** → **S2 问答核心**（必须先有会话才能提问）→ **S3 历史与搜索**（需要先有消息数据）→ **S4 监控与发布**

| 风险 | 影响 | 应对 |
|------|------|------|
| 上游 LLM 不可用 | 问答功能降级 | 四级降级兜底（本地模型保证基本可用） |
| 数据库性能瓶颈 | 历史查询慢 | 提前设计索引 + Redis 缓存 |
| 前端 SSE 兼容性 | 流式响应异常 | 提供降级方案（非流式响应） |
| 开发进度延期 | 里程碑推迟 | 每阶段预留 20% 缓冲时间 |
