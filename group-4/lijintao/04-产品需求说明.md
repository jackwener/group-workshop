> **04 的定位**：`03` 说了"为什么做"，04 翻译成"做什么、不做什么、多重要"。`05` 再拆成用户故事和验收标准。

## 1. 愿景与目标

> 把 `03` §1 的痛点翻译成正面目标。格式："构建 XXX，帮助用户在 XXX 内完成 XXX"。

**痛点→目标映射**：

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息分散、无统一入口 | 统一会话问答入口 |
| 信息阅读效率低 | 快速问答响应（3秒内首字节） |
| 历史记录难追溯 | 会话历史自动沉淀，随时回看与搜索 |

## 2. 目标用户

> 把 `03` §2 的一句话展开成具体角色。思考：谁会用？用来做什么？多常用？

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 投研分析师 | 快速查询投研观点与市场解释 | 每天多次 |
| 投资经理 | 验证投资假设、获取数据支持 | 每天 3-5 次 |
| 风控人员 | 查询风险指标、合规信息 | 每周多次 |

## 3. 核心业务场景

> 把 `03` §2 提案概要拆成 4~5 条用户路径。每条场景 = 一条用户操作动线。

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 新建会话并提问 | 用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库 |
| SC-02 | 查看历史会话 | 用户从侧边栏选择已有会话 → 加载历史消息 → 继续对话 |
| SC-03 | 搜索历史记录 | 用户在搜索框输入关键词 → 系统高亮匹配的历史消息 → 用户点击查看详情 |
| SC-04 | 删除会话 | 用户在侧边栏选择会话 → 点击删除 → 确认后会话及历史消息永久删除 |
| SC-05 | 监控系统状态 | 管理员访问健康检查端点 → 查看各组件状态 → 接收异常告警 |

## 4. 产品规则

> 把 `03` §4 成功标准 + §3 范围约束展开成可落地的规则。参考方向：输入约束、返回字段、状态管理、降级策略。

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 每条提问必须绑定 `session_id` | 03 §2 "会话式问答" |
| R-02 | `content` 长度 1～4000 字符，为空或超长返回明确错误 | 03 §4 "P0 全部可测" |
| R-03 | 回答必须携带 `role`、`content`、`provider`、`is_degraded` 字段 | 数据完整性要求 |
| R-04 | 四级降级策略：Azure OpenAI → OpenAI → Claude → 本地模型，降级时 `is_degraded=true` | 03 §5 风险应对 |
| R-05 | 会话状态：活跃/已删除，删除后不可恢复 | 数据生命周期管理 |
| R-06 | 单用户最多创建 100 个会话，单会话最多 1000 条消息 | 系统容量约束 |

## 5. 能力与优先级

> `03` §3 范围表写了"做什么"，04 按 P0/P1 排优先级。P0 = 必须实现，阻塞发布；P1 = 应当实现，不阻塞首版。

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 会话管理（列表 / 新建 / 删除） | **P0** | SC-01, SC-02, SC-04 |
| 问答提交与四级降级 | **P0** | SC-01 |
| 历史记录查看与搜索 | **P0** | SC-02, SC-03 |
| 流式响应（SSE） | **P0** | SC-01 |
| 系统健康检查 | **P1** | SC-05 |
| 用户认证与授权 | **P1** | 全局 |

## 6. 验收与成功标准（PRD 层）

> 从 `03` §4 可度量标准出发，加上演示条件。
> **参考句式**："种子数据 ≥ N 条下，XXX 在 N 分钟内完成"

| 标准 | 度量 |
|------|------|
| 可演示 | 种子数据 ≥ 10 条下，主路径 + 历史 + 能力状态 **3 分钟内**演示完毕 |
| 离线可用 | 未配置密钥时系统仍返回离线演示回复（`is_degraded=true`） |
| 性能达标 | 问答响应 P95 ≤ 3秒，历史查询 ≤ 2秒 |
| 准确率达标 | 投研问题问答准确率 ≥ 85%（基于 100 条典型问题测试） |

## 7. 与 05 用户故事的关系

> **04 定"做什么、多重要"；05 定"谁要什么、怎么验收"。** 填写完本文后，下一步进入 `05` 将场景拆成 US + AC。

| 本文（PRD） | 作用 | 05 中落地 |
|-------------|------|-----------|
| §3 核心场景 | 一条叙事场景 → 一条或多条 US | SC-01 → US-001 + US-002 |
| §4 产品规则 | 字段/状态/错误口径 | 拆入各 US 的 AC |
| §5 能力优先级 | P0 / P1 | 与各 US 优先级一致 |
