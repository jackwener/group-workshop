## 1. 里程碑（S1～S4）

> **切分原则**：每刀切出一个**可演示的用户价值**。不是"接口写好了"，而是"能给业务看什么"。

**示例 — S1**：

**S1 会话管理**：创建/列表/删除会话 API + 前端会话侧栏 → 满足 REQ-001 部分 → 验证 TC-M01-020～025

| 阶段 | 交付要点（可演示） | 满足的 REQ/US | 验证 TC |
|------|-------------------|--------------|---------|
| **S1** 会话管理 | 会话 CRUD API + 前端侧栏 | REQ-M4RA-001 | TC-M01-020～025 |
| **S2** 问答核心 | 问答提交 + 三级降级 + 来源标签 | REQ-M4RA-002 | TC-M01-001～004 |
| **S3** 研报功能 | 研报上传/解析 + 多研报对比 + 研报管理 | REQ-M4RA-003, 004, 006 | TC-M01-048～056 |
| **S4** 智能问答与收口 | 研报智能问答（原文引用）+ 全链路 E2E + 发布准备 | REQ-M4RA-005 | TC-M01-060～065 |

## 2. WBS 任务拆分

> **拆分原则**：按**工程职责**切（路由、存储、Agent、前端），不按功能切。一个 W 可跨多个 S 迭代推进。

| 任务ID | 任务名称 | 具体内容 | DoD（指向 Spec） | 推进阶段 |
|--------|----------|----------|------------------|----------|
| W1 | 路由实现 | `agent_bp.py` 端点注册、参数校验 | 对齐 `09` 全14个端点与错误码 | S1 起贯穿 S4 |
| W2 | 存储层 | `storage.py` JSON CRUD | 对齐 `10` 数据模型，16个 Storage 方法全实现 | S1～S3 |
| W3 | Agent 编排 | `agent.py` 三级降级编排，研报解析/对比编排 | 对齐 `08` §4 降级链 + `07` §1.2 SLO | S2～S3 |
| W4 | 前端视图 | `App.jsx` 会话侧栏、问答区、研报多标签页、对比分析 | 对齐 `06` 全部 UI 规格，9个 State 变量 | S1～S4 |
| W5 | 研报解析引擎 | PDF/HTML 解析器，关键信息提取（评级/目标价/观点） | 解析准确率 ≥ 85%（`07` §7），状态流转 `10` §8 | S3 |
| W6 | 测试门禁 | `tests/` 下全部 TC 实现 + CI 流水线 | 对齐 `13` 质量门禁 G-LINT / G-UNIT / G-INT / G-AC | S1～S4 |

## 5. 依赖与风险

**示例 — 依赖链**：

**S1 会话管理** → **S2 问答核心**（必须先有会话才能提问）→ **S3 研报功能**（上传/解析/对比/管理）→ **S4 智能问答与收口**

| 风险 | 影响 | 应对 |
|------|------|------|
| 上游 LLM 不可用 | 问答降级 | Demo 模式兆底，S2 演示不阻塞 |
| PDF 解析库兼容性 | 解析准确率不达标 | 提前准备多格式测试样本，S3 分配足够 buffer |
| 前后端接口契约变更 | 联调返工 | 以 `09` 为契约真源，变更走 CR 流程 |
