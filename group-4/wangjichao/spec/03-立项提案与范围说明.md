## 1. 背景与问题

> 描述用户遇到的问题，至少写 2~3 条痛点。参考：信息获取、历史记录、可追溯性、系统可用性。

| 痛点 | 来源 |
|------|------|
| 研报阅读耗时：每天需阅读10+份研报，平均每份30-50页，耗时2-3小时 | 会议纪要-S01 |
| 研报关键信息提取不完整：难以快速提取评级、目标价、核心观点 | 会议纪要-S01 |
| 多份研报对比困难：需手动复制粘贴到Excel整理，效率低 | 邮件沟通-S02 |
| 股票数据查询不便：需在多个系统间切换 | 邮件沟通-S02 |

## 2. 提案概要

> 用 3~5 句话概括要做什么。参考格式："在 XXX 应用内交付 YYY 能力"。要素：会话式问答 · 能力降级 · 可追溯

在研报平台内交付研报聚合分析能力，支持研报解析（PDF/HTML）、智能问答（基于研报内容自然语言问答，支持引用原文）、研报对比（自动生成关键指标对比表），解决研报阅读耗时、信息提取困难、多份研报对比繁琐的问题。系统采用内部部署确保数据安全，并具备能力降级机制。

## 3. 范围边界

> 明确"做什么"和"不做什么"，避免范围蔓延。各写 3~4 条。

| 做（范围内） | 不做（范围外） |
|-------------|---------------|
| 会话管理：创建、列表、删除 | 多租户/行级数据权限 |
| 研报解析：支持PDF/HTML格式，自动提取标题、评级、目标价、核心观点 | 舆情监控、新闻告警 |
| 研报管理：新增、搜索、阅读、标记 | 编辑功能 |
| 智能问答：基于研报内容自然语言问答，支持引用原文 | 投资建议生成 |
| 研报对比：多份研报关键指标自动生成对比表 | 会议记录管理 |

## 4. 成功标准（可度量）

> 写出 3~4 条可量化的验收标准。句式：用户在 X 分钟内完成 XXX 全链路 / 未配置外部模型时返回 XXX

| 标准 | 度量方式 |
|------|----------|
| 主路径可走通 | 用户在 3 分钟内完成"上传研报 → 自动解析 → 提问 → 查看答案及原文引用"全链路 |
| 研报解析准确率 | 评级、目标价、核心观点等关键字段提取准确率 ≥ 85% |
| 问答可用性 | 用户可以在平台完成研报内容的自然语言问答，答案附带原文引用 |
| 研报对比效率 | 3份研报对比表生成时间 ≤ 30秒 |
| 研报可管理 | 用户可以新增、搜索、标记研报 |

## 5. 风险（简表）

> 列出 2~3 个主要风险。常见方向：外部依赖不可用、数据存储并发、模块间契约延期。

| 风险 | 影响 | 应对 |
|------|------|------|
| 外部 LLM 不可用 | 问答功能降级 | 三级降级：CoPaw → 百炼 → Demo 模式兜底 |
| 回答不准确（幻觉） | 问答可用性、用户信任度 | 辅助判断：原文引用、多模型对比验证 |
| 数据安全风险 | 合规问题 | 内部部署，数据不出域，符合用户访谈中"数据安全第一"要求 |

## 6. 立项前置条件（Go / No-Go）

- ☐ 后端与前端可独立启动
- ☐ 演示数据目录可读写
- ☐ LLM 服务接入配置完成（CoPaw/百炼至少一个可用）
- ☐ 研报解析测试数据准备（PDF/HTML格式样本）
