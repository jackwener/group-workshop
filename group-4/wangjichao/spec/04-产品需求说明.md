> **04 的定位**：`03` 说了"为什么做"，04 翻译成"做什么、不做什么、多重要"。`05` 再拆成用户故事和验收标准。

## 1. 愿景与目标

> 把 `03` §1 的痛点翻译成正面目标。格式："构建 XXX，帮助用户在 XXX 内完成 XXX"。

**示例 — 痛点→目标映射**：

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息分散、无统一入口 | 统一会话问答入口 |
| 复盘成本高 | 会话历史自动沉淀，随时回看 |

| 03 痛点 | 04 目标 |
|---------|---------|
| 研报阅读耗时，每天2-3小时 | 构建研报自动解析功能，帮助用户在10秒内提取关键信息 |
| 研报关键信息提取不完整 | 系统自动提取评级、目标价、核心观点，确保关键信息完整性 |
| 多份研报对比困难 | 一键生成多研报对比表，帮助用户在1分钟内完成对比分析 |
| 股票数据查询不便 | 集成股票数据查询，研报阅读界面直接展示相关数据 |

## 2. 目标用户

> 把 `03` §2 的一句话展开成具体角色。思考：谁会用？用来做什么？多常用？

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 投研分析师 | 快速查询投研观点与市场解释 | 每天多次 |
| 投资经理 | 研报核心信息快速浏览与对比 | 每周2-3次 |
| 研究助理 | 研报整理与信息提取辅助 | 每天频繁 |

## 3. 核心业务场景

> 把 `03` §2 提案概要拆成 4~5 条用户路径。每条场景 = 一条用户操作动线。

**示例 — SC-01**：

**SC-01 新建会话并提问**：用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 新建会话并提问 | （见上方示例） |
| SC-02 | 研报上传与解析 | 用户上传PDF/HTML研报 → 系统自动提取标题、评级、目标价、核心观点 → 用户查看解析结果 |
| SC-03 | 多研报对比分析 | 用户选择多份研报 → 系统生成关键指标对比表（评级、目标价、核心观点）→ 用户查看对比结果 |
| SC-04 | 研报智能问答 | 用户对研报内容提问 → 系统返回答案并标注原文引用 → 支持追问与澄清 |
| SC-05 | 研报管理 | 用户新增研报 → 搜索研报（按标题/评级/时间）→ 标记研报（重点/已读）→ 查看研报详情 |

## 4. 产品规则

> 把 `03` §4 成功标准 + §3 范围约束展开成可落地的规则。参考方向：输入约束、返回字段、状态管理、降级策略。

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 每条提问必须绑定 `session_id` | 03 §2 "会话式问答" |
| R-02 | `query` 长度 1～500 字符，为空或超长返回明确错误 | 03 §4 "P0 全部可测" |
| R-03 | 研报解析结果 MUST 包含字段：标题、评级、目标价、核心观点、来源研报ID | 02 S-01 "需求记录" |
| R-04 | LLM服务不可用时，系统MUST降级返回离线演示回复，并标注 `answer_source=demo` | 02 S-03 "数据安全第一" |
| R-05 | 所有研报数据MUST本地存储，不得上传至外部服务器 | 02 S-03 "必须本地部署" |

## 5. 能力与优先级

> `03` §3 范围表写了"做什么"，04 按 P0/P1 排优先级。P0 = 必须实现，阻塞发布；P1 = 应当实现，不阻塞首版。

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 会话管理（列表 / 新建 / 删除） | **P0** | SC-01, SC-03 |
| 问答提交与三级降级 | **P0** | SC-01 |
| 研报上传与解析（PDF/HTML） | **P0** | SC-02 |
| 多研报对比分析 | **P0** | SC-03 |
| 研报智能问答（带原文引用） | **P1** | SC-04 |
| 研报管理（新增/搜索/标记） | **P1** | SC-05 |

## 6. 验收与成功标准（PRD 层）

> 从 `03` §4 可度量标准出发，加上演示条件。
> **参考句式**："种子数据 ≥ N 条下，XXX 在 N 分钟内完成"

| 标准 | 度量 |
|------|------|
| 可演示 | 种子数据 ≥ 10 条下，主路径 + 历史 + 能力状态 **3 分钟内**演示完毕 |
| 离线可用 | 未配置密钥时系统仍返回离线演示回复（`answer_source=demo`） |
| 解析效率 | 研报上传后在 **5 秒内**完成解析并返回关键信息 |
| 问答响应 | 智能问答平均响应时间 **≤ 3 秒**，引用原文准确率 ≥ 90% |
| 研报解析准确率 | 评级、目标价、核心观点等关键字段提取准确率 **≥ 85%** |
| 研报对比效率 | 3份研报对比表生成时间 **≤ 30秒** |

## 7. 与 05 用户故事的关系

> **04 定"做什么、多重要"；05 定"谁要什么、怎么验收"。** 填写完本文后，下一步进入 `05` 将场景拆成 US + AC。

| 本文（PRD） | 作用 | 05 中落地 |
|-------------|------|-----------|
| §3 核心场景 | 一条叙事场景 → 一条或多条 US | SC-01 → US-001 + US-002 |
| §4 产品规则 | 字段/状态/错误口径 | 拆入各 US 的 AC |
| §5 能力优先级 | P0 / P1 | 与各 US 优先级一致 |
