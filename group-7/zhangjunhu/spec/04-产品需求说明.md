> **04 的定位**：`03` 说了"为什么做"，04 翻译成"做什么、不做什么、多重要"。`05` 再拆成用户故事和验收标准。

## 1. 愿景与目标

> 把 `03` §1 的痛点翻译成正面目标。格式："构建 XXX，帮助用户在 XXX 内完成 XXX"。

**示例 — 痛点→目标映射**：

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息分散、无统一入口 | 统一会话问答入口 |
| 复盘成本高 | 会话历史自动沉淀，随时回看 |

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息分散：研报、新闻、数据分布在多个系统，无统一问答入口 | 构建统一研报问答入口，支持自然语言查询研报信息 |
| 效率低：研报内容多、长，需关联不同数据源 | 实现智能问答提取关键信息，支持横向对比分析 |
| 易用性：无界面，数据切换复杂、对比不直观 | 提供可视化界面，支持研报数据直观展示与对比 |

## 2. 目标用户

> 把 `03` §2 的一句话展开成具体角色。思考：谁会用？用来做什么？多常用？

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 投研分析师 | 快速查询投研观点与市场解释 | 每天多次 |
| 投研总监 | 查看整体研报覆盖情况，掌握重要信息 | 每天1-2次 |
| 运维人员 | 监控系统健康状态，及时发现处理问题 | 按需 |

## 3. 核心业务场景

> 把 `03` §2 提案概要拆成 4~5 条用户路径。每条场景 = 一条用户操作动线。

**示例 — SC-01**：

**SC-01 新建会话并提问**：用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 新建会话并提问 | （见上方示例） |
| SC-02 | 研报信息查询 | 用户选择会话 → 输入研报相关问题 → 系统返回研报关键信息（评级、目标价、核心观点） |
| SC-03 | 历史记录查看 | 用户点击历史会话 → 查看过往问答记录 → 可基于历史继续提问 |
| SC-04 | 股票信息查询 | 用户在问答中涉及股票 → 点击股票信息 → 查看相关股票数据 |

## 4. 产品规则

> 把 `03` §4 成功标准 + §3 范围约束展开成可落地的规则。参考方向：输入约束、返回字段、状态管理、降级策略。

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 每条提问必须绑定 `session_id` | 03 §2 "会话式问答" |
| R-02 | `query` 长度 1～500 字符，为空或超长返回明确错误 | 03 §4 "P0 全部可测" |
| R-03 | 回答必须携带 answer、llm_used、model、response_time_ms、answer_source 字段 | 03 §4 "关键内容完整" |
| R-04 | 三级降级策略：CoPaw → 百炼 → Demo，静默执行不抛异常 | 03 §5 "外部 LLM 不可用" |
| R-05 | 会话状态：当前会话不可删除，历史会话可删除且不可恢复 | 05 US-001 AC-001-02 |

## 5. 能力与优先级

> `03` §3 范围表写了"做什么"，04 按 P0/P1 排优先级。P0 = 必须实现，阻塞发布；P1 = 应当实现，不阻塞首版。

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 会话管理（列表 / 新建 / 删除） | **P0** | SC-01, SC-03 |
| 问答提交与三级降级 | **P0** | SC-01, SC-02 |
| 历史记录查看 | **P0** | SC-03 |
| 股票信息查询 | **P1** | SC-04 |
| 健康检查 | **P1** | 运维场景 |

## 6. 验收与成功标准（PRD 层）

> 从 `03` §4 可度量标准出发，加上演示条件。
> **参考句式**："种子数据 ≥ N 条下，XXX 在 N 分钟内完成"

| 标准 | 度量 |
|------|------|
| 可演示 | 种子数据 ≥ 10 条下，主路径 + 历史 + 能力状态 **3 分钟内**演示完毕 |
| 离线可用 | 未配置密钥时系统仍返回离线演示回复（`answer_source=demo`） |
| 关键内容完整 | 问答返回包含评级、目标价、核心观点等关键字段 |
| 历史可追溯 | 30天内会话历史可查询，按时间倒序排列 |

## 7. 与 05 用户故事的关系

> **04 定"做什么、多重要"；05 定"谁要什么、怎么验收"。** 填写完本文后，下一步进入 `05` 将场景拆成 US + AC。

| 本文（PRD） | 作用 | 05 中落地 |
|-------------|------|-----------|
| §3 核心场景 | 一条叙事场景 → 一条或多条 US | SC-01 → US-001 + US-002 |
| §4 产品规则 | 字段/状态/错误口径 | 拆入各 US 的 AC |
| §5 能力优先级 | P0 / P1 | 与各 US 优先级一致 |
