## 1. 里程碑（S1～S4）

> **切分原则**：每刀切出一个**可演示的用户价值**。不是"接口写好了"，而是"能给业务看什么"。

**示例 — S1**：

**S1 会话管理**：创建/列表/删除会话 API + 前端会话侧栏 → 满足 REQ-001 部分 → 验证 TC-M01-020～025

| 阶段 | 交付要点（可演示） | 满足的 REQ/US | 验证 TC |
|------|-------------------|---------------|---------|
| **S1** 会话管理 | 会话 CRUD API + 前端侧栏 | REQ-001 部分 | TC-M01-020～025 |
| **S2** 问答核心 | 问答提交 API（SSE 流式）+ 三级降级 + 前端流式问答区 | REQ-002 | TC-M01-001～004 |
| **S3** 历史记录 | 问答记录查询 + 关键词搜索 + 相似性检测 + 首次命名 | REQ-003 | TC-M01-030～031, TC-M01-060～061 |
| **S4** 股票信息查询 | 股票标记识别 + 股票信息查询端点 + 前端触发查询 | REQ-004 | TC-M01-070～072 |

## 2. WBS 任务拆分

> **拆分原则**：按**工程职责**切（路由、存储、Agent、前端），不按功能切。一个 W 可跨多个 S 迭代推进。

| 任务ID | 任务名称 | 具体内容 | DoD（指向 Spec） | 推进阶段 |
|--------|----------|----------|------------------|----------|
| W1 | 路由实现 | `agent_bp.py` 端点注册、参数校验、SSE流式 | 对齐 `09` 端点与错误码 | S1 起贯穿 S4 |
| W2 | 存储层 | `storage.py` JSON CRUD + 搜索 | 对齐 `10` 数据模型 | S1～S3 |
| W3 | Agent 编排 | `agent.py` 三级降级逻辑 + 流式生成 | 对齐 `08` 降级策略 | S2～S3 |
| W4 | 前端视图 | `App.jsx` 会话侧栏、流式问答区、历史搜索、股票标记 | 对齐 `06` FSD | S1～S4 |
| W5 | 状态管理 | React useState 状态流转 + SSE 流式状态 | 对齐 `06` 状态管理 | S2～S3 |
| W6 | 测试门禁 | pytest 测试用例编写 | 对齐 `13` 测试策略 | S2～S4 |
| W7 | 股票服务 | `stock_service.py` 股票识别 + 信息查询 | 对齐 `09` 股票端点 | S4 |

## 3. S × W 对应矩阵

> 读法：**●** = 主要推进，**○** = 少量涉及，**—** = 不涉及

| WBS \ 阶段 | S1 | S2 | S3 | S4 |
|------------|----|----|----|----|  
| **W1** 路由 | ● sessions | ● ask (SSE) | ● records + search + similar | ● stock |
| **W2** 存储 | ● sessions CRUD | ● 记录落库 | ● 搜索+相似 | ○ |
| **W3** Agent | — | ● 三级降级+流式 | ○ 优化 | — |
| **W4** 前端 | ● 会话侧栏 | ● 流式提问区 | ● 搜索+相似性 | ● 股票标记 |
| **W5** 状态机 | — | ● SSE流式状态 | ● 搜索状态 | ○ |
| **W6** 测试 | ○ fixture | ● P0 用例 | ● P1 用例 | ● 覆盖率 |
| **W7** 股票 | — | — | — | ● 股票服务+前端 |

## 5. 依赖与风险

**示例 — 依赖链**：

**S1 会话管理** → **S2 问答核心**（必须先有会话才能提问）→ **S3 历史与状态** → **S4 发布准备**

| 风险 | 影响 | 应对 |
|------|------|------|
| 上游 LLM 不可用 | 问答降级 | Demo 模式兜底 |
| 研报格式差异大 | 解析困难 | 持续迭代支持新格式 |
| 前端状态管理复杂 | 开发延期 | 简化状态设计，分阶段实现 |
