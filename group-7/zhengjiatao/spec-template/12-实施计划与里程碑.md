## 1. 里程碑（S1～S4）

> **切分原则**：每刀切出一个**可演示的用户价值**。不是"接口写好了"，而是"能给业务看什么"。

**示例 — S1**：

**S1 会话管理**：创建/列表/删除会话 API + 前端会话侧栏 → 满足 REQ-001 部分 → 验证 TC-M01-020～025

| 阶段 | 交付要点（可演示） | 满足的 REQ/US | 验证 TC |
|------|-------------------|---------------|---------|
| **S1** 会话管理 | 会话 CRUD API + 前端侧栏 | REQ-001 | TC-001 |
| **S2** 问答核心 | 问答提交 API + 流式响应 + 三级降级 + 前端提问区 | REQ-002 | TC-002 |
| **S3** 历史记录 | 问答记录查询 API + 历史记录展示 + 复制导出功能 | REQ-003 | TC-003 |
| **S4** 运维监控 | 健康检查 API + 系统监控 + 集成测试 + 发布准备 | REQ-004 | TC-004 |

## 2. WBS 任务拆分

> **拆分原则**：按**工程职责**切（路由、存储、Agent、前端），不按功能切。一个 W 可跨多个 S 迭代推进。

| 任务ID | 任务名称 | 具体内容 | DoD（指向 Spec） | 推进阶段 |
|--------|----------|----------|------------------|----------|
| W1 | 路由实现 | `agent_bp.py` 端点注册、参数校验 | 对齐 `09` 端点与错误码 | S1 起贯穿 S4 |
| W2 | 存储层 | `storage.py` JSON CRUD | 对齐 `10` 数据模型 | S1～S2 |
| W3 | Agent 编排 | `agent.py` 三级降级编排、结果组装 | 对齐 `08` §4 降级策略，支持 copaw/bailian/demo 三级降级 | S2～S4 |
| W4 | 前端视图 | React 组件：Sidebar、ChatArea、InputArea | 对齐 `06` 功能规格，实现会话管理、问答交互、历史展示 | S1～S4 |
| W5 | Provider 层 | `copaw_bridge.py`、`bailian_qa.py` 外部 API 调用 | 对齐 `09` /ask API，支持 CoPaw、百炼、Demo 三种模式 | S2～S3 |
| W6 | 测试门禁 | 单元测试、集成测试、API 测试 | 对齐 `13` 测试策略，P0 用例 100% 通过 | S2～S4 |

## 5. 依赖与风险

**依赖链**：

```
S1 会话管理 → S2 问答核心 → S3 历史记录 → S4 运维监控
   (W1,W2,W4)   (W1,W3,W4,W5)   (W1,W2,W4)     (W1,W3,W4,W6)
```

**关键路径**：
- S1 完成前：W2 存储层必须先于 W4 前端侧栏完成
- S2 完成前：W5 Provider 层必须先于 W3 Agent 编排完成
- S3 完成前：W2 级联删除功能必须先于 S3 演示

| 风险 | 影响 | 应对 |
|------|------|------|
| 上游 LLM 不可用 | 问答功能降级，用户体验下降 | Demo 模式兜底，确保基础功能可用 |
| 外部 API 响应超时 | 用户等待时间过长，体验差 | 设置 20s/120s 分级超时，超时自动降级 |
| JSON 文件并发写入冲突 | 数据丢失或损坏 | Storage 层加文件锁，或切换至 SQLite |
| 前端状态管理复杂 | 流式响应状态同步问题 | 使用 React Hooks 严格管理，增加单元测试 |
