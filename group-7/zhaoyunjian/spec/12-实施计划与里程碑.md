## 1. 里程碑（S1～S4）

> **切分原则**：每刀切出一个**可演示的用户价值**。不是"接口写好了"，而是"能给业务看什么"。

**示例 — S1**：

**S1 会话管理**：创建/列表/删除会话 API + 前端会话侧栏 → 满足 REQ-001 部分 → 验证 TC-M01-020～025

| 阶段 | 交付要点（可演示） | 满足的 REQ/US | 验证 TC |
|------|-------------------|---------------|---------|
| **S1** 会话管理 | 会话 CRUD API + 前端会话侧栏，支持新建/切换/删除会话 | REQ-M1QA-001 (US-001) | TC-001-01~05 |
| **S2** 问答核心 | 问答提交API + 三级降级 + 前端问答区，支持提问与回答展示 | REQ-M1QA-002 (US-002) | TC-002-01~04 |
| **S3** 研报管理 | 研报上传/列表/删除API + 分析功能 + 前端研报管理页 | REQ-M1QA-003 (US-003) | TC-003-01~06 |
| **S4** 高级功能 | 历史记录查看 + 健康检查 + 导出功能，系统整体联调 | REQ-M1QA-004~006 (US-004~006) | TC-004~006 |

## 2. WBS 任务拆分

> **拆分原则**：按**工程职责**切（路由、存储、Agent、前端），不按功能切。一个 W 可跨多个 S 迭代推进。

| 任务ID | 任务名称 | 具体内容 | DoD（指向 Spec） | 推进阶段 |
|--------|----------|----------|------------------|----------|
| W1 | 路由实现 | `agent_bp.py` 端点注册、参数校验、traceId注入 | 对齐 `09` 12个端点与10个错误码 | S1 起贯穿 S4 |
| W2 | 存储层 | `storage.py` JSON文件CRUD，Session/QARecord/Report实体 | 对齐 `10` 数据模型与Storage方法清单 | S1～S3 |
| W3 | Agent编排 | `agent.py` 三级降级链(CoPaw→百炼→Demo)，结果组装 | 对齐 `08` 4.1 降级策略，`07` 1.2 | S2～S3 |
| W4 | 前端视图 | React组件：会话侧栏、问答区、研报管理页、历史记录 | 对齐 `09` 响应DTO，支持所有交互 | S1～S4 |
| W5 | 研报分析 | 研报上传处理、异步分析任务、关键信息提取 | 对齐 `09` /reports 端点，`03` 研报分析 | S3 |
| W6 | 测试门禁 | pytest单元测试、API集成测试、前端组件测试 | 覆盖 `05` 所有AC，`09` 参数校验规则 | S2～S4 |

## 5. 依赖与风险

**关键路径与依赖链**：

```
S1 会话管理 → S2 问答核心 → S3 研报管理 → S4 高级功能
    ↓              ↓              ↓
  W2存储层      W3Agent       W5研报分析
  (基础数据)   (核心能力)    (扩展功能)
```

| 风险 | 影响 | 应对 |
|------|------|------|
| 上游 LLM 不可用 | 问答功能降级，用户体验下降 | Demo 模式兜底，确保基础功能可用 |
| 研报分析耗时过长 | 大文件分析阻塞API响应 | 异步任务队列，后台分析+状态轮询 |
| 文件存储空间不足 | 无法上传新研报 | 存储配额限制(50MB/文件)，定期清理 |
| 并发访问JSON文件 | 数据损坏或丢失 | 文件锁机制，或尽快迁移至SQLite(P1) |
