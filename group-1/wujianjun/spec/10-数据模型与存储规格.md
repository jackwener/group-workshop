## 1. 概念模型

```
Session（会话）1 ── * QARecord（问答记录）
   │                      │
   │  session_id (PK)     │  id (PK)
   │  title               │  session_id (FK → Session)
   │  query_count          │  query / answer / llm_used
   │  created_at           │  response_time_ms / answer_source
   └  updated_at           └  timestamp
```

> **核心关系**：一个 Session 可包含零到多条 QARecord。外键通过 `session_id` 字段逻辑引用。

## 2. 存储引擎

| 项 | 说明 |
|----|------|
| 引擎 | JSON 文件（`json` 标准库） |
| 编码 | UTF-8，缩进 2 空格 |
| 读写模式 | RMW（全量读入 → 修改 → 全量写回） |
| 并发安全 | 无锁，不支持并发写入 |
| 文件布局 | `{DATA_DIR}/sessions.json` + `qa_records.json` |

## 3. 实体定义 — Session

| 字段 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| `session_id` | `string` (UUID) | 是 | **PK** | 会话唯一标识 |
| `title` | `string` | 是 | ≤23 字符 | 默认"新会话"，首次问答自动重命名 |
| `created_at` | `string` (ISO-8601) | 是 | UTC+Z | 创建时间 |
| `updated_at` | `string` (ISO-8601) | 是 | UTC+Z | 最后更新时间 |
| `query_count` | `integer` | 是 | ≥ 0 | 累计问答次数 |

## 4. 实体定义 — QARecord

| 字段 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| `record_id` | `string` | 是 | **PK**，`rec_{ts}` | 基于时间戳生成 |
| `session_id` | `string` | 是 | **FK** → Session | 所属会话 |
| `query` | `string` | 是 | 1–500 字符 | 用户提问原文 |
| `answer` | `string` | 是 | — | LLM/Demo 返回的答案 |
| `llm_used` | `boolean` | 是 | RULE-005 | 是否使用真实 LLM |
| `model` | `string\|null` | 是 | — | 模型标识 |
| `response_time_ms` | `integer` | 是 | SLO < 5000 | 响应耗时（ms） |
| `answer_source` | `string` | 是 | 枚举 | `copaw`\|`bailian`\|`demo` |

## 5. Storage 方法清单

> 列出 `storage.py` 模块中 `Storage` 类的全部公开方法。每个方法标注关联的 TC 编号（来自 `13`）。

**类定义**：`class Storage`（定义于 `storage.py`，对齐 `08` §2 后端分层）

### 5.1 会话管理

| 方法 | 签名 | 行为 | 关联 TC |
|------|------|------|---------| |
| `create_session` | `(session_id: str, title: str = "新会话") → dict` | 创建新会话，返回完整 Session 对象 | TC-M01-001, TC-M01-002 |

## 6. 关键业务逻辑

**示例 — 首次问答自动命名**：

```python
if session["query_count"] == 1:
    session["title"] = query[:20] + ("..." if len(query) > 20 else "")
```

> **规则**：仅首次问答（query_count 从 0 → 1）触发，后续不再自动更名。

| 逻辑 | 触发条件 | 行为 |
|------|----------|------|
| 首次问答自动命名 | `query_count` 从 0 → 1 | 标题 = query 前 20 字 + `...`（超过 20 字时）|
| 级联删除 | 删除 Session 时 | 同步删除所有关联 QARecord |
| 更新会话时间戳 | 每次问答提交后 | `updated_at` = 当前时间（ISO-8601 UTC）|
| 计数器递增 | 每次问答提交后 | `query_count` += 1 |
| 三级降级标记 | LLM 调用失败/未配置 | `llm_used=false`, `answer_source="demo"` |

## 7. API 响应 DTO 概要

> 详细端点定义见 `09`。此处列出关键 DTO 与存储字段的映射关系。

| API 端点 | 核心 DTO 字段 | 额外注入 |
|----------|---------------|----------|
| `POST /ask` | answer, llm_used, model, response_time_ms, answer_source | `traceId`, `record_id` |
| `POST /sessions` | session_id, title, created_at, updated_at, query_count | `traceId` |
| `GET /sessions` | sessions[]: session_id, title, created_at, updated_at, query_count | `traceId`, `total` |
| `GET /sessions/{id}/records` | records[]: record_id, query, answer, llm_used, model, response_time_ms, answer_source, timestamp | `traceId`, `session_id`, `total` |
| `DELETE /sessions/{id}` | message, deleted_session_id, deleted_records_count | `traceId` |
| `GET /capabilities` | copaw_configured, bailian_configured, model, mode | `traceId` |
