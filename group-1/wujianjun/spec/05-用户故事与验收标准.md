> **本文只做一件事**：按用户能理解的子场景拆成多条 **User Story**，并为每条写清 **REQ-ID**、**验收标准（AC）**。

## 字段说明 — 每条 UserStory 必须包含以下字段

| 字段 | 填写说明 | 数据来源 ← | 流向下游 → |
|------|----------|------------|-----------|
| **需求编号** | 唯一编号，如 REQ-M1IRA-001 | ← `03` 范围边界 | → `14` 追踪矩阵首列 |
| **故事** | 作为【角色】，我希望【行为】，以便【价值】 | ← `03` 提案概要 | → `06` FSD 功能点 |
| **优先级** | P0（必须）/ P1（应该）/ P2（可选） | ← `03` §4 成功标准 | → `12` 里程碑排期 |
| **来源** | 对应 03 哪一条范围 | ← `03` 范围边界 | |
| **前置条件** | 触发该故事的前提状态 | ← `03` 提案概要 | → `13` 测试前置 |
| **功能对齐** | 对应功能规格 + 非功能约束 | | → `06` FSD · `07` NFR |
| **设计对齐** | 对应架构、接口、数据、安全 | | → `08` 架构 · `09` API · `10` Data · `11` 安全 |
| **验证对齐** | 对应测试用例 + 追踪矩阵行 | | → `13` TC · `14` 追踪矩阵行 |
| **验收标准** | AC，每条可独立验证 | ← 故事 + `07` NFR | → `13` 测试用例依据 |

## US-001（P0）会话管理

| 字段 | 内容 |
|------|------|
| **需求编号** | REQ-M1IRA-001 |
| **故事** | 作为投研分析师，我希望创建、查看和删除问答会话，以便管理不同研报的问答上下文 |
| **优先级** | P0 |
| **来源** | ← 03 §3 范围边界「会话管理：创建、列表、删除会话」 |
| **前置条件** | 系统已部署，用户可访问Web界面 |
| **功能对齐** | → 06 §3 Sidebar 会话管理 · 07 §5.1 输入约束 |
| **设计对齐** | → 08 §2 后端分层 · 09 POST/GET/DELETE /sessions API · 10 Session 表 · 11 §4 安全 |
| **验证对齐** | → 13 TC-M01-020~024 · 14 第1~4行 |

| 验收标准 | 描述（每条可独立测试） |
|----------|----------------------|
| AC-001-01 | 用户可创建新会话，系统自动生成 session_id 和默认标题"新会话" |
| AC-001-02 | 用户可查看所有会话列表，按创建时间倒序排列 |
| AC-001-03 | 用户可删除指定会话，删除后级联删除该会话下所有问答记录 |
| AC-001-04 | 首次提问后，会话标题自动更新为问题前20字 + "..." |

## US-002（P0）研报问答

| 字段 | 内容 |
|------|------|
| **需求编号** | REQ-M1IRA-002 |
| **故事** | 作为投研分析师，我希望基于研报内容进行自然语言问答，以便快速获取关键信息 |
| **优先级** | P0 |
| **来源** | ← 03 §3 范围边界「研报问答：基于研报内容的自然语言问答，支持引用原文」 |
| **前置条件** | 已创建会话，query 长度 1~500 字符 |
| **功能对齐** | → 06 §4 Main 内容区 · 07 §1.1 延迟 SLO < 5s |
| **设计对齐** | → 08 §4 三级降级编排 · 09 POST /ask API · 10 QARecord 表 · 11 §5 LLM 安全 |
| **验证对齐** | → 13 TC-M01-001~004 · 14 第5~8行 |

| 验收标准 | 描述（每条可独立测试） |
|----------|----------------------|
| AC-002-01 | 用户输入有效 query（1~500字符），系统返回 answer、llm_used、model、response_time_ms、answer_source |
| AC-002-02 | query 为空或空白时，返回 400 错误码 EMPTY_QUERY |
| AC-002-03 | query 超过500字符时，返回 400 错误码 INVALID_QUERY |
| AC-002-04 | 无外部 LLM 密钥时，系统自动降级为 Demo 模式，answer_source='demo'，正常返回答案 |
| AC-002-05 | 问答响应时间 P95 < 5 秒（通过 response_time_ms 验证）|

## US-004（P0）数据安全与降级

| 字段 | 内容 |
|------|------|
| **需求编号** | REQ-M1IRA-004 |
| **故事** | 作为投研分析师，我希望系统本地部署且数据不出域，以便保障敏感信息安全 |
| **优先级** | P0 |
| **来源** | ← 03 §3 范围边界「数据安全：本地部署，数据不出域」「能力降级：三级降级」 |
| **前置条件** | 系统已部署 |
| **功能对齐** | → 06 §2.1 能力状态芯片 · 07 §4 安全需求 |
| **设计对齐** | → 08 §4 三级降级 · 09 /capabilities API · 10 本地 JSON 存储 · 11 §3 数据安全 |
| **验证对齐** | → 13 TC-M01-005 · 14 第11行 |

| 验收标准 | 描述（每条可独立测试） |
|----------|----------------------|
| AC-004-01 | 系统显示当前可用能力状态（CoPaw/百炼/离线演示） |
| AC-004-02 | 所有用户数据仅存储在本地 JSON 文件，不传输到外部（LLM API 除外） |
| AC-004-03 | LLM API Key 通过环境变量配置，禁止硬编码在代码中 |
