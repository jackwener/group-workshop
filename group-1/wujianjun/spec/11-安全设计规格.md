## 1. 安全目标与合规要求

> 明确本模块需遵循的安全目标和外部合规标准。投研场景尤其关注数据隐私与内部信息防泄露。

| 安全目标 | 说明 | 对应合规 |
|----------|------|----------|
| 数据不出域 | 所有用户数据、研报内容、问答记录禁止传输至外部服务 | 内部信息安全规范 |
| 最小权限原则 | 每个组件只拥有完成任务所需的最低权限 | 安全设计最佳实践 |
| 敏感数据保护 | API Key 环境变量存储，用户查询仅存本地 JSON，日志脱敏 | `07` §4.1 敏感数据保护 |
| 服务可用性保障 | 三级降级机制确保 LLM 不可用时仍能提供 Demo 服务 | `07` §1.2 降级策略 |

## 2. 认证与授权

> 定义用户身份验证方式和权限控制模型。写出认证流程和角色划分。

### 2.1 认证机制

| 项目 | 规格 |
|------|------|
| 认证方式 | **教学版：无认证（开放访问）**；生产版：JWT Token / 内部 SSO 对接 |
| Token 有效期 | 教学版：不适用；生产版：Access Token 30min, Refresh Token 7d |
| 密码策略 | 教学版：不适用；生产版：最少8位，含大小写+数字，90天强制更换 |
| 多因素认证 | 教学版：不适用；生产版：敏感操作需 MFA |

> 对齐 `07` §4：API 认证无（开放访问），Workshop 教学版。

### 2.2 角色与权限矩阵

| 角色 | 研报上传 | 研报阅读 | 问答交互 | 对比分析 | 系统管理 |
|------|----------|----------|----------|----------|----------|
| 分析师（教学版） | ✓ | ✓ | ✓ | ✓（P1）| ✗ |
| 管理员（教学版） | ✓ | ✓ | ✓ | ✓ | ✓ |
| 投研总监（生产版）| ✓ | ✓ | ✓ | ✓ | ✗ |
| 投资经理（生产版）| ✗ | ✓ | ✓ | ✗ | ✗ |

> **差距说明**：教学版无角色区分，所有用户拥有同等权限；生产版需实现 RBAC，与内部权限系统对接。

## 3. 数据安全

> 定义数据分类分级、加密策略、存储安全规范。**投研场景核心关注点**。

### 3.1 数据分类与分级

| 数据类型 | 安全等级 | 示例 | 保护措施 |
|----------|----------|------|----------|
| 研报原文 | **机密** | PDF/HTML 研报文件 | 加密存储，访问审计 |
| 问答记录 | **内部** | 用户提问与AI回答 | 存储加密，定期清理 |
| 用户信息 | **内部** | 用户名、角色、操作日志 | 脱敏展示，最小采集 |
| 系统配置 | 一般 | 模型参数、界面配置 | 版本控制 |

### 3.2 加密策略

| 场景 | 加密方式 | 说明 |
|------|----------|------|
| 传输加密 | **教学版：HTTP（本地开发）**；生产版：TLS 1.2+ | 所有 API 通信强制 HTTPS |
| 存储加密 | **教学版：明文 JSON**；生产版：AES-256 | 研报文件与问答记录落盘加密 |
| 密钥管理 | 环境变量存储（`.env`），禁止硬编码 | 对齐 `07` §4.1：API Key 通过环境变量配置 |

> **生产环境建议**：
> - 使用 Vault / AWS Secrets Manager 管理密钥
> - 密钥定期轮转（建议 90 天）
> - JSON 文件采用 AES-256-GCM 加密存储

## 4. 接口安全

> 与 `09` API 规格配合，定义 API 层面的安全防护措施。

| 防护措施 | 实现方式 | 说明 |
|----------|----------|------|
| 输入校验 | 服务端白名单校验 | 所有用户输入进行类型、长度、格式校验，对齐 `09` §9 参数校验规则 |
| SQL 注入防护 | N/A（JSON 文件存储）| 教学版无数据库，不涉及 SQL 注入风险 |
| XSS 防护 | 输出转义 + CSP | 研报内容渲染时防止脚本注入 |
| CSRF 防护 | **教学版：无 CSRF Token**；生产版：SameSite Cookie + CSRF Token | 状态变更接口（POST/DELETE）需 CSRF 校验 |
| 速率限制 | **教学版：无限制**；生产版：100 req/min/user | 对齐 `07` §4：教学场景不限速 |
| 文件上传校验 | N/A | 当前版本不支持文件上传功能 |

### 4.1 端点安全校验覆盖

| API 端点 | 输入校验 | 错误码 | 安全措施 |
|----------|----------|--------|----------|
| `POST /ask` | query 1~500 字符，session_id 非空 | EMPTY_QUERY, INVALID_QUERY, SESSION_NOT_FOUND | 参数白名单校验 |
| `POST /sessions` | title ≤ 100 字符 | INVALID_QUERY | 默认值填充 |
| `DELETE /sessions/<id>` | id 存在性校验 | SESSION_NOT_FOUND | 级联删除确认 |
| `GET /sessions/<id>/records` | id 存在性校验 | SESSION_NOT_FOUND | 只读操作 |
| `GET /sessions` | limit/offset 范围校验 | - | 分页参数校验 |
| `GET /capabilities` | 无参数 | - | 只读操作 |

## 5. LLM / AI 安全

> 针对大模型集成的专项安全措施。投研场景数据敏感，需严格管控数据流向。

| 风险点 | 防护措施 | 验收标准 |
|--------|----------|----------|
| 数据外泄至第三方模型 | 本地部署 / 内网百炼服务，禁止调用外网 API | 网络出口审计零外传记录 |
| Prompt 注入攻击 | 系统 Prompt 隔离，用户输入预处理过滤 | 输入长度限制 500 字符，特殊字符转义 |
| 模型幻觉 / 错误信息 | 回答标注来源引用（answer_source），标识置信度 | 每条回答携带 `answer_source` 和 `llm_used` 标识 |
| 敏感信息泄露（模型回复）| 输出过滤层，正则匹配敏感信息并脱敏 | 对齐 `07` §4.1：日志禁止记录 API Key 明文 |
| API Key 泄露 | 环境变量存储，禁止硬编码，日志脱敏 | 代码仓库扫描零 API Key 明文命中 |
| 服务不可用 | 三级降级机制（CoPaw → 百炼 → Demo）| Demo 模式始终可用，`llm_used=false` 时降级标识明确 |

## 6. 审计与日志

> 定义安全审计日志的记录范围、保留策略。

| 事件类型 | 记录内容 | 保留期限 | 告警 |
|----------|----------|----------|------|
| API 请求 | traceId、端点、方法、响应码、响应时间 | 30 天 | 响应时间 > 5s 告警 |
| 问答操作 | session_id、query 摘要、answer_source | 90 天 | 敏感关键词告警 |
| 会话管理 | session_id、操作类型（创建/删除）、时间戳 | 90 天 | 批量删除告警 |
| 系统配置变更 | 变更人、变更前后值 | 永久 | 关键配置变更即时通知 |
| 错误日志 | error.code、traceId、堆栈摘要 | 30 天 | 500 错误即时告警 |

> 对齐 `07` §4.1：日志禁止记录 API Key 明文，使用 `***` 脱敏。

## 7. 安全威胁清单（STRIDE 简表）

> 基于 STRIDE 模型，列出主要安全威胁与应对方案。

| 类型 | 威胁 | 风险等级 | 应对措施 | 负责人 |
|------|------|----------|----------|--------|
| **S**poofing | 伪造用户身份访问研报 | **高** | 强认证 + Token 校验（生产版）| 后端开发 |
| **T**ampering | 研报内容在传输中被篡改 | 中 | TLS + 文件哈希校验 | 后端开发 |
| **R**epudiation | 用户否认操作行为 | 中 | 审计日志记录所有操作，traceId 追踪 | 后端开发 |
| **I**nformation Disclosure | 内部数据通过 AI 模型泄露 | **高** | 本地部署 + 输出过滤 + 数据不出域 | 架构师 |
| **D**enial of Service | 大量请求导致服务不可用 | 中 | 速率限制 + 三级降级策略（生产版）| 后端开发 |
| **E**levation of Privilege | 普通用户获取管理员权限 | **高** | RBAC 权限控制（生产版），最小权限原则 | 后端开发 |

> **威胁等级说明**：高 = 需优先处理；中 = 需在上线前处理；低 = 可后续迭代。

## 8. 部署安全

> 定义部署架构中的安全要求。

- [x] 生产/开发环境**严格隔离**，数据不互通
- [x] 数据库访问仅限应用服务器 IP 白名单（教学版：本地 JSON 无此需求）
- [x] 敏感配置（API Key、密码）通过环境变量注入，不入代码仓库
- [x] 依赖包定期安全扫描（`pip audit` / `npm audit`）
- [x] **API Key 通过 `.env` 文件配置，禁止硬编码在代码中**（对齐 `07` §4.1）
- [x] **日志文件禁止记录 API Key 明文，使用 `***` 脱敏**
- [x] **JSON 数据文件权限设置为仅应用用户可读写**
- [x] **生产环境启用 HTTPS，禁止 HTTP 明文传输**
