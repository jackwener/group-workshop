> **04 的定位**：`03` 说了"为什么做"，04 翻译成"做什么、不做什么、多重要"。`05` 再拆成用户故事和验收标准。

## 1. 愿景与目标

基于 `03` §1 的痛点，翻译成正面目标：

| 03 痛点 | 04 目标 |
|---------|---------|
| 研报阅读耗时：每天阅读10+份研报耗时2-3小时 | 构建智能问答入口，帮助用户在30秒内获取关键信息 |
| 关键信息提取不完整：不知如何快速定位重点 | 自动提取评级、目标价、核心观点，准确率≥80% |
| 多份研报对比困难：需手动复制粘贴 | 一键生成多份研报对比表（P1迭代）|
| 股票数据查询分散：需多系统切换 | 在问答界面直接展示相关股票数据（P1迭代）|

## 2. 目标用户

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 投研分析师 | 快速获取研报关键信息，辅助投资决策 | 每天多次 |
| 投研总监 | 回溯团队问答历史，了解分析思路 | 每天1-2次 |
| 投资经理 | 快速查询行业观点和市场解释 | 每周数次 |

## 3. 核心业务场景

基于 `03` §2 提案概要，拆解为以下用户路径：

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 新建会话并提问 | 用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库 |
| SC-02 | 查看历史问答 | 用户选择历史会话 → 查看问答记录列表 → 点击记录查看详情 |
| SC-03 | 管理会话 | 用户在会话列表中 → 新建/删除会话 → 会话数据同步更新 |
| SC-04 | 能力状态查看 | 用户打开页面 → Header 显示当前能力状态（CoPaw/百炼/离线演示）|
| SC-05 | 离线模式体验 | 未配置LLM密钥时 → 用户提问 → 系统返回Demo演示回复 |

## 4. 产品规则

基于 `03` §4 成功标准 + §3 范围约束，展开为可落地的规则：

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 每条提问必须绑定 `session_id`，未绑定返回 400 错误 | 03 §2 "会话式问答" |
| R-02 | `query` 长度 1～500 字符，为空返回 EMPTY_QUERY，超长返回 INVALID_QUERY | 03 §4 "P0 全部可测" |
| R-03 | 回答必须携带 answer、llm_used(bool)、model、response_time_ms、answer_source | 03 §4 "P95 < 5s" |
| R-04 | 三级降级顺序固定：CoPaw → 百炼 → Demo，不可跳级 | 03 §3 "能力降级" |
| R-05 | 会话标题首次提问后自动更新为 query 前20字 + "..." | 03 §3 "会话管理" |
| R-06 | 删除会话时级联删除该会话下所有问答记录 | 03 §3 "会话管理" |
| R-07 | 所有用户数据仅存储在本地 JSON 文件，不传输外部（LLM除外）| 03 §3 "数据安全" |

## 5. 能力与优先级

基于 `03` §3 范围表，按 P0/P1 排优先级：

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 会话管理（列表 / 新建 / 删除） | **P0** | SC-01, SC-03 |
| 问答提交与三级降级 | **P0** | SC-01, SC-05 |
| 问答历史查看 | **P0** | SC-02 |
| 能力状态展示 | **P0** | SC-04 |
| 数据安全与本地存储 | **P0** | 全场景 |
| 研报对比分析 | P1 | 未来迭代 |
| 股票数据联动展示 | P1 | 未来迭代 |

## 6. 验收与成功标准（PRD 层）

基于 `03` §4 可度量标准，加上演示条件：

| 标准 | 度量 |
|------|------|
| 可演示 | 种子数据 ≥ 10 条下，主路径 + 历史 + 能力状态 **3 分钟内**演示完毕 |
| 离线可用 | 未配置密钥时系统仍返回离线演示回复（`answer_source=demo`）|
| 问答响应达标 | P95 响应时间 < 5 秒（通过 `response_time_ms` 字段验证）|
| 信息提取准确 | 评级/目标价/核心观点提取准确率 ≥ 80%（抽样评估）|

## 7. 与 05 用户故事的关系

> **04 定"做什么、多重要"；05 定"谁要什么、怎么验收"。** 填写完本文后，下一步进入 `05` 将场景拆成 US + AC。

| 本文（PRD） | 作用 | 05 中落地 |
|-------------|------|-----------|
| §3 核心场景 | 一条叙事场景 → 一条或多条 US | SC-01 → US-001 + US-002 |
| §4 产品规则 | 字段/状态/错误口径 | 拆入各 US 的 AC |
| §5 能力优先级 | P0 / P1 | 与各 US 优先级一致 |
