## 1. 安全目标与合规要求

> 明确本模块需遵循的安全目标和外部合规标准。投研场景尤其关注数据隐私与内部信息防泄露。

| 安全目标 | 说明 | 对应合规 |
|----------|------|----------|
| 数据不出域 | 所有用户数据、研报内容、问答记录禁止传输至外部服务 | 内部信息安全规范 |
| 最小权限原则 | 每个组件只拥有完成任务所需的最低权限 | 安全设计最佳实践 |
| 审计可追溯 | 所有关键操作可追溯至用户和时间点 | 审计合规要求 |
| **API 开放访问可控** | 教学版开放访问，生产版强制认证，确保访问可控 | `07` §4 API 认证 |
| **敏感数据环境隔离** | LLM API Key、用户数据通过环境变量存储，禁止硬编码 | `07` §4.1 敏感数据保护 |

## 2. 认证与授权

> 定义用户身份验证方式和权限控制模型。写出认证流程和角色划分。

### 2.1 认证机制

| 项目 | 当前教学版 | 生产建议 |
|------|------------|----------|
| 认证方式 | **无认证，开放访问**（`07` §4） | 对接内部 SSO/OAuth2.0 |
| Token 有效期 | 不适用 | Access Token 30min, Refresh Token 7d |
| 密码策略 | 不适用 | 最少8位，含大小写+数字，90天强制更换 |
| 多因素认证 | 不适用 | 敏感操作需 MFA 验证 |

### 2.2 角色与权限矩阵

| 角色 | 研报上传 | 研报阅读 | 问答交互 | 对比分析 | 系统管理 | 说明 |
|------|----------|----------|----------|----------|----------|------|
| 分析师 | ✗ | ✓ | ✓ | ✓ | ✗ | 核心用户，可阅读研报、使用问答和对比功能 |
| 管理员 | ✓ | ✓ | ✓ | ✓ | ✓ | 全权限，包含研报上传和系统管理 |
| 访客 | ✗ | ✗ | ✗ | ✗ | ✗ | 教学版无此角色（开放访问等同访客） |

## 3. 数据安全

> 定义数据分类分级、加密策略、存储安全规范。**投研场景核心关注点**。

### 3.1 数据分类与分级

| 数据类型 | 安全等级 | 示例 | 保护措施 |
|----------|----------|------|----------|
| 研报原文 | **机密** | PDF/HTML 研报文件 | 加密存储，访问审计 |
| 问答记录 | **内部** | 用户提问与AI回答 | 存储加密，定期清理 |
| 用户信息 | **内部** | 用户名、角色、操作日志 | 脱敏展示，最小采集 |
| 系统配置 | 一般 | 模型参数、界面配置 | 版本控制 |

### 3.2 加密策略

| 场景 | 当前教学版方案 | 生产建议 |
|------|----------------|----------|
| 传输加密 | HTTP（本地开发） | TLS 1.2+，所有 API 通信强制 HTTPS |
| 存储加密 | 明文存储（JSON 文件） | AES-256，研报文件与问答记录落盘加密 |
| 密钥管理 | **环境变量存储**（`.env`），禁止硬编码（`07` §4.1） | 环境变量 + KMS，密钥定期轮转 |

## 4. 接口安全

> 与 `09` API 规格配合，定义 API 层面的安全防护措施。

| 防护措施 | 当前教学版 | 生产建议 | 说明 |
|----------|------------|----------|------|
| 输入校验 | ✅ 已实现 | 服务端白名单校验 | 所有用户输入进行类型、长度、格式校验（`09` §8） |
| SQL 注入防护 | ✅ 不适用（JSON 存储） | 参数化查询 / ORM | 禁止字符串拼接 SQL |
| XSS 防护 | ✅ 输出转义 | 输出转义 + CSP | 研报内容渲染时防止脚本注入 |
| **CSRF 防护** | **无（开放访问，无 Session Cookie）** | SameSite Cookie + CSRF Token | 教学版无认证故无 CSRF 风险；生产版状态变更接口需 CSRF Token |
| 速率限制 | **无**（`07` §4） | 100 req/min/user | 教学场景不限速；生产防止接口滥用 |
| 文件上传校验 | 类型白名单 + 大小限制 | 类型白名单 + 大小限制 | 仅允许 PDF/HTML，限制单文件大小 |

## 5. LLM / AI 安全

> 针对大模型集成的专项安全措施。投研场景数据敏感，需严格管控数据流向。

| 风险点 | 防护措施 | 验收标准 |
|--------|----------|----------|
| 数据外泄至第三方模型 | 本地部署模型 / 内网百炼服务，禁止调用外网 API | 网络出口审计零外传记录；`answer_source` 字段可追踪数据来源 |
| Prompt 注入攻击 | 系统 Prompt 隔离，用户输入预处理过滤（长度限制 500 字符 `07` §5.1） | 通过渗透测试验证；过滤危险指令关键词 |
| 模型幻觉 / 错误信息 | 回答标注来源引用（`answer_source`: copaw/bailian/demo），标识置信度 | 人工抽检准确率 ≥ 90%；Demo 模式明确标识为离线演示 |
| 敏感信息泄露（模型回复） | 输出过滤层，正则匹配敏感信息并脱敏 | 敏感词库覆盖完整；用户查询内容不传输到第三方（LLM 除外 `07` §4.1） |

## 6. 审计与日志

> 定义安全审计日志的记录范围、保留策略。

| 事件类型 | 记录内容 | 保留期限 | 告警 |
|----------|----------|----------|------|
| 登录 / 登出 | 用户ID、时间、IP、结果 | 180天 | 连续失败 ≥5 次告警 |
| 研报访问 | 用户ID、文档ID、操作类型 | 365天 | 异常批量下载告警 |
| 数据导出 | 导出内容摘要、目标 | 365天 | 每次导出需审批 |
| 系统配置变更 | 变更人、变更前后值 | 永久 | 关键配置变更即时通知 |

## 7. 安全威胁清单（STRIDE 简表）

> 基于 STRIDE 模型，列出主要安全威胁与应对方案。

| 类型 | 威胁 | 风险等级 | 应对措施 | 负责人 |
|------|------|----------|----------|--------|
| **S** (Spoofing) | 伪造用户身份访问研报 | **高** | 教学版：开放访问（风险接受）；生产版：强认证 + Token 校验 | 安全组 |
| **T** (Tampering) | 研报内容在传输中被篡改 | 中 | 教学版：本地文件系统安全依赖；生产版：TLS + 文件哈希校验 | 安全组 |
| **R** (Repudiation) | 用户否认执行过敏感操作（如删除会话） | 中 | 操作审计日志（`traceId` 全链路追踪 `07` §3.1） | 安全组 |
| **I** (Information Disclosure) | 内部数据通过AI模型泄露 | **高** | 本地部署 + 输出过滤；用户数据仅本地 JSON 存储（`07` §4.1） | 安全组 |
| **D** (Denial of Service) | 大量请求导致服务不可用 | 中 | 教学版：降级策略（CoPaw→百炼→Demo `07` §1.2）；生产版：速率限制 | 运维组 |
| **E** (Elevation of Privilege) | 普通用户越权执行管理操作 | **高** | 角色权限矩阵控制（§2.2）；敏感操作二次确认 | 安全组 |

## 8. 部署安全

> 定义部署架构中的安全要求。

- [x] 敏感配置（API Key、密码）**通过环境变量注入**，不入代码仓库（`07` §4.1）
- [x] **JSON 文件存储**，无数据库，数据本地隔离（`08` §5）
- [ ] 生产/开发环境**严格隔离**，数据不互通
- [ ] 依赖包定期安全扫描（`pip audit` / `npm audit`）
- [ ] 定期安全漏洞扫描与渗透测试（每季度）
- [ ] 生产环境禁止 DEBUG 模式，关闭详细错误信息
- [ ] API 端点版本化管理（当前 `/api/v1`），废弃接口及时下线
- [ ] 容器/服务器安全加固，最小化暴露面
- [ ] 日志脱敏处理，禁止记录敏感字段（API Key、密码等）
