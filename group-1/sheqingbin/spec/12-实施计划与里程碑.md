## 1. 里程碑（S1～S4）

> **切分原则**：每刀切出一个**可演示的用户价值**。不是"接口写好了"，而是"能给业务看什么"。

**示例 — S1**：

**S1 会话管理**：创建/列表/删除会话 API + 前端会话侧栏 → 满足 REQ-001 部分 → 验证 TC-M01-020～025

| 阶段 | 交付要点（可演示） | 满足的 REQ/US | 验证 TC |
|------|-------------------|---------------|---------|
| **S1** 会话管理 | 会话 CRUD API + 前端侧栏 | REQ-001 部分 | TC-M01-020～025 |
| **S2** 问答核心 | 问答提交 API + 前端提问区 + 三级降级编排 | REQ-002 全部 | TC-M01-030～040 |
| **S3** 历史记录 | 问答记录 API + 历史记录展示 + 对比分析功能 | REQ-003 全部 | TC-M01-050～060 |
| **S4** 发布准备 | 健康检查、完整测试、文档完善、性能优化 | REQ-004 全部 | TC-M01-070～080 |

## 2. WBS 任务拆分

> **拆分原则**：按**工程职责**切（路由、存储、Agent、前端），不按功能切。一个 W 可跨多个 S 迭代推进。

| 任务ID | 任务名称 | 具体内容 | DoD（指向 Spec） | 推进阶段 |
|--------|----------|----------|------------------|----------|
| W1 | 路由实现 | `agent_bp.py` 端点注册、参数校验 | 对齐 `09` 端点与错误码 | S1 起贯穿 S4 |
| W2 | 存储层 | `storage.py` JSON CRUD | 对齐 `10` 数据模型 | S1～S2 |
| W3 | Agent 编排 | `agent.py` 三级降级链、结果组装 | 对齐 `08` §4 降级策略，支持 copaw/bailian/demo | S2～S3 |
| W4 | 前端视图 | React 组件：会话侧栏、提问区、消息展示区 | 对齐 `09` 接口响应，支持流式/非流式展示 | S1～S3 |
| W5 | 状态管理 | `useState` + `useEffect` 管理 8 个状态变量 | 会话状态、消息状态、加载状态、错误状态 | S1～S3 |
| W6 | 测试门禁 | pytest 单元测试 + 接口测试 + 前端组件测试 | 对齐 `13` 测试策略，P0 用例 100% 覆盖 | S2～S4 |

## 3. S × W 对应矩阵

> 读法：**●** = 主要推进，**○** = 少量涉及，**—** = 不涉及

| WBS \ 阶段 | S1 | S2 | S3 | S4 |
|------------|----|----|----|----|
| **W1** 路由 | ● sessions | ● ask | ● records | ○ health |
| **W2** 存储 | ● sessions CRUD | ● 记录落库 | ● 历史查询 | — |
| **W3** Agent | — | ● 三级降级 | ● 对比分析 | — |
| **W4** 前端 | ● 会话侧栏 | ● 提问区 | ● 历史展示 | ○ 优化 |
| **W5** 状态机 | ● 会话状态 | ● 消息状态 | ● 加载/错误 | — |
| **W6** 测试 | ○ fixture | ● P0 用例 | ● P1 用例 | ● 回归测试 |

## 5. 依赖与风险

**示例 — 依赖链**：

**S1 会话管理** → **S2 问答核心**（必须先有会话才能提问）→ **S3 历史与状态** → **S4 发布准备**

| 风险 | 影响 | 应对 |
|------|------|------|
| 上游 LLM 不可用 | 问答降级 | Demo 模式兜底 |
| 前端后端接口不匹配 | 联调延期 | 每日接口契约确认，Mock 数据先行 |
| 需求变更（对比分析复杂度） | S3 延期 | 预留 20% 缓冲时间，MVP 优先交付 |
