> **04 的定位**：`03` 说了"为什么做"，04 翻译成"做什么、不做什么、多重要"。`05` 再拆成用户故事和验收标准。

## 1. 愿景与目标

> 把 `03` §1 的痛点翻译成正面目标。格式："构建 XXX，帮助用户在 XXX 内完成 XXX"。

**示例 — 痛点→目标映射**：

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息分散、无统一入口 | 统一会话问答入口 |
| 复盘成本高 | 会话历史自动沉淀，随时回看 |

| 03 痛点 | 04 目标 |
|---------|--------|
| 信息分散、多系统无统一问答入口 | 统一投研问答入口，一站式查询研报、新闻、数据 |
| 内部研报解析提取关键信息困难 | AI 自动解析研报，提取关键信息并支持对比分析 |

## 2. 目标用户

> 把 `03` §2 的一句话展开成具体角色。思考：谁会用？用来做什么？多常用？

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 投研分析师 | 快速查询投研观点与市场解释 | 每天多次 |
| 研究主管 | 对比不同券商研报观点，辅助投资决策 | 每天 1~2 次 |
| 系统管理员 | 维护系统配置、管理研报数据源 | 每周数次 |

## 3. 核心业务场景

> 把 `03` §2 提案概要拆成 4~5 条用户路径。每条场景 = 一条用户操作动线。

**示例 — SC-01**：

**SC-01 新建会话并提问**：用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 新建会话并提问 | （见上方示例） |
| SC-02 | 查看历史会话记录 | 用户点击左侧历史会话 → 加载对话记录 → 浏览历史问答内容 |
| SC-03 | 删除会话 | 用户点击会话的 × 按钮 → 确认弹窗 → 会话及关联记录被删除 |
| SC-04 | 研报对比分析 | 用户提问对比类问题 → AI 识别意图 → 解析研报 → 返回对比表格 |

## 4. 产品规则

> 把 `03` §4 成功标准 + §3 范围约束展开成可落地的规则。参考方向：输入约束、返回字段、状态管理、降级策略。

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 每条提问必须绑定 `session_id` | 03 §2 "会话式问答" |
| R-02 | `query` 长度 1～500 字符，为空或超长返回明确错误 | 03 §4 "P0 全部可测" |
| R-03 | 回答必须携带 `answer`、`answer_source`、`llm_used`、`response_time_ms` 字段 | 09 §3 POST /ask 响应 |
| R-04 | 降级策略：CoPaw → 百炼 → Demo 三级降级，不可跳级，静默执行 | 03 §5 "外部 LLM 不可用" |
| R-05 | 首次问答自动以 query 前 20 字命名会话标题，标题最长 23 字符超出截断 | 05 AC-001-02 |

## 5. 能力与优先级

> `03` §3 范围表写了"做什么"，04 按 P0/P1 排优先级。P0 = 必须实现，阻塞发布；P1 = 应当实现，不阻塞首版。

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 会话管理（列表 / 新建 / 删除） | **P0** | SC-01, SC-03 |
| 问答提交与三级降级 | **P0** | SC-01 |
| 研报对比分析 | **P0** | SC-04 |
| 历史记录查看 | **P0** | SC-02 |
| 能力状态探测（capabilities） | **P1** | SC-01 |

## 6. 验收与成功标准（PRD 层）

> 从 `03` §4 可度量标准出发，加上演示条件。
> **参考句式**："种子数据 ≥ N 条下，XXX 在 N 分钟内完成"

| 标准 | 度量 |
|------|------|
| 可演示 | 种子数据 ≥ 10 条下，主路径 + 历史 + 能力状态 **3 分钟内**演示完毕 |
| 离线可用 | 未配置密钥时系统仍返回离线演示回复（`answer_source=demo`） |
| 研报对比可用 | 用户提交对比类问题后 10 秒内返回对比结果表格 |
| 错误可理解 | query 为空或超长时返回明确中文错误提示（`EMPTY_QUERY` / `INVALID_QUERY`） |

## 7. 与 05 用户故事的关系

> **04 定"做什么、多重要"；05 定"谁要什么、怎么验收"。** 填写完本文后，下一步进入 `05` 将场景拆成 US + AC。

| 本文（PRD） | 作用 | 05 中落地 |
|-------------|------|-----------|
| §3 核心场景 | 一条叙事场景 → 一条或多条 US | SC-01 → US-001 + US-002 |
| §4 产品规则 | 字段/状态/错误口径 | 拆入各 US 的 AC |
| §5 能力优先级 | P0 / P1 | 与各 US 优先级一致 |
