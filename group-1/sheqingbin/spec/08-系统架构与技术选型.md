│  ┌────────────────────────────┐ │

│  └────┬──────────┬────────────┘ │
│       ▼          ▼              │
│  ┌────────┐ ┌──────────┐       │
│  │ LLM 层 │ │ 文件系统  │       │

### 1.2 架构风格

> 选择架构风格时思考：教学场景需要什么样的复杂度？分层带来什么好处？

| 决策 | 选型 | 理由 |
|------|------|------|
| **前后端分离** | React SPA + Flask REST API | 教学清晰度：前端独立开发服务器 |
| **单体部署** | 前后端各一个进程 | 不引入微服务复杂度 |
| **分层架构** | Route → Agent → Storage | 替换存储引擎时上层零改动 |
| **JSON 文件存储** | `json` 标准库读写 | 教学场景无需数据库依赖，降低复杂度 |
| **降级编排策略** | 三级降级链（CoPaw → 百炼 → Demo） | 确保服务高可用，外部 LLM 故障时自动降级，用户无感知 |

## 2. 后端分层结构

> 每层写清"允许做什么、禁止做什么"。

| 层 | 文件 | 允许做 | 禁止做 |
|----|------|--------|--------|
| **Route** | `agent_bp.py` | 参数校验、HTTP 状态码、traceId | 直接读写文件、调用 LLM |
| **Agent** | `agent.py` | 降级编排、结果组装 | 感知 HTTP 请求/响应 |
| **Provider** | `copaw_bridge.py` / `bailian_qa.py` | HTTP 调用外部 API | 操作本地存储 |
| **Storage** | `storage.py` | 文件 CRUD、数据校验 | 调用外部 API |

## 3. 前端架构

| 项 | 选型 | 理由 |
|----|------|------|
| UI 框架 | React（Hooks）≥ 18 | 教学通用性最高 |
| 构建工具 | Vite ≥ 5 | 极快 HMR，零配置启动 |
| 状态管理 | `useState` + `useEffect` | 8 个 state 变量足够 |
| HTTP 客户端 | `fetch` API | 浏览器原生，不引入 axios |
| 样式方案 | CSS Modules / 内联样式 | 无额外依赖，组件级样式隔离 |
| 组件库 | 无（原生 HTML + CSS） | 教学场景保持简洁，避免引入 UI 库学习成本 |
| 路由 | 无（单页应用无路由切换） | 功能简单，无需 React Router |
| 图标 | Unicode 字符 / SVG 内联 | 无需引入图标库，减少依赖 |

## 7. ADR（架构决策记录）

> 每条 ADR 记录一个"为什么选 A 而不选 B"的决策。至少写 2 条。

### ADR-001：为什么选择 Flask 而非 FastAPI？

**决策**：选用 Flask 作为后端 Web 框架。

**背景**：需要选择一个 Python Web 框架来构建 REST API。

**考虑选项**：
- **A. Flask**：轻量级，同步框架，学习曲线平缓
- **B. FastAPI**：现代异步框架，自动生成文档，性能更高

**决策理由（选 A 不选 B）**：
1. **学习曲线**：Flask 无需理解 async/await，学员具备 Python 基础即可上手
2. **教学清晰度**：同步代码执行流程直观，便于调试和理解
3. **依赖简单**：Flask 核心依赖少，减少环境配置问题

---

### ADR-002：为什么选择 JSON 文件而非 SQLite 作为首版存储？

**决策**：首版采用 JSON 文件存储，而非 SQLite 数据库。

**背景**：教学场景需要一种简单、易懂的持久化方案。

**考虑选项**：
- **A. JSON 文件**：使用 Python 标准库 `json` 读写
- **B. SQLite**：轻量级关系型数据库，单文件存储

**决策理由（选 A 不选 B）**：
1. **零依赖**：JSON 无需安装任何数据库驱动，学员只需 Python 环境即可运行
2. **可视化**：JSON 文件可直接用文本编辑器打开查看，便于调试和理解数据结构
3. **教学聚焦**：避免引入 SQL 语法和数据库概念，让学员专注业务逻辑学习
4. **易于重置**：直接删除文件即可清空数据，方便反复测试

---

### ADR-003：为什么选择 React Hooks 而非类组件？

**决策**：前端采用 React Hooks（函数组件）编写，而非传统类组件。

**背景**：React 提供了两种组件编写方式：类组件和函数组件（Hooks）。

**考虑选项**：
- **A. 函数组件 + Hooks**：使用 `useState`、`useEffect` 等 Hook
- **B. 类组件**：使用 `class` 关键字和生命周期方法

**决策理由（选 A 不选 B）**：
1. **现代标准**：Hooks 是 React 官方推荐的主流写法，社区生态更完善
2. **代码简洁**：函数组件代码量更少，无需理解 `this` 绑定和生命周期方法
3. **逻辑复用**：自定义 Hook 便于抽离状态逻辑，比高阶组件更直观
4. **教学衔接**：与当前 React 官方文档和教程保持一致，学员后续学习更顺畅

---

### ADR-004：为什么采用三级降级而非单点故障？

**决策**：采用 CoPaw → 百炼 → Demo 的三级降级链，而非依赖单一 LLM 服务。

**背景**：LLM 服务可能因网络、配额、服务故障等原因不可用。

**考虑选项**：
- **A. 三级降级链**：主服务故障时自动切换到备用服务
- **B. 单 LLM 服务**：仅依赖一个 LLM 提供商

**决策理由（选 A 不选 B）**：
1. **高可用性**：即使主服务 CoPaw 故障，百炼和 Demo 仍可保证服务可用
2. **教学演示**：Demo 模式无需 API Key，方便学员在无网络环境下演示
3. **用户体验**：降级静默执行，用户通过 `answer_source` 字段感知，无中断体验
4. **成本控制**：Demo 模式零成本，可用于开发测试环境

---

| ADR | 决策 | 核心理由 |
|-----|------|----------|
| ADR-001 | Flask 而非 FastAPI | 学习曲线低，同步代码更易教学 |
| ADR-002 | JSON 文件而非 SQLite 首版 | 零依赖，可视化，教学聚焦业务逻辑 |
| ADR-003 | React Hooks 而非类组件 | 现代标准，代码简洁，社区主流 |
| ADR-004 | 三级降级而非单点故障 | 高可用，支持离线演示，用户体验好 |

## 8. 安全架构

> 对齐 `07` 4 安全需求。当前教学版与生产需求的差距。

| 层 | 当前措施 | 生产改进 |
|----|----------|----------|
| 认证 | 无（开放访问） | JWT Token 认证 |
| 授权 | 无（所有用户同权限） | RBAC 角色权限控制 |
| CORS | 全开放 | 白名单域名限制 |
| 密钥 | 环境变量 `.env` | Vault / Secrets Manager |
| 输入校验 | Route 层手动校验 | JSON Schema 验证 + 参数消毒 |
| 日志审计 | print 输出 | 结构化日志 + 审计追踪 |
| 速率限制 | 无 | 基于 IP / 用户的限流（如 100 次/分钟） |
| HTTPS | 无（开发环境 HTTP） | TLS 1.2+ 强制加密 |
| 数据加密 | 明文存储 | 敏感字段加密（AES-256） |
| 会话安全 | 无会话过期 | 会话超时 + 刷新机制 |
