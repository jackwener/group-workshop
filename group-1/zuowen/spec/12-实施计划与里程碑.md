## 1. 里程碑（S1～S4）

> **切分原则**：每刀切出一个**可演示的用户价值**。不是"接口写好了"，而是"能给业务看什么"。

**示例 — S1**：

**S1 会话管理**：创建/列表/删除会话 API + 前端会话侧栏 → 满足 REQ-001 部分 → 验证 TC-M01-020～025

| 阶段 | 交付要点（可演示） | 满足的 REQ/US | 验证 TC |
|------|-------------------|---------------|---------|
| **S1** 会话管理 | 会话 CRUD API + 前端侧栏 | REQ-001 部分 | TC-M01-020～025 |
| **S2** 问答核心 | 问答 API + 三级降级 + 流式输出 | REQ-002 | TC-M01-001～004 |
| **S3** 研报摘要与对比 | 研报摘要卡片 + 对比表格 + AI总结 | REQ-003 | TC-M01-010～015 |
| **S4** 发布准备 | 端到端测试 + 性能优化 + 文档完善 | 全部 P0 REQ | TC-M01-全量 |

## 2. WBS 任务拆分

> **拆分原则**：按**工程职责**切（路由、存储、Agent、前端），不按功能切。一个 W 可跨多个 S 迭代推进。

| 任务ID | 任务名称 | 具体内容 | DoD（指向 Spec） | 推进阶段 |
|--------|----------|----------|------------------|----------|
| W1 | 路由实现 | `agent_bp.py` 端点注册、参数校验 | 对齐 `09` 端点与错误码 | S1 起贯穿 S4 |
| W2 | 存储层 | `storage.py` JSON CRUD | 对齐 `10` 数据模型 | S1～S2 |
| W3 | Agent 编排 | `agent.py` 三级降级逻辑 | 对齐 `07` 降级策略 | S2～S3 |
| W4 | 前端视图 | `App.jsx` 会话侧栏 + 问答区 + 摘要卡片 | 对齐 `06` 功能规格 | S1～S4 |
| W5 | 状态机 | React state 管理、错误处理 | 对齐 `06` 状态管理 | S2～S3 |
| W6 | 测试门禁 | pytest 用例、覆盖率、CI 配置 | 对齐 `13` 测试策略 | S2～S4 |

## 3. S × W 对应矩阵

> 读法：**●** = 主要推进，**○** = 少量涉及，**—** = 不涉及

| WBS \ 阶段 | S1 | S2 | S3 | S4 |
|------------|----|----|----|----|
| **W1** 路由 | ● sessions | ● ask | ● records | ○ 优化 |
| **W2** 存储 | ● sessions CRUD | ● 记录落库 | — | — |
| **W3** Agent | — | ● 三级降级 | ● 摘要编排 | ○ 性能调优 |
| **W4** 前端 | ● 会话侧栏 | ● 提问区 | ● 摘要卡片 | ● 完善交互 |
| **W5** 状态机 | — | — | ● 加载/错误态 | — |
| **W6** 测试 | ○ fixture | ● P0 用例 | ● 全量覆盖 | ● 门禁通过 |

## 5. 依赖与风险

**示例 — 依赖链**：

**S1 会话管理** → **S2 问答核心**（必须先有会话才能提问）→ **S3 历史与状态** → **S4 发布准备**

| 风险 | 影响 | 应对 |
|------|------|------|
| 上游 LLM 不可用 | 问答降级 | Demo 模式兜底 |
| 数据源接口变更 | 研报摘要功能不可用 | 预留适配层，支持多数据源配置 |
| 前端开发进度延迟 | 影响整体演示 | 优先完成核心交互，UI 美化可延后 |
