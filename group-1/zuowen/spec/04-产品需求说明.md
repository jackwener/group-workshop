> **04 的定位**：`03` 说了"为什么做"，04 翻译成"做什么、不做什么、多重要"。`05` 再拆成用户故事和验收标准。

## 1. 愿景与目标

> 把 `03` §1 的痛点翻译成正面目标。格式："构建 XXX，帮助用户在 XXX 内完成 XXX"。

**示例 — 痛点→目标映射**：

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息分散、无统一入口 | 统一会话问答入口 |
| 复盘成本高 | 会话历史自动沉淀，随时回看 |
| 对比效率低 | 多来源研报自动对比分析 |
| 数据源切换繁琐 | 多维度数据统一接入与展示 |

## 2. 目标用户

> 把 `03` §2 的一句话展开成具体角色。思考：谁会用？用来做什么？多常用？

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 投研分析师 | 快速查询投研观点与市场解释 | 每天多次 |
| 投研经理 | 管理会话记录，进行研报对比分析 | 每天 |
| 投资总监 | 查看关键摘要，辅助投资决策 | 每周多次 |

## 3. 核心业务场景

> 把 `03` §2 提案概要拆成 4~5 条用户路径。每条场景 = 一条用户操作动线。

**示例 — SC-01**：

**SC-01 新建会话并提问**：用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 新建会话并提问 | （见上方示例） |
| SC-02 | 查看研报摘要 | 用户输入公司名 → 系统返回多来源研报摘要 → AI生成总结结论 |
| SC-03 | 研报对比分析 | 用户选择公司+指标 → 系统生成对比表格 → 支持溯源查看原文 |
| SC-04 | 会话管理与标签 | 用户对会话打标签 → 支持分组管理 → 快捷检索历史会话 |

## 4. 产品规则

> 把 `03` §4 成功标准 + §3 范围约束展开成可落地的规则。参考方向：输入约束、返回字段、状态管理、降级策略。

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 每条提问必须绑定 `session_id` | 03 §2 "会话式问答" |
| R-02 | `query` 长度 1～500 字符，为空或超长返回明确错误 | 03 §4 "P0 全部可测" |
| R-03 | 回答必须携带 answer、llm_used、model、response_time_ms、answer_source 字段 | 03 §4 "生成关键摘要" |
| R-04 | 降级策略：CoPaw → 百炼 → Demo，不可跳级，静默执行 | 03 §5 "三级降级" |
| R-05 | 会话状态：新建时 query_count=0，每次提问后 +1，首次提问自动重命名 | 03 §3 "会话管理" |

## 5. 能力与优先级

> `03` §3 范围表写了"做什么"，04 按 P0/P1 排优先级。P0 = 必须实现，阻塞发布；P1 = 应当实现，不阻塞首版。

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 会话管理（列表 / 新建 / 删除） | **P0** | SC-01, SC-03 |
| 问答提交与三级降级 | **P0** | SC-01 |
| 研报摘要生成与AI总结 | **P0** | SC-02 |
| 多维度研报对比分析 | **P0** | SC-03 |
| 会话标签与分组管理 | **P1** | SC-04 |

## 6. 验收与成功标准（PRD 层）

> 从 `03` §4 可度量标准出发，加上演示条件。
> **参考句式**："种子数据 ≥ N 条下，XXX 在 N 分钟内完成"

| 标准 | 度量 |
|------|------|
| 可演示 | 种子数据 ≥ 10 条下，主路径 + 历史 + 能力状态 **3 分钟内**演示完毕 |
| 离线可用 | 未配置密钥时系统仍返回离线演示回复（`answer_source=demo`） |
| 研报摘要质量 | 用户输入公司名后，系统返回 ≥ 3 个来源的研报摘要，并生成总结结论 |
| 对比表格可用 | 用户指定指标后，系统生成对比表格，支持溯源查看原文链接 |

## 7. 与 05 用户故事的关系

> **04 定"做什么、多重要"；05 定"谁要什么、怎么验收"。** 填写完本文后，下一步进入 `05` 将场景拆成 US + AC。

| 本文（PRD） | 作用 | 05 中落地 |
|-------------|------|-----------|
| §3 核心场景 | 一条叙事场景 → 一条或多条 US | SC-01 → US-001 + US-002 |
| §4 产品规则 | 字段/状态/错误口径 | 拆入各 US 的 AC |
| §5 能力优先级 | P0 / P1 | 与各 US 优先级一致 |
